## 2. 적 붙잡기 · 옮기기 공통 장치 (EnemyHold — 첫 영웅 구현 때 만듦)
새 영웅 다섯 중 넷이 적의 움직임을 직접 다룸 (들어 올림 · 던짐 · 밀어 쌓음 · 구멍에 빠짐 · 종이가 되어 펄럭임). 따로따로 만들면 서로 · 기존 시스템(적 스킬 `casting`, 넉백, 풀링, 보스)과 엉킴 → 한 곳에서.
- `EnermyController` 에 `[NonSerialized] public object holder;` — null 이 아니면 FixedUpdate 의 자기 이동을 하지 않음 (`casting` 은 적 자신의 기술용이라 빌려 쓰지 않음). 접촉 피해도 주지 않음(들린 적 · 묻힌 적이 플레이어를 치지 않게).
- 정적 도우미 `EnemyHold` (새 파일): `bool TryTake(EnermyController e, object owner)` (보스 · 중간 보스 · 이미 잡힌 적 · 죽은 적은 거절, 중간 보스는 영웅 문서에서 따로 허용 가능) · `void Release(EnermyController e, object owner)` · `void ReleaseAll(object owner)` (판 끝 · 영웅 정리 · 씬 전환 때) · 적이 죽거나 풀로 돌아가면(`PoolDead` · `ReviveForPool`) holder 자동 해제.
- 옮기는 동안 위치는 owner 가 직접 `transform.position` 으로 (지도 접기 `MapLoopPull` 과 같은 방식). 벽 · 경기장 밖으로 내보내지 않게 경기장 경계(ArenaRules)로 자름.
- 보스(`boss.cs`)는 잡지 않음 — 필살기의 「보스를 들어 메침」 같은 것은 보스를 실제로 옮기지 않고 연출(그림자 · 들썩임) + 피해로.

## 2-1. 입력은 둘뿐 (공사 반장 기획에서 나온 원칙 — 다섯 영웅 공통)
이 게임 입력은 **공격(좌클릭)** 과 **필살기(우클릭, 게이지)** 두 가지 (기존 9명 모두 우클릭 = 게이지 필살기). 콘셉트의 「우클릭 고유」와 「필살기」를 따로 두면 오조작 · 키 부족.
→ 콘셉트의 「우클릭 고유」 동작은 **평타 쪽(누르기 · 떼기 · 오래 누르기 · 연타)** 이나 **필살기 쪽(게이지 · 누르고 있다 떼기)** 중 하나로 접는다. 예: 공사 반장 = 덤프는 평타 떼기, 우클릭은 철거 공고. 다른 키(쉬프트 등)를 새로 만들지 않는다.

## 3. 영웅 문서(hero-<키>.md)가 채울 틀
1. **정체 · 글**: 이름 · 칭호 · description · weapon · attack · skill · skillDesc (CharacterData 말투, 한국어. 번역은 구현 때 4개 언어).
2. **스탯 배율**: hp · damage · attackSpeed · gauge · sig · special · move · range (+ 필요하면 mag). 기준: 밸런스 문서 + 기존 9명과 「1판 DPS · 생존」이 비슷한 띠 안 (근거 한두 줄).
3. **평타 · 우클릭 · 필살기**: 동작을 프레임 단위가 아니라 「입력 → 무엇이 언제 일어남 → 수치」로. 범위 표시(범위표시 기획 규칙), 조준 표시(HeroAim), 패드 조작에서 어떻게 되는지, 자동 조작(GameInput.Auto · AutoplayBot)에서 최소한 굴러가는 방법.
4. **레벨업 전용 카드 6장** (Pierce · Multi · Knock · Glare · ExtraA · ExtraB 자리 — 각 자리의 뜻은 기존 영웅 카드 참고) — 이름 · 한 문장 · 수치 표(레벨 1~최대).
5. **고유 스킬 10개** (4단계) — 이름 · 한 문장 · 단계 수치. 영웅 동사를 넓히는 것 위주, 「피해 +n%」만 있는 카드 금지.
6. **스킬 진화 7개** — 재료 두 개 · 이름 · 효과.
7. **특수 능력 7개** (무기 3: 1차 진화 형태 = 영웅 전용 무기 + 궁극기 / 패시브 4) — 이름 · 효과 · 진화 효과.
8. **무기 강화 3개** (2차 진화) — 이름 · 효과.
9. **갈래 5개** — 빌드-시너지 기획 · 구현 안내의 틀 그대로 (입문 · 공명 I · II · 완성 · 극의 · 대가 · 교차 효과 2개 이상 · 31번 새 카드). 수치 상수 표.
10. **손맛 서명** (HeroImpacts 갈래): 평타 특수 조건(무엇일 때) · 고유 스킬 · 진화 · 필살기의 소리(Impact.Sounds 중 · 필요하면 새 합성 소리 이름과 묘사) · 흔들림 방향 · 세기.
11. **해금 비밀** (desert-secrets.md 의 그 영웅 칸을 구체화): 소품 그림 · 위치(사막 좌표 기준 방향 · 거리) · 판정 · 힌트 · 발견 연출 · 다시 했을 때 보상 · 일일 도전에서.
12. **이야기 · 대사**: StoryDirector 3곳(등장 · 보스 앞 · 엔딩 한 줄), 전령 대사 6줄, 기억 조각, 보스 기억 명사, 거울의 군주가 흉내 낼 평타 · 필살기 패턴, 개발자가 이 영웅으로 순환할 때 쓸 이름.
13. **그림 목록**: 32칸 몸 시트 6프레임 (idle 2 · run 4 — 기존 규격) 묘사 · 손에 든 것(held) · 영웅 전용 무기 3 · 이펙트(fx_*) 목록 · 메뉴 초상 128칸 묘사.
14. **스킨 6** (concept.md) — id · 이름 · 등급 · 한 줄.
15. **계약 · 보드**: 영웅 계약 H(...) 몇 개 · 기록 키(RunCounters `Hero(...)`).

## 4. 수치 원칙
- 밸런스: 새 영웅 1판 화력 · 생존은 기존 9명의 띠 안 (밸런스 문서의 측정법). 「참신한 동작」이 손해가 되지 않게 — 동작이 어려운 만큼 맞혔을 때 보상이 큼.
- 범위 표시 · 조준선은 「범위표시 기획」 규칙.
- 갈래 한 갈래가 다른 갈래보다 ±8% 넘게 세지 않게 (빌드-시너지 기획의 원칙).
