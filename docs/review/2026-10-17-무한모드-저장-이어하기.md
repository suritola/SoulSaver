## 1. 이야기 모드 저장이 실제로 어떻게 되는지 (코드로 확인)

### 1-1. 저장 칸 · 자료

- `Assets/Scripts/RunSave.cs:14-15`: `const string Key = "run.save"; const int Version = 1;`
- `RunSave.Data`(`:18-60`): 판 상태를 통째로 적지 않고 **「선택」을 글자 코드로 순서대로**(`log`), 그 밖의 값(체력 · 경험치 · 코인 · 조각 · 처치 수 · 게이지 · 판 기록)은 저장 순간의 값 그대로. 저장은 `JsonUtility.ToJson(d)` 한 줄(`:263`), `Prefs.SetString` + `Prefs.Save()`.

### 2-2. `RunSave.Save()` 무한 분기 두 곳

(a) `:215` `bool bossDown = sp.bossCleared;` → `bool bossDown = !GameMode.IsEndless && sp.bossCleared;`

- 이유: 무한 모드에서 `EnemySpawner.OnBossDefeated`(`EnemySpawn.cs:265`)가 `bossCleared = true` 로 켜면 `EndlessMode.OnBossDefeated`(`:332`)가 바로 `false` 로 되돌리지만, **클리어 연출 5초(`finalStage == 3`) 동안은 `:322` 에서 먼저 돌아가 `bossCleared` 가 `true` 로 남는다.** 그때 `Save()` 가 `bossDown` 가지를 타면 `Chapters.Next(4) < 0` 이라 `:222` 에서 `return` — 저장이 조용히 빠진다. 무한 모드는 늘 「지금 장 · 처치 수」 가지(`:238-260`)로 간다.

### 2-3. `RunSave.Data` 에 더하는 필드 (Version 1 그대로 · 모두 기본값으로 호환)

```csharp
{
```

```csharp
    d.endlessBosses = BossesDefeated;
    d.endlessTrophies = trophies;
    d.endlessFinal = finalStage == 3 ? 4 : finalStage;              // 클리어 연출 5초 중이면 이어할 때 바로 한계 돌파 (보너스 · 기록은 ClearEndless 가 이미 적었음)

    d.endlessNextBoss = bossLive || nextBoss == float.MaxValue ? -1f : Mathf.Max(0f, nextBoss - Time.time);
    d.endlessNextMid = Mathf.Max(0f, nextMidBoss - Time.time);

        for (int i = 0; i < bossPrefabs.Length; i++)
            if (bossPrefabs[i] != null && bossPrefabs[i].TryGetComponent(out bosss b) && bosss.KindAlive(b.bossKind)) mask |= 1 << i;
```

```csharp
{

void RestoreFinal(int aliveMask)

    int made = 0;

        Vector3 at = (Vector3)spawner.bossSpawnPoint + (made == 0 ? Vector3.zero : Quaternion.Euler(0f, 0f, 90f * made) * Vector3.right * 4.5f);

    spawner.bossCleared = false;
```

## 7. 같이 고치면 좋은 것 (작고 안전 · 각 한 줄)

### 7-1. 메인 메뉴에서 지난 무한 기록 글 지우기 — `MenuExtras.InstallMainMenu` (`:102-105` 근처)

### 7-2. 죽을 때 저장 삭제를 「저장하는 판」에만 — `PlayerController.DeathSequence :1342`


### 7-3. 그대로 두는 것 (바꾸지 않음 — 이유 기록)

- `EndlessMode.OnDestroy` 의 기록 · 순위표 업로드: 메뉴로 나가며 저장할 때도 올라가지만 `KeepBest`(`SteamManager.cs:379`)라 이어한 뒤의 더 긴 기록으로 덮인다. 끝내 이어하지 않은 판이면 그 시간이 실제로 버틴 시간이라 그대로 두어도 맞다. `BestSeconds` 도 같은 이유.
- 되감기(강제 종료 → 최대 1분): 이야기 모드와 같게 두라는 지시. 순위표에 미치는 폭이 1분 이내이고 죽은 판은 되살릴 수 없다. 뒤에 필요하면 `Submit` 의 `details` 에 「이어한 판」 표시 한 칸을 더하는 정도로 따로 다룬다(이번 범위 밖).

## 10. 호환 · 위험 · 메모

- `RunSave.Version` 1 그대로 — 이야기 저장은 손대지 않고 그대로 읽힌다. 새 필드는 `Data` 끝에 기본값(`-1` 둘 포함)으로.
- 한 칸(`run.save`) 공유: 이야기 판과 무한 판을 동시에 둘 수 없다. 이것은 「일반 모드 저장과 똑같이」의 직접 결과이며, 바꾸려면 저장 칸을 둘로 나누는 다른 설계가 된다(이번 범위 밖).
- 성능: `SaveRun` · `RestoreRun` 은 저장 · 이어하기 때 한 번씩. `EndlessMode.Update` · HUD · `Watcher.Update` 는 손대지 않아 매 프레임 할당이 늘지 않는다.
- 생성: 보스 재등장은 지금 쓰는 프리팹 `Instantiate` 길(`SpawnBoss` · `StartFinal` 꼴 · `SpawnFinalBoss`) 그대로. 스크립트 붙은 씬 오브젝트를 복제하지 않는다.

- `Peek()` 의 캐릭터 잠김 검사는 그대로 — 무한 모드 캐릭터도 열린 캐릭터라야 이어진다(해금을 되돌릴 길이 없으니 실질 영향 없음).
