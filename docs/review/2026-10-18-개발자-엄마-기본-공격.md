## B. 설계 원칙

1. **정체성**: 개발자는 「화면 · 코드 · 마우스 · 키보드」로 공간을 **지정**한다(시스템 공격 · 읽기). 엄마는 「집안일 · 훈육 · 비교」로 **몸으로 들이닥친다**(몸 쓰기 · 규칙). 둘 다 글자 연출(코드 줄 · 오류 창 · 잔소리 같은 말투)을 쓴다 — 결계와 같은 세계관.
2. **피하는 법이 모두 다름**: 한 보스 안에서 「빈틈 사이로 · 사각형 밖으로 · 보스에게서 멀리 · 안전 칸으로 · 도는 빈자리로 · 옆으로 비켜서기」(개발자), 「선에서 비켜서기 · 부채꼴 밖 · 길 밖 · 움직이는 띠의 빈틈 · 쏴서 부수기 · 가만히 있기」(엄마). 결계 공격 · 영웅 흉내와도 겹치지 않는다(A4).
3. **기본 공격답게**: 한 대는 대부분 영웅 흉내(16% · 32%)보다 가볍다. 무거운 것(최대 등급)은 예고가 긴 것(빌드 실패 1.2초 이상 · 불 끄고 자 1.0초 + 규칙)만.
4. **공정성 규칙** (모든 고유 공격)
   - 예고 없이 나타나는 피해 없음. 예고 바닥 개발자 0.5초 · 엄마 0.42초(`DevTele` 0.35초보다 길게).
   - 판정은 예고 모양 그대로(원 `+0.2` · 띠 반폭 `+0.2` · 사각형 `+0.2`). 예고 자리는 시작 때 고정(보스가 영웅 흉내로 움직여도 예고 자리에서 터짐).
   - 영역 공격은 **출구가 열린 자리에만** 둔다(벽 · 맵 밖 검사, E7).
   - 한 번 쓸 때 맞는 수 최대 `OwnMaxHits = 2`(탄은 피격 무적 0.6초가 대신).
   - 동시에 도는 영웅 필살기 수를 공격마다 제한(문턱, E2). 「불 끄고 자!」 · 「타임 세일!」은 영웅 필살기를 멈추고 쓴다.
   - (검토 보탬) **피하는 데 이동이 필요한 공격은 플레이어가 느려진 동안 시작하지 않는다.** 거너 흉내 `DevLockOn`이 플레이어를 0.2배까지 늦추면 16 × 10 사각형에서 5칸 나가는 데 1.2초가 넘어 예고 0.95초로는 피할 수 없다. 규칙: `PlayerController.MoveSlowNow`(새 읽기 전용 · `Time.time < slowUntil ? slowFactor : 1`) `< 0.7`이면 이동 회피 공격(라이브 코딩 · 불 끄고 자 제외 전부)은 자리 잡기처럼 기다린다(같은 상한). 반대로 **고유 공격이 도는 동안 영웅 줄은 거너를 건너뛴다**(다음 영웅으로 · 차례 순서만 한 칸 밀림).
   - (검토 보탬) 「안전 자리」(확인 버튼 · 고리 빈자리 바깥 · 빗자루 빈틈 · 범위 선택 출구)는 `IsWall`뿐 아니라 **`EndlessTerrain.NearZone(자리, 0.5)`(용암 · 늪)도 피한다** — 안전하라고 가리킨 곳이 용암이면 피할 수 없는 공격이 된다.
5. **피해 등급** (raw 는 × `Power`, 상한은 최대 체력 × share / scale, 끝에 × `DevPow`)

| 등급 | raw | share | 개발자 실제 (× 0.8) | 엄마 실제 (× 1.6) |
|---|---|---|---|---|
| 가벼움 | 10 | 0.08 | 6.4% | 12.8% |
| 보통 | 14 | 0.12 | 9.6% | 19.2% |
| 무거움 | 16 | 0.16 | 12.8% | 25.6% |
| 규칙 (불 끄고 자) | 18 | 0.18 | — | 28.8% |
| 최대 (빌드 실패) | 18 | 0.20 | 16% | — |

   (방어 · 피해 감소는 그 뒤에 그대로 걸린다: `taken = 위 값 × (1 − def)` · `PlayerController.cs:1321`.)
6. **엄마판 원칙**: 엄마는 개발자의 「2배」(피해 `DevPow` 2배 · 이동 2배 · 필살기 간격 절반)라는 설정을 따른다. 고유 공격도 **한 대 2배 · 쉬는 간격 짧게 · 예고 짧게(약 0.85배)**. 대신 탄 수는 적고 빠르며, 보스가 직접 움직이는 공격이 있다(D8 비교표).

### C2. 범위 선택 — [구간 0부터]

- **동작**
  1. 플레이어가 사각형 **안쪽 60% 안 무작위 자리**에 오도록 중심을 잡는다(늘 한가운데가 아님). 출구 검사(E7) 실패면 최대 6번 다시 고르고, 그래도 안 되면 플레이어 자리를 중심으로.

  3. 여러 개 선택(구간 1 이상): 첫 끌기가 끝나면 바로 두 번째를 끈다. 두 번째 사각형은 첫 사각형의 한 변에 겹쳐 붙고(중심 = 첫 중심 ± 0.75 × 변), 붙는 쪽은 **플레이어가 움직이던 쪽**(최근 속도) — 나머지 세 쪽은 열려 있다.

- **피해**: 보통(14 · 0.12 → 9.6%) · `OwnMaxHits 2`(삭제 + 붙여넣기).

### C3. 빌드 실패 — [구간 0부터]

- **정체성**: 빌드 버튼을 누르면 머리 위 진행 막대가 차오르고, 100%에서 언제나 실패한다. 노트북에서 오류가 터져 나온다.
- **동작**
  1. 기준점 = 시작 때 보스 자리(고정). 머리 위(기준점 + `extents.y + 1.6`)에 막대: 바탕 검정 α 0.85(선 폭 0.6, 길이 5.5) · 채움 금색 → 75% 넘으면 주황 → 빨강(선 폭 0.42) · 글자 「빌드 중… 47%」(TMP `SetText(format, pct)`, 형식 문자열은 공격마다 한 번 만듦). 머리 위 이름표는 이 공격 동안 숨김(글자가 겹치지 않게).
  2. 동시에 기준점에 경고 원(반지름 R, 시간 = 빌드 시간). 10%마다 `dev_key`(음높이 0.9 → 1.4).
  3. 100%: 막대 빨강 깜빡 · 「빌드 실패!」(빨강, 크게) · `dev_error`(0.8) + `boom`(0.8, 0.85) + 흔들림 0.25 · `fx_explosion`(R × 2.2, 빨강 주황) · `fx_shock`(R × 2.4) · 둘레에 초록 · 흰 글리치 불꽃 12.
  4. 오류 조각: 기준점에서 고리 탄(빨강 구슬 · 글자 「!」 · 반지름 0.4 · 속도 7 · 꼬리 없음).
  5. 다시 빌드 (구간 2): 0.5초 뒤 「다시 빌드…」로 막대가 0.9초에 다시 차고(반지름 6 원) 한 번 더 터짐 + 조각 12.
- **판정**: 기준점에서 거리 < R + 0.2. 조각은 탄 판정.
- **피해**: 폭발 최대(18 · 0.2 → 16%, 예고 1.2초 이상이라 허용) · 조각 가벼움(6.4%) · `OwnMaxHits 2`.

| 구간 | 빌드 시간 | 반지름 R | 조각 |
|---|---|---|---|
| 0 | 1.5초 | 7 | 12발 |
| 1 | 1.35초 | 7 | 16발 |
| 2 | 1.2초 + 다시 빌드 0.9초 | 7.5 / 6 | 16발 + 0.25초 뒤 반 칸 엇갈린 16발 / 다시 빌드 12발 |

- 피하는 법: 막대가 차기 전에 개발자에게서 멀어진다(붙어 싸우는 검사 · 도적에게 거리를 강요하는 공격) → 날아오는 조각 사이 틈으로.

### C4. 오류 창 — [구간 1부터] · 같은 공격 다시 쓰기까지 8초

  3. 확인 0.9초: 빛 띠가 밝아짐(선 폭 9, 따뜻한 흰빛 α 0.28 맥동) · 엄마 머리 위 엄마 눈(`fx_momeye`) · 플레이어 머리 위 「…」.
     - 매 프레임: 빛 안(`DistanceToSegment < 4.5`) **이고** 움직임 → 한 대 + 「안 자고 뭐 해!」 + `mom_slap` + 흔들림 0.2 · 확인 끝.
     - (검토로 고침) 움직임 = `MoveInput.magnitude > 0.25`(의도) **또는** 위치 속도 > **6칸/초가 2프레임 연속**(돌진 · 순간이동 · 몸이 나가는 평타). 예전 값 3칸/초 · 1프레임은 잡몹에게 밀림 · 지형 끼임 풀기 · 프레임 튐에도 걸려 억울한 피격이 된다. `lastPos`는 **확인 시작 프레임에 지금 자리로** 넣는다(넣지 않으면 첫 프레임에 큰 이동으로 잡힘). `Time.deltaTime == 0`(멈춤)인 프레임은 건너뜀.
     - 확인이 시작될 때 이미 움직이고 있던 플레이어를 위해 확인 첫 **0.12초**는 보지 않는다(경고 1.0초 동안 멈출 시간은 충분 · 키를 떼는 반응 시간만 봐줌).
  4. 안 들켰으면 「…자는구나.」(부드러운 흰색) + `chime`(0.25, 0.8).
  5. 다시 확인: 0.5초 뒤 엄마 머리 위 「…진짜 자?」 + 빛 띠를 그때 플레이어 쪽으로 다시 조준(경고 0.8초) + 확인 0.8초. **(검토로 고침) 첫 확인에서 들켰으면 다시 확인은 없다**(「안 자고 뭐 해!」 뒤 엄마가 문을 닫고 끝).
- **피해**: 규칙(18 · 0.18 → 28.8%) · **`OwnMaxHits 1`**(검토로 고침: 2 이면 한 번에 57.6% — 결계 32%와 합쳐 거의 즉사 압박).
- 쏘기 · 제자리 공격은 괜찮다(이동 입력 · 위치 변화만 봄). 몸이 움직이는 기술(돌진 · 순간이동)과 **몸이 앞으로 나가는 평타**(기창 `LanceIntercept` 등)는 움직임으로 친다 — 도움말에 적는다(H4 `mom.lights` 고침).
- 처음 쓸 때만 경고 1.0초 → **1.4초**(규칙을 처음 읽을 시간 · 판마다 처음 한 번 · 난이도 옵션이 아니라 소개 박자). 구간 3 알림 부제(「불 끄고 자!」)와 도움말 `mom.lights`는 **구간 3에 들어설 때** 띄워(첫 사용 전에 읽히게) 첫 사용과 겹치지 않게 한다.
- 처음 한 번 도움말 `mom.lights`.

## E. 영웅 필살기 흉내 · 결계 · 침식과 함께 도는 법

### E1. 두 줄 차례

- **영웅 줄**: 지금 `DeveloperTurn` 그대로(`DevInterval` · `DevMaxRunning` · 알림 · 순서). 바뀌는 것은 맨 앞 가드 하나: `OwnHoldsHero`(자리 잡기 중 · 영웅 멈춤 구간)면 새로 시작하지 않음. (검토 보탬) 그리고 **고유 공격이 도는 동안 차례가 거너면 건너뛰고 다음 영웅**(거너의 플레이어 감속이 고유 공격의 회피 거리를 무너뜨림, B4).
- **고유 줄**: 새 `OwnTurn`. 보스당 한 번에 하나(`ownRunning`). 끝나면 `ownNext = now + OwnRest`.
  - `OwnRest` 개발자 `Lerp(1.8, 3.4, HpFrac)` · 엄마 `Lerp(1.3, 2.5, HpFrac)`.
  - 첫 고유 공격: 등장 뒤 개발자 1.6초(「라이브 코딩」 고정) · 엄마 1.2초(「슬리퍼 투척」 고정).
  - **영웅 줄 첫 차례를 3초 → 4.5초**(개발자 · 엄마만): 첫 고유 공격이 먼저 읽히게(지금은 `Start`의 `next = now + 3`, `BossSkills.cs:49`).
- `DevRunning`(밖에서 보는 값) = 영웅 필살기 수 + (고유 공격 중이면 1). → 결계 대기(`DevReady`)와 침식 대기(`Ready`)가 고유 공격도 기다린다(최대 3초).
- 고유 공격이 「끝남」 = 마지막 판정(또는 마지막 줄 발사 · Ctrl+Z 뒤집기 · 메달 내놓기)이 지난 때. 이미 날아가는 탄 · 쫓는 메달은 세지 않는다(영웅 흉내의 탄과 같음).
- `boss.casting` = 영웅 필살기가 돌거나 고유 공격 중. 둘 중 마지막이 끝날 때만 끈다.

### E2. 문턱 · 자리 잡기 · 영웅 멈춤

| 공격 | 문턱 (이 수 이하로 영웅 필살기가 돌 때만 시작) | 자리 잡기 최대 | 영웅 멈춤 |
|---|---|---|---|
| 라이브 코딩 · 빌드 실패 | 3 | 4초 | 없음 |
| 범위 선택 · 로딩 중… · 스택 오버플로 | 2 | 4초 | 없음 |
| 오류 창 | 1 | 4초 | 경고 동안 |
| 슬리퍼 투척 | 4 | 3초 | 없음 |
| 효자손 | 4 | 3초 | 다가서기 ~ 첫 휘두름 (약 1.3초 · D2) |
| 빗자루질 · 엄친아 | 3 | 3초 | 없음 |
| 타임 세일! | 1 (+ 보스를 옮기는 영웅 흉내 `heroMovers == 0`) | 3초 | 돌진 동안 |
| 불 끄고 자! | 0 + 조용한 시간 1.2초 (D6) | 5초 | 끝까지 (메달도 멈춤) |

- (검토 보탬) 「영웅 멈춤」은 모두 **끝 시각**(`heroHoldUntil = 시작 + 그 공격의 최대 길이 + 0.3`)으로만 건다. 「끝날 때 푼다」는 `bool`을 쓰지 않는다 — 공격이 어떤 길로 끊겨도 시각이 지나면 영웅 줄이 저절로 돌아온다. `FinishOwn` · `CancelOwn` · `AfterDomain`은 0으로.
- (검토 보탬) 플레이어가 느려진 동안(`MoveSlowNow < 0.7`, B4)도 자리 잡기와 같이 기다린다(라이브 코딩 · 불 끄고 자 제외 · 같은 상한).
- 고유 차례가 되었는데 문턱이 막히면 **자리 잡기**: 그 동안 새 영웅 필살기를 시작하지 않는다(도는 것은 끝까지). 수가 문턱 아래로 내려가면 바로 시작. 최대 시간이 지나도 안 되면 이번 차례는 포기 · `ownNext = now + 1.5` · 다음엔 다른 공격을 고름.
- (검토 보탬) **포기한 공격은 「다시 쓰기 시간」 = 자리 잡기 최대 × 2(6 ~ 10초)를 받는다.** 없으면 체력 바닥(영웅 필살기 3 ~ 5개가 늘 돎)에서 불 끄고 자(문턱 0) · 타임 세일(문턱 1)이 번갈아 뽑혀 「자리 잡기 5초 → 포기 → 1초 → 자리 잡기 3초 …」로 **영웅 줄이 대부분 멈추는** 굶주림이 생긴다. 또 자리 잡기 시간 합이 최근 10초 중 6초를 넘으면 다음 고유 차례는 문턱 3 이상인 공격만 고른다.
- 효과: 체력이 높을 때(영웅 필살기 0 ~ 1개)는 거의 기다리지 않고 빈 시간을 고유 공격이 채운다. 바닥 근처(영웅 필살기 3 ~ 5개)에서는 큰 공격 차례마다 잠깐의 「숨 고르기 → 시그니처」 박자가 생긴다.

### E3. 고르기

1. 그 구간에 열린 공격 목록에서, 다시 쓰기 시간(오류 창 8 · 타임 세일 7 · 엄친아 10 · 불 끄고 자 14초)이 안 지난 것 · 상한(메달 2 이상 살아 있으면 엄친아 제외 · 메달이 있으면 불 끄고 자 제외) · **바로 앞에 쓴 것**을 빼고 무작위 하나. 목록이 4개 이상이면 그 앞의 것도 뺀다.
2. 새로 열린 공격(구간 소개)은 1번보다 먼저.
3. 고를 것이 없으면 `ownNext = now + 0.5`.
4. 자리 잡기 중에는 고른 공격을 바꾸지 않는다(문턱이 오락가락하지 않게) — 포기했을 때만 다시 고름.

### E4. 결계 · 침식 · 쉬는 시간

| 상황 | 고유 공격 |
|---|---|
| 게이지가 차서 기다림 (`DevHold`) · 침식 대기 (`ErosionPending`) | 새로 시작 안 함 (`BossSkills.Update` 가 이미 return). 도는 것은 끝까지 — `DevRunning`에 들어 있어 결계가 기다림 |
| 결계 · 침식이 실제로 시작될 때 | **`CancelOwn()`**: 도는 고유 공격을 끊고 그 공격의 표시 · 메달을 지움(피해 없이). 이미 쏜 탄은 그대로(영웅 흉내 탄과 같음) · **멈춰 있던 Ctrl+Z 탄은 되살려 곧 사라지게**(C1). (검토로 고침) **이 공격이 띄운 경고 원 · 띠(`Telegraph`)도 거둔다** — 그대로 두면 컷신(시간 멈춤) 뒤 결계 안에서 피해 없는 가짜 경고가 남은 시간 동안 보여, 결계 공격을 읽는 것을 방해한다. `Telegraph`에 「쓰임 번호」(`useId`, `Init*`마다 +1)와 `EndEarly(int useId)`(번호가 같을 때만 풀로 돌림)를 더하고, 고유 공격은 띄운 경고의 `(Telegraph, useId)`를 고정 배열(최대 16)에 적어 둔다 |
| 결계 중 · 침식 중 | 없음 (`Active`) · 안전장치: `Update`에서 `Active`인데 `ownRunning`이면 `CancelOwn()` |
| 결계 · 침식이 끝남 | `AfterDomain(2f)` → 영웅 2초 뒤 · **고유 2.5초 뒤**(자리 잡기 · 영웅 멈춤 초기화) |
| 보스가 쓰러짐 | `CancelOwn()` (쓰러지는 1초 동안 표시가 멈춘 채 남지 않게) · 메달도 `TickMedals`가 `!Alive`면 지움 |
| 보스를 옮기는 영웅 흉내 (검사 `DevSpin` · 도적 `DevDash` · 유령 `DevPossess` — 유령은 지금 차례에서 건너뛰지만 나중에 되살릴 때를 위해 목록에 둠) | `DeveloperTurn`이 이 셋을 시작할 때 `heroMovers++`, `DevRun`이 끝날 때 `heroMovers--`(`DevRun(routine, mover)`로 깃발을 넘김). (검토 보탬) 누수 대비: `devRunning`이 0이 되는 순간 `heroMovers = 0`으로 맞춘다(영웅 흉내가 예외로 죽어 `--`가 빠져도 타임 세일이 영원히 막히지 않게). 도적처럼 돌진 사이사이 쉬는 동안에도 0이 아니므로, 타임 세일은 `heroMovers == 0`일 때만 시작하고 돌진 동안 새 영웅 필살기를 멈춤 · 효자손은 다가서지 않음 → 보스 위치를 두 코루틴이 동시에 쓰지 않음 |

### E7. 공정성 점검표 (구현 때 함수로)

- `PathClear(from, to)`: 선분 위 세 점이 맵 안(`Hostile.InArena`)이고 벽 아님(`Hostile.IsWall`).
- 범위 선택 · 오류 창: 플레이어 → 각 변 바깥 1.2칸 네 방향 중 **둘 이상** `PathClear`(오류 창은 하나 이상 + 버튼까지 `PathClear`). 아니면 다시 고름(최대 6번).
- 로딩 중…: 처음 빈자리 방향의 탈출 길 `PathClear`.
- 빗자루질: 시작 · 끝 가운데가 맵 안, 플레이어 → 빈틈 가로 이동 `PathClear`.
- 타임 세일 · 효자손 다가서기 · 슬리퍼 목표: 끝점 `ClampArena` + 벽이면 줄임.
- 스택 오버플로 탑 · 빌드 실패 기준점: 보스 자리라 늘 맵 안.
- 모든 경고 시간 ≥ 바닥(개발자 0.5 · 엄마 0.42) — 표의 수치가 이미 지킴. 상수는 바닥과 비교하는 `OwnTele(s)`를 거친다(나중에 수치를 바꿔도 바닥 아래로 내려가지 않게).
- (검토 보탬) 안전 자리 검사 `SafeSpot(p)` = `InArena` · `!IsWall` · `!EndlessTerrain.NearZone(p, 0.5)`. `PathClear`의 세 점도 `SafeSpot`.
- (검토 보탬) 회피 거리 검사: 이동으로 피하는 공격은 시작 때 `필요 거리 ÷ (20 × MoveSlowNow) + 0.15 ≤ 경고 시간`을 확인하고, 아니면 시작하지 않는다(B4 · 감속 중 대기와 같은 뜻 · 구현은 한 함수 `CanOutrun(dist, warn)`).

### E8. 끊길 때 되돌릴 상태 · 기다림의 시간 상한 (검토 보탬 · 반드시 지킴)

1.2.7 사고(리치 의식이 끊겨 무적이 남고 침식 · 15분이 영원히 멈춤)의 교훈: **켜 둔 상태는 끊기는 모든 길에서 되돌아가야 하고, 모든 기다림에는 시각 상한이 있어야 한다.** 개발자 · 엄마에게는 `ClearSkillState` · `BusyWatchdog` · `CancelForErosion`이 돌지 않으므로(머리말) 고유 공격이 스스로 지킨다.

**모든 `while` 기다림**은 `while (Time.time < t && e == ownEpoch && Alive) yield return null;` 꼴로 **시각 끝**을 갖는다 — 「무엇이 될 때까지」(예: 메달이 깨질 때까지 · 플레이어가 멈출 때까지) 기다리는 루프는 쓰지 않는다.

### E9. 빨라진 결계 게이지와 합친 압박 (검토 보탬)

- 리듬(A3): 개발자 · 엄마 모두 **결계(연출 포함 약 15 ~ 18초) ↔ 결계 사이(약 15초)**가 번갈아 온다. 싸움 시간의 거의 절반이 결계다. 고유 공격은 결계 사이 창에서 결계가 사라진 뒤 약 1.9초부터 · 다음 결계 대기(최대 3초) 전까지, 실질 약 10 ~ 12초에 산다.
- 결계 사이 창 하나에서 받을 수 있는 최대 피해(체력 바닥 · 모두 맞는다고 가정, 피격 무적 0.6초가 사이를 벌림):
  - 개발자: 고유 3번 × 최대 2대 × 6.4 ~ 16% + 영웅 흉내. 고유 몫 최대 약 50% — **대부분 가벼움 · 보통이라 실제 평균은 15 ~ 25%**.
  - 엄마(이번 검토로 효자손 · 불 끄고 자 1대 · 메달 묶음 2대): 고유 3 ~ 4번 × 19.2 ~ 28.8%. 고유 몫 최대 약 90% — 피하지 못하면 결계 하나 없이도 쓰러질 수 있는 압박이다. 엄마는 「모든 능력 2배」 설정의 최종 보스라 의도된 세기지만, **결계 32% 한 대와 고유 28.8%가 0.6초 간격으로 이어지면 61%** 이므로 다음을 지킨다:
    1. 결계 · 침식이 끝나고 고유 첫 공격은 **가벼운 것만**(개발자 라이브 코딩 · 범위 선택, 엄마 슬리퍼 · 빗자루) — 결계를 막 버틴 직후 무거운 한 방이 바로 오지 않게.
    2. 결계 대기(`DevHold`) 중에는 이미 도는 고유 공격도 **새 휘두름 · 새 줄 · 새 슬리퍼를 더 시작하지 않고** 지금 경고 중인 것까지만 끝냄(대기 3초 동안 고유 + 곧 결계 컷신이 겹치지 않게).
    3. 수치 조정은 N 절의 손잡이(엄마 고유 share ×0.85)로 — 밸런스 패치노트에 「무엇이 · 얼마 → 얼마」로 적는다.
- QA 측정 제안(손으로 · 일괄 실행 없이): 엄마전 한 판에서 결과 화면 「받은 피해」의 「개발자 엄마 · 〈기술〉」 합과 「보스 결계」 합을 비교 — 고유 합이 결계 합의 1.5배를 넘으면 엄마 고유 share 를 ×0.85.

### H6. 받은 피해 이름 (`AttackLabel`)

- 고유 공격의 모든 피해는 「〈보스 이름〉 · 〈기술 이름〉」: 예) 「개발자 · 라이브 코딩」, 「개발자 엄마 · 불 끄고 자!」. 직접 판정은 `AttackLabel.Pending`, 탄은 `h.label`. 문자열은 보스 · 기술마다 **정적 표**(할당 없음).
- 결과 화면 「받은 피해」 · 「쓰러진 곳」은 `AttackLabel.Translate`가 부분마다 번역 → 「Developer · Live Coding」.
- `AttackLabel.BossSkill` 표(`AttackLabel.cs:13-26`)에도 고유 공격 코루틴 이름 → 기술 이름을 더한다(`Pending`이 빠졌을 때의 대비).

### H7. 망자의 전령 (`Herald`)

지금 `cause=개발자`는 원인이 **정확히** 「개발자」일 때만 맞고(`Herald.cs:172`), 조건은 `·`로 나뉘어 「개발자 · 라이브 코딩」을 조건에 쓸 수 없다. 고친다:
- `Facts`에 `causeHead`(원인의 「 · 」 앞) · `skill`(뒤)을 더한다(`Gather`, `Herald.cs:54`).
- `Matches`의 `cause`: `v == cause` → 8점, `v == causeHead` → 6점(지금의 개발자 · 엄마 줄이 고유 공격 사망에도 나옴). 새 키 `skill`: `v == skill` → 8점.
- 새 줄(`Herald.Lines.cs` 표 + `LocTable.Herald.cs`의 `A`): 조건 「cause=개발자 · skill=라이브 코딩」처럼(6 + 8 = 14점이라 일반 줄보다 먼저).

### I1. 풀 · 상한 (보스마다, 처음 쓸 때 만들고 다시 씀)

`BossSkills`에 `GameObject ownRoot`(「DevOwnRoot」, 세계 원점, `Own(ownRoot)`로 `owned`에 넣음) 하나를 두고 모든 풀을 그 아래에 둔다 → 보스가 사라지면(`OnDisable`, `BossSkills.cs:39-43`) 한 번에 지워진다.

| 풀 | 최대 | 만드는 법 | 쓰는 곳 |
|---|---|---|---|
| 월드 글자 `TextMeshPro` | 8 | `new GameObject` + `AddComponent<TextMeshPro>` · 글꼴 `UIKit.Font` · 재질 `Notice.WorldMaterial` · `Effect` 층 45 | 터미널 · 빌드 · 창 3 · 로딩 · 스택 · 번호 · 불 끄고 자 2 |
| 실선 `LineRenderer` | 12 | `Hostile.NewLine` | 빌드 막대 2 · 창 테두리 · 버튼 고리 · 부채꼴 테두리 · 밑선 · 진행 호 · 빛 띠 |
| 점선 | 8 | `SpecialAbilities.SharedFx.NewLine(name, true)` — **인스턴스 함수**(정적 아님) · **재질이 하나씩 생기므로 보스마다 8개만 한 번** · 만든 뒤 **`ownRoot` 아래로 옮김**(안 옮기면 보스가 지워져도 장면 끝까지 남음) · `SharedFx`가 null 이면 실선 `Hostile.NewLine`으로 대신 | 선택 사각형 둘 |
| 점 (구슬 모양) | 48 | `MakeSprite(Glow)` + `HostileProjectile.Dress` + 글리프 자식 | 로딩 고리 · 주석 유령 글자(30) |
| 블록 | 24 | `MakeSprite(fx_codeblock)` | 스택 |
| 아이콘 | 12 | `MakeSprite` (그림은 쓸 때 바꿈) | 커서 · 키캡 · 빗자루 7 · 효자손 · 엄마 눈 · 후광 |
| 사각 스프라이트 | 6 | `MakeSprite(OwnWhite)` | 삭제 번쩍임 · 창 그림자 · 제목 막대 |
| 부채꼴 | 1 | `MeshFilter`(정적 메시) + `MeshRenderer` | 효자손 |

- 슬리퍼(공격당 최대 3)는 `Fx.Play(loop)`로 만들고 끝나면 지움 · 혹시 몰라 `Own`에 넣음.
- 메달은 `BossPart.Make`(새 오브젝트) · 말풍선 TMP 는 메달 자식 → 메달과 함께 지워짐 · 살아 있는 것 최대 3 · 목록 `List<Medal>`을 재사용.
- 탄: `Hostile.Shoot`(풀). 고유 탄 상한 320. Ctrl+Z 를 위해 `(HostileProjectile, Serial)` 목록을 재사용(정적 배열).

### I2. `Instantiate` 금지

이번 작업에는 `Instantiate`가 없다. 모든 표시는 `new GameObject` + 필요한 컴포넌트(SpriteRenderer · TMP · LineRenderer · MeshRenderer)만. 풀 오브젝트에 **스크립트 컴포넌트를 붙이지 않는다**(메달 움직임도 `BossSkills`의 목록이 돌림 · `BossPart`만 예외로 원래 쓰던 것).

(검토 보탬)
- 스크립트가 붙는 새 오브젝트는 기존 도구가 만드는 것뿐이다: `SkillTag`(공격마다 하나 · `HideOwnTag`가 지움 · 대상이 없어지면 스스로 지움) · `Fx.Play`의 `FxAnim`(슬리퍼) · `FadeSprite`(타임 세일 잔상) · `BossPart`(메달). 모두 **`Update`에서 자기 자신이나 다른 스크립트 붙은 오브젝트를 만들지 않는다** — 1.1.8 ~ 1.2.0 의 「스크립트 붙은 오브젝트를 `Instantiate`로 복제 → 매 프레임 증식」과 같은 길이 없음을 구현 뒤 한 번 더 확인(`git grep -n "Instantiate" -- "Assets/Scripts/BossSkills.*Own*.cs"` 결과 0).
- 잔상 `FadeSprite`는 0.03초 → **0.05초마다 · 공격당 최대 30개**(돌진 2바퀴 약 3초에 60개가 생기던 것).
- 보스 오브젝트(`gameObject`) · 보스 그림 · 풀 항목을 `Instantiate(…)`로 복제해 잔상 · 분신을 만들지 않는다 — 잔상은 지금처럼 스프라이트만 옮겨 담은 `FadeSprite`.

### I3. 정리 경로

| 언제 | 무엇을 |
|---|---|
| 공격이 정상으로 끝남 | 그 공격이 쓴 풀 항목 `SetActive(false)` · 이름표 지움 · `ownRunning = false` |
| `CancelOwn()` (결계 · 침식 시작, 보스 쓰러짐, `Active` 안전장치) | `StopCoroutine(ownCo)` · `ownEpoch++` · 모든 풀 숨김 · 슬리퍼 지움 · 메달 지움(작은 `fx_spark`, 피해 없음) · 자리 잡기 · 영웅 멈춤 초기화 · `casting`은 영웅 필살기가 없고 `BossUltimate.Active`가 아닐 때만 끔 |
| 보스 오브젝트가 지워짐 · 장면 전환 | `OnDisable` → `owned`(ownRoot 포함) 모두 지움 · 코루틴은 Unity 가 멈춤 |
| 점선 재질 | `SpecialFeedback.OnDestroy`가 장면 끝에 지움(지금 규칙) |
| 정적 | `ConeMesh` · `OwnWhite` · 글리프 배열 · 정적 표만 (판 사이 상태 없음). `ownGlobalOwner`는 보스 참조라 장면이 바뀌면 Unity null → 무해 · `FinishOwn` · `CancelOwn` · `OnDisable`에서 자기가 주인이면 null 로 · (검토 보탬) **`BossUltimate.ResetStatics`에서도 null**(1.2.8 의 「장면 시작 때 정적 상태 비움」과 같은 자리 · `BossSkills.ResetOwnStatics()`를 부름) |
| 정리 한 곳 (검토 보탬) | `FinishOwn` · `CancelOwn` · 감시가 **같은 `ResetOwnState()`** 를 부른다 — 공격마다 「정상 끝」과 「끊김」 정리 코드를 따로 쓰면 한쪽이 빠진다. 공격 코드 안에서는 정리하지 않고, 풀 항목은 「이번 공격이 켠 목록」(고정 배열)에 적어 두었다가 `ResetOwnState`가 끔 |

- **고유 공격은 코루틴 하나 안에서 모든 움직임을 같이 갱신한다**(여러 슬리퍼 · 여러 줄 · 두 고리 · 두 탑). 하위 `StartCoroutine`을 쓰지 않아야 `StopCoroutine(ownCo)` 한 번으로 다 멈춘다.
- 정적 이벤트 구독 없음.

### I4. 할당 0

- 매 프레임 문자열을 만들지 않는다: 진행 % · 스택 수는 TMP `SetText(format, value)`(형식은 공격마다 한 번) · 터미널 글자는 `maxVisibleCharacters`.
- 목록은 필드에 두고 `Clear()` 재사용 · LINQ · 캡처 람다 없음 · 대기는 `while (Time.time < t) yield return null;`.
- 받은 피해 이름은 정적 표(보스 2 × 기술 12).

### I5. 예상 부하

가장 무거운 순간(개발자 구간 2 · 라이브 코딩 6줄): 탄 약 150(꼬리 없음 → 지금 영웅 흉내 탄 400 · 꼬리보다 가벼움) + 글리프 자식 150. 다른 공격은 선 몇 개 · 점 48 이하. 지금 개발자전 최대 부하(필살기 8겹 · 탄 400)를 넘지 않는다.

## K. 엣지 케이스

1. **결계가 3초 넘게 기다려 고유 공격 위에 펼쳐짐** → `CancelOwn` (도는 영웅 필살기는 지금처럼 계속 — 바꾸지 않음).
2. **보스가 쓰러지는 중** → `Update`에서 `!Alive && ownRunning` → `CancelOwn` · 이미 쏜 탄은 날아감(영웅 흉내와 같음).
3. **플레이어가 쓰러짐** → 판정 함수가 `IsDying`이면 피해 없음 · 표시는 공격 끝까지(장면이 곧 바뀜).
4. **플레이어가 무적**(돌진 무적 · 최후의 보루 · 결계 직후) → `TryHit` false · 맞은 수에 안 셈.
5. **영웅 흉내가 보스를 옮김** → 예고 자리 고정(빌드 · 스택) · 효자손은 다가서지 않음 · 타임 세일은 시작하지 않음(`heroMovers`, E4).
6. **보스 몸 색 싸움**(빙의 투명 · 속달 깜빡) → 고유 공격은 몸 색을 쓰지 않고 후광만.
7. **맵 가장자리 · 벽** → E7 출구 검사 · 끝점 줄이기 · 고리 빈자리 방향.
8. **탄 상한** → 줄 통째로 건너뜀(반쯤 잘린 벽 없음).
9. **탄이 플레이어 기술에 지워짐**(쳐내기 · 최후의 보루 · 지우개 · 자명종 · 초월) → Ctrl+Z 목록은 `h != null && h.isActiveAndEnabled && h.Serial == 저장값`일 때만 뒤집음(지워졌거나 다른 공격이 다시 쓴 탄은 건드리지 않음).
10. **주석 유령 글자** → 탄이 아니라 지워지지 않음 · 피해 없음.
11. **메달이 「불 끄고 자」와 겹침** → 메달 정지 · 메달이 있으면 불 끄고 자를 고르지 않음.
12. **게임패드 스틱 흔들림** → 이동 판정은 `MoveInput.magnitude > 0.25` + 위치 속도 3칸/초.
13. **트레일러 자동 조종** (`GameInput.Auto`) → 도움말 안 뜸(지금 규칙) · 공격은 그대로.
14. **언어를 판 중간에 바꿈** → 공격을 시작할 때 번역 · 다음 공격부터 새 언어.
15. **색각 모드** → 경고는 `Telegraph`가 · 직접 그리는 선 · 글자 · 부채꼴은 `Hostile.Accessible`.
16. **번쩍임 · 화면 흔들림 끔** → 삭제 · 쾅 번쩍임 α 0.2 · 흔들림은 `Hostile.Shake`가 설정을 따름.
17. **그래픽 품질 낮음** → `Fx.Spawn` 장식 예산(지금 규칙) · 글리프는 그대로(판독용).
18. **일시정지 · 컷신(`timeScale 0`)** → `Time.time` 기준 루프라 함께 멈춤. 월드 글자는 UI 아래라 메뉴를 덮지 않음.
19. **큰 피해로 구간 둘을 한 번에 넘음** → 마지막 구간 알림만 · 새 공격은 모두 열고 소개는 차례로.
20. **개발자와 엄마가 함께(이어하기 드문 경우)** → `ownGlobalOwner`로 둘 합쳐 고유 공격 1 · 구간 알림은 각자.
21. **엄마 다가서기 중 결계 시작** → `CancelOwn`이 위치 이동을 멈춤(그 자리에서 결계 · 결계 중심은 보스 자리, `BossUltimate.cs:177`).
22. **빗자루 띠가 프레임 끊김으로 건너뜀** → 판정 폭 1.4 · 프레임 이동 0.22(60fps) · 큰 끊김(Δt > 0.1)에서는 지난 위치 ~ 지금 위치 구간을 합쳐 판정.
23. **슬리퍼 · 돌진이 빠름** → 선분 판정(지난 자리 → 지금 자리).
24. **메달을 범위 공격이 한꺼번에 깨뜨림** → 「비교 거부!」는 0.6초에 한 번(`FloatText` throttle).
25. **오류 창 버튼 위에 영웅 흉내 경고 원** → 창 밖 출구가 있음 + 창 경고 동안 새 영웅 필살기 없음.
26. **로딩 고리가 영웅 흉내 경고와 겹쳐 빈자리가 막힘** → 문턱 2 · 고리 시간 1.4 ~ 1.8초 동안 빈자리가 돌아 다른 각도로 기회.
27. **약한 잡몹(1초 4마리)이 「자는 척」을 방해** → 쏘기는 괜찮음(움직임만 봄) · 빛 밖으로 나가도 됨.
28. **HP 회복 등으로 구간이 다시 올라감** → 구간은 내려가지 않음(가장 낮았던 구간 유지).
29. (검토) **거너 흉내 감속 중** → 이동 회피 고유 공격은 시작하지 않고(B4), 고유 공격 중엔 거너 차례를 건너뜀(E1).
30. (검토) **안전 자리가 용암 · 늪** → `SafeSpot`이 `NearZone`으로 거름(E7). 오류 창 버튼 자리가 하나도 없으면 오류 창을 이번엔 쓰지 않음(C4).
31. (검토) **Ctrl+Z 로 멈춘 탄이 있을 때 결계 시작** → 탄 속도 되살림 + 곧 사라짐(C1 · E8).
32. (검토) **고유 공격 경고가 떠 있을 때 결계 시작** → 그 경고들 `EndEarly`(E4).
33. (검토) **고유 코루틴 · `TickMedals` · `OwnTurn` 예외** → 감시 12초 · `try/catch`가 정리(E8). 이때도 영웅 줄 · 결계 · 침식은 막히지 않음(멈춤 · 대기는 모두 끝 시각).

    bool OtherOwnBusy => ownGlobalOwner != null && ownGlobalOwner != this && ownGlobalOwner.ownRunning;

    void OwnTurn(PlayerController p)
    {
        if (ownNext < 0f) ownNext = Time.time + (boss.developerMom ? OwnFirstMom : OwnFirstDev);
        UpdateOwnPhase();                                   // 구간 오름 → 알림 · introQueue

        else if (Time.time - ownClaimSince >= ClaimMaxOf(ownPick))

    }

        yield return RoutineOf(a, e);                       // LiveCoding(e) … LightsOut(e)
        if (e == ownEpoch) FinishOwn();
    }

        if (devRunning == 0 && !BossUltimate.Active && boss != null) boss.casting = false;
    }

    {
        ownClaimSince = -1f; heroHoldUntil = 0f; ownPick = Own.None;
        if (ownCo != null) { StopCoroutine(ownCo); ownCo = null; }

        if (ownGlobalOwner == this) ownGlobalOwner = null;
        if (!ownRunning) return;
        ownRunning = false; HideOwnPools(); HideOwnTag();

    }

    //   heroHoldUntil = medalFreezeUntil = 0 · 클레임 −1 · 이번 공격이 켠 풀 항목 끔 · 이름표 · 후광 숨김
    //   · 띄운 Telegraph 를 EndEarly(useId) · Ctrl+Z 로 멈춘 탄 되살림(speed 복원 · life = Age + 0.6)

    {
        try
        {
            bool medals = medalCount > 0;
            if ((ownRunning || medals) && (!Alive || BossUltimate.Active)) CancelOwn();
            else if (ownRunning && Time.time - ownStartedAt > OwnWatchdog) { Debug.LogWarning("고유 공격 감시: 끊음 " + ownPickRunning); CancelOwn(); }
            if (medals) TickMedals();
        }
        catch (System.Exception ex) { Debug.LogException(ex); CancelOwn(); ownNext = Time.time + 5f; }
    }

    float OwnDmg(float raw, float share)
    {
        PlayerController pl = Hostile.Player;
        float v = raw * Power;
        if (pl != null) v = Mathf.Min(v, pl.PlayerMaxHealth * share / Mathf.Max(0.01f, GameMode.DamageMul * Chapters.HurtMul));
        return v * DevPow;
    }

    {
        PlayerController pl = Hostile.Player;
        if (!inside || pl == null || pl.IsDying || ownHits >= OwnMaxHits) return false;
        AttackLabel.Pending = OwnLabel(a);                  // 정적 표 「개발자 · 라이브 코딩」
        bool hit = pl.TryHit(OwnDmg(raw, share));
        AttackLabel.Pending = null;
        if (hit) ownHits++;
        return hit;
    }
}
