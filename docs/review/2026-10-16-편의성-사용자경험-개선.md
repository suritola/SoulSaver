## 번역 방식 (모든 항목 공통)

- 한국어 문장이 열쇠. `LocTable.Entries["한국어"] = L(en, ja, zh)` (`LocTable.cs:6-9`). `UIKit.Text` · `UIKit.MakeButton` · `Loc.T()` 가 자동 번역하고, 언어를 바꾸면 `UIKit.Remember` 로 다시 쓴다.
- 새 문구는 **새 파일 `Assets/Scripts/LocTable.Ux.cs`** 에 `LocTable.Notice.cs:7-26` 과 같은 꼴로 넣는다 (정적 생성자를 건드리지 않음 · 키 중복 크래시 방지):
  ```csharp
  public static partial class LocTable
  {
      [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
      static void AddUx()
      {
          void C(string key, string ko, string en, string ja, string zh) { if (!Entries.ContainsKey(key)) Entries[key] = E(ko, en, ja, zh); }
          C("게임패드 연결이 끊어졌습니다", "게임패드 연결이 끊어졌습니다", "Gamepad disconnected", "ゲームパッドの接続が切れました", "手柄已断开连接");
          // … 아래 각 항목의 문구 표
      }
  }
  ```
- 키 표시는 `{INTERACT}` `{REROLL}` 처럼 쓰면 `KeyBindings.Apply` (`KeyBindings.cs:457-478`) 가 바뀐 키 · 패드 버튼 이름으로 바꾼다. 안내문에 `[ESC]` 를 쓰면 패드일 때 `[B]` 가 된다.
- 체험판: `Demo.On` 분기가 필요한 항목만 따로 표시. 나머지는 체험판 빌드(`SOULSAVER_DEMO`)에 그대로 들어간다.

## 1. 스팀 오버레이 · 게임패드 분리 때 자동 일시정지

**문제**
- 자동 일시정지는 창 포커스를 잃을 때만 (`ESCmenu.cs:48-53`). 스팀 오버레이(Shift+Tab · 패드 가이드 버튼 · 스팀 덱 스팀 버튼)는 창 포커스를 빼앗지 않아, 오버레이가 화면을 덮은 채 게임이 계속 돌아간다 → 친구 메시지에 답하다 죽는다.
- `SteamManager.cs` 에 스팀 콜백은 `PersonaStateChange_t` 하나 (`442-447`). `GameOverlayActivated_t` 는 없다 (grep 0건).
- 패드가 빠지면 `GamePad.Poll` (`GamePad.cs:103-160`) 은 축이 0 으로 읽혀 조용히 멈출 뿐, 감지 · 안내 · 멈춤이 없다 (`GetJoystickNames` grep 0건). 플레이어는 캐릭터가 서 있는 채 맞는다.

**해결**
1. `ESCmenu.cs` — `OnApplicationFocus` 의 몸통을 빼내 둘이 같이 쓴다.
   ```csharp
   // 바깥 요인(포커스 잃음 · 스팀 오버레이 · 패드 분리)으로 멈춰야 할 때
   public void PauseFromOutside()
   {
       if (isEscOpen || GameInput.Auto || Application.isBatchMode || StoryDirector.Playing) return;
       if (Time.timeScale == 0f || (shop != null && shop.isShopOpen)) return;
       ToggleEsc();
   }
   public static void RequestPause() => FindFirstObjectByType<ESCmenu>()?.PauseFromOutside();   // 게임 씬이 아니면 null → 아무 일 없음
   void OnApplicationFocus(bool focus) { if (!focus) PauseFromOutside(); }
   ```
2. `SteamManager.cs` — `Initialized = SteamAPI.Init()` (`68`) 바로 뒤, `#if STEAM` 안에:
   ```csharp
   static Callback<GameOverlayActivated_t> overlayHook;
   if (Initialized) overlayHook = Callback<GameOverlayActivated_t>.Create(e => { if (e.m_bActive != 0) ESCmenu.RequestPause(); });
   ```
   오버레이를 **닫을 때는 아무것도 하지 않음** (Alt+Tab 복귀와 같게, 플레이어가 ESC 로 직접 재개). `SteamAPI.RunCallbacks()` 는 이미 `Update` (`183-187`) 에서 돈다.
3. `GamePad.cs` — `Poll` 끝(또는 `Update`, `390-394`)에 1초마다(실제 시간) 패드 수를 센다.
   ```csharp
   static int padCount = -1; static float nextPadScan;
   static void ScanPads()
   {
       if (Time.unscaledTime < nextPadScan) return;
       nextPadScan = Time.unscaledTime + 1f;
       int n = 0; foreach (string s in Input.GetJoystickNames()) if (!string.IsNullOrEmpty(s)) n++;
       if (padCount < 0) { padCount = n; return; }                       // 처음 한 번은 기준만
       bool inGame = SceneManager.GetActiveScene().name == "GameScene";
       if (padCount > 0 && n == 0)
       {
           bool wasActive = Active;
           SetActive(false);                                               // 안내 글자 · 커서를 키보드로
           if (wasActive && inGame) { ESCmenu.RequestPause(); Notice.Toast(NoticeIcon.Warn, Loc.T("게임패드 연결이 끊어졌습니다"), 4f); }
       }
       else if (padCount == 0 && n > 0 && inGame) Notice.Toast(NoticeIcon.Info, Loc.T("게임패드가 연결되었습니다"), 3f);
       padCount = n;
   }
   ```
   `Notice.Toast` 는 HUD 캔버스(게임 씬)에만 있으므로 `inGame` 일 때만 띄움.

**예외**
- 보스전 · 습격 중: 멈춰도 안전 (timeScale 0). 레벨업 · 보상 · 상점 창이 열린 상태: `Time.timeScale == 0f` 라 그대로 둠(이미 멈춤). 일시정지 중: `isEscOpen` 이라 무시. 이야기 · 보스 등장 연출: `StoryDirector.Playing` 이라 무시(연출은 건너뛰기 키가 따로). 튜토리얼: 그대로 적용(튜토리얼도 ESC 메뉴를 씀). 이어하기 복원 중(`RunSave.Restore`): 멈춰도 복원 코루틴은 unscaled 가 아니라 다음 프레임에 이어지므로 문제 없음. 메인 메뉴 · 결과 화면: `ESCmenu` 가 없어 아무 일 없음(오버레이는 원래 메뉴를 가리지 않음).
- 패드가 쓰던 중 아니었으면(키보드로 플레이 중 패드가 빠짐) 멈추지 않고 안내만 생략.
- GameSettings: 새 설정 없음 — 「포커스 잃을 때 멈춤」과 같은 규칙으로 늘 켜짐. 키 바꾸기와 무관.
- 체험판: 포함 (`SteamManager` 는 체험판에도 `DemoAppId` 로 들어감).

## 2. 전투 중 마우스 커서를 창 안에 가두기 (설정 「게임」)

**문제**
- `Cursor.lockState` 를 쓰는 곳이 없다 (grep 0건). 창 모드에서 화면 가장자리 적을 조준하면 커서가 창 밖으로 나가고, 거기서 클릭하면 포커스를 잃어 **전투 중에 갑자기 일시정지**(`ESCmenu.cs:48-53`)된다. 모니터 두 대면 전체 화면(FullScreenWindow)에서도 커서가 옆 모니터로 넘어가 조준이 끊긴다.
- `CursorSkin.cs` (`21-39`) 는 커서 그림만 바꾸고 가두지 않는다.

**해결**
1. `GameSettings.cs` — 키 · 필드 · 속성 추가 (`9-27`, `35`, `96-119` 패턴):
   ```csharp
   const string ConfineKey = "settings.confineCursor";
   static bool confineCursor = true;
   // Load(): confineCursor = Prefs.GetInt(ConfineKey, 1) == 1;
   public static bool ConfineCursor { get { Load(); return confineCursor; } set { Load(); confineCursor = value; Prefs.SetInt(ConfineKey, value ? 1 : 0); } }
   ```
2. `CursorSkin.cs` (DontDestroyOnLoad, `Update` 가 이미 매 프레임 돈다) — 상태를 계산해 바뀔 때만 적용:
   ```csharp
   static CursorLockMode applied = CursorLockMode.None;
   void UpdateConfine()
   {
       bool inGame = SceneManager.GetActiveScene().name == "GameScene";
       bool want = GameSettings.ConfineCursor && inGame && Application.isFocused && Time.timeScale > 0f
                   && !ESCmenu.IsOpen && !GamePad.Active && !StoryDirector.Playing && !BossUltimate.CutscenePlaying;
       CursorLockMode m = want ? CursorLockMode.Confined : CursorLockMode.None;
       if (m != applied) { applied = m; Cursor.lockState = m; }
   }
   ```
   `OnApplicationFocus(false)` 에서도 `None` 으로(알트탭 뒤 커서가 자유롭게).
3. `MenuExtras.cs BuildGameplay` (`825-855`) — 줄 하나 추가. 지금 7줄이 75 간격(200 ~ -250)이라 꽉 찼으므로 **항목 6 과 함께 9줄 · 60 간격**으로 다시 놓는다: y = 200, 140, 80, 20, -40, -100, -160, -220, -280. 그에 맞춰 `Open` (`630`) 의 `page` 를 `UIKit.Rect("Page", win, new Vector2(0f, -40f), new Vector2(1100f, 600f))` 로 (아래 끝 -340, 「닫기」 위 끝 -326 과 겹치지 않음 — 마지막 줄 상자 아래 끝 -305).
   ```csharp
   ToggleRow("커서를 창 안에 가두기", -220f, () => GameSettings.ConfineCursor, v => GameSettings.ConfineCursor = v,
             "전투 중 마우스가 창 밖으로 나가지 않게 합니다. 멈춘 화면 · 메뉴 · 패드를 쓸 때는 풀립니다. 창 모드나 모니터가 두 대일 때 유용합니다.");
   ```

**예외**
- 레벨업 · 보상 · 상점 · 영혼 트리 · 일시정지(모두 timeScale 0): 풀림 → 창 밖으로 자유롭게. 보스 결계 컷신: `BossUltimate.CutscenePlaying` 으로 풀림. 이야기 연출: 풀림. 튜토리얼: 전투와 같게 적용. 이어하기: 복원이 끝나 시간이 흐르면 자동 적용.
- 게임패드: `GamePad.Active` 면 풀림(패드 중엔 OS 커서가 숨겨져 있음 `GamePad.cs:168`). 패드 → 마우스로 돌아오면 다음 프레임에 다시 가둠.
- Alt+Tab · Win 키는 OS 가 처리하므로 막히지 않음. macOS 는 Confined 를 지원하지 않아 None 과 같음(무해).
- 키 바꾸기: 무관. 체험판: 포함.

## 3. 설정 탭마다 「이 탭 기본값으로」

**문제**
- 「기본값으로」는 조작 탭에만 있다 (`MenuExtras.cs:950-956` → `KeyBindings.ResetAll`). 일반(볼륨 3개 · 마우스 감도 · 비활성 음소거) · 화면(UI 크기 · 안내 크기 · 수직 동기화 · 흔들림 · 번쩍임) · 게임(7개) 탭에는 없고, `GameSettings.cs` 에 되돌리기 함수가 없다.
- 감도를 300% 로 올려 보거나 UI 를 80% 로 줄여 본 플레이어는 원래 값(100% · 100% · 볼륨 50%)을 기억해서 손으로 되돌려야 한다.

**해결**
1. `GameSettings.cs` — 속성 setter 를 거쳐 되돌린다(부수 효과 — `AudioListener.volume` · `UiScaler.ApplyAll` · `CursorSkin.Refresh` · `ApplyVSync` — 가 그대로 따라옴):
   ```csharp
   public static void ResetGeneral()  { Volume = 0.5f; MusicVolume = 1f; SfxVolume = 1f; MouseSensitivity = 1f; MuteUnfocused = true; Save(); }          // 언어는 그대로
   public static void ResetDisplay()  { UiScaleIndex = 2; NoticeSize = 1; VSync = true; ScreenShake = true; Flashes = true; Save(); }                   // 화면 모드 · 해상도는 그대로
   public static void ResetGameplay() { Hints = true; DamageNumbers = 0; MyFxAlphaIndex = 0; ColorBlind = false; GameCursor = true; AutoLevelUp = false;
                                        ConfineCursor = true; OneClickPick = false; CodexSeen.ShowAll = false; Save(); }                               // 항목 2 · 6 포함
   ```
   기본값은 `Load()` (`96-119`) 의 두 번째 인자와 똑같아야 한다 — 상수로 빼서 둘이 같이 쓰면 어긋나지 않는다.
2. `MenuExtras.cs SettingsUI.Open` (`616-634`) — 「닫기」(0, -364 · 260×76) 오른쪽에 발 버튼:
   ```csharp
   resetButton = UIKit.MakeButton(win, "이 탭 기본값으로", new Vector2(330f, -364f), new Vector2(280f, 64f), ResetTab, 24f);
   RowTip(resetButton.GetComponentInChildren<TMP_Text>(), "이 탭 기본값으로", "이 탭의 설정만 처음 값으로 되돌립니다. 언어 · 화면 모드 · 해상도 · 키 설정은 그대로 둡니다.");
   ```
   창 안쪽 폭 ±578 이라 330±140 = 190~470 안에 든다.
3. 두 번 누르기 (레벨업 「포기」 `LevelShop.EvoUI.cs:268-303` 과 같은 2초 규칙):
   ```csharp
   static float resetArmedAt = -99f;
   static void ResetTab()
   {
       TMP_Text t = resetButton.GetComponentInChildren<TMP_Text>();
       if (Time.unscaledTime - resetArmedAt >= 2f) { resetArmedAt = Time.unscaledTime; t.text = Loc.T("한 번 더 누르면 되돌립니다"); UISound.Click(); return; }
       resetArmedAt = -99f;
       if (tab == 0) GameSettings.ResetGeneral(); else if (tab == 1) GameSettings.ResetDisplay(); else if (tab == 2) KeyBindings.ResetAll(); else GameSettings.ResetGameplay();
       Deselect();
       ShowTab(tab);                                   // 줄을 다시 그려 새 값이 보이게
       t.text = Loc.T("이 탭 기본값으로");
       Notice.Toast(NoticeIcon.Info, Loc.T("되돌렸습니다"), 2f);    // 게임 씬에서만 보임, 메뉴에선 버튼 글자가 돌아오는 것으로 충분
   }
   ```
   `ShowTab` (`636-652`) 첫 줄에서 `resetArmedAt = -99f` 로 무장을 풀고, 조작 탭에서는 기존 `기본값으로`(`950`) 버튼을 **지운다**(발 버튼이 대신함 · 안내 글 `949` 는 그대로).

## 4. 무한 모드 · 일일 도전 「포기하고 결과 보기」

**문제**
- 무한 모드 · 일일 도전에서 그만두려면 ESC → 「메인 메뉴로」밖에 없다 (`ESCmenu.cs:65-68, 110-115`). 이때 `EndlessMode.OnDestroy` (`EndlessMode.cs:354-368`) 가 생존 시간 · 최고 기록 · 순위표 제출은 하지만, 바로 메인 메뉴로 가 버려 **결과 화면(생존 시간 · 보스 처치 · 순위 보기 · 획득 포인트 · 다음 목표, `MenuExtras.cs:21-100`)을 못 본다**. 기록을 남기고 끝내려면 일부러 죽어야 한다.
- 확인 창 안내(`SaveNote`, `84-89`)는 「지금 진행 중인 판이 끝납니다」라서 기록이 남는지도 알 수 없다.
- 덤으로 생기는 버그: 메인 메뉴로 나가면 `EndlessMode.LastSeconds` 가 그대로 남아(`-1` 로 되돌리는 곳은 결과 화면 `MenuExtras.cs:99` 만) 다음에 **이야기 모드에서 죽으면 결과 화면에 지난 무한 모드 기록 줄이 섞여 나온다** (`71` 의 `LastSeconds < 0f` 검사).

**해결**
1. `ESCmenu.cs`
   ```csharp
   static bool GiveUpMode => GameMode.IsEndless || DailyChallenge.Active;
   public void onPressMainMenu()
   {
       if (GiveUpMode) { Confirm("ConfirmGiveUp", "여기서 포기하고 결과를 볼까요?", "지금까지의 생존 시간 · 보스 처치 수가 기록되고 순위표에 올라갑니다.", "포기하고 결과 보기", GiveUp); return; }
       Confirm("ConfirmMainMenu", "정말로 메인 메뉴로 가시겠습니까?", SaveNote(), "메인 메뉴로", GoMainMenu);
   }
   void GiveUp()
   {
       CloseConfirm();
       RunStats.GaveUp = true;
       Time.timeScale = 1f;
       IsOpen = false;
       SceneManager.LoadScene("GameOver");          // EndlessMode.OnDestroy 가 기록 · 제출, 결과 화면이 그대로 보여 줌
   }
   ```
   `Start()` 에서 `GiveUpMode` 면 씬의 메인 메뉴 버튼 글자를 바꾼다: `escMenu` 아래 `Button` 들을 돌며 `GetComponentInChildren<TMP_Text>()` 의 `text == Loc.T("메인 메뉴로")` 인 것을 찾아 `UIKit.Remember(t, "포기하고 결과 보기"); t.text = Loc.T("포기하고 결과 보기");` (씬 이름을 모르니 글자로 찾음 · `SceneLocalizer` 가 되돌리지 않게 `Remember` 로 덮음).
2. `RunStats.cs` — `public static bool GaveUp;` 추가, `Boot` 의 GameScene 로드 때 `false` (`48-71` 초기화 묶음), 밸런스 기록 `47` 줄 결과를 `cleared ? "clear" : GaveUp ? "quit" : s.name == "GameOver" ? "death" : "quit"`. `BuildDamagePanel` 의 「쓰러진 곳」 줄 (`271`) 조건에 `&& !GaveUp`.
   같은 `Boot` 에 `if (s.name == "MainMenu") EndlessMode.LastSeconds = -1f;` 를 넣어 위 「섞여 나오는 기록」 버그도 막는다.
3. `MenuExtras.cs InstallGameOver` (`25-36`) — `RunStats.Cleared` 분기 옆에 `else if (RunStats.GaveUp)`: 제목을 `Loc.T("여기까지!")` 금빛으로, 해골 숨김(클리어와 같은 처리). 나머지(기록 · 순위 보기 · 다시 하기 버튼)는 그대로 쓰면 된다 — `ResultScreen.BuildRetry` 의 「같은 설정으로 다시」도 무한 모드에 그대로 맞는다.
4. 이야기 모드는 바뀌지 않는다(저장 → 메인 메뉴).

**예외**
- 보스(개발자 · 엄마 포함) 중: 포기 가능, 처치 수는 쓰러뜨린 것까지만. 레벨업 · 보상 창이 열린 채 ESC 로 들어온 경우: 씬이 바뀌며 `ChoiceUI.Open` 은 `Boot` 가 `false` 로 되돌림(`ChoiceUI.cs:41-45`), 레벨업 창은 씬과 함께 사라짐. 한계 돌파(클리어 뒤) 구간: 그대로 포기 가능. 일일 도전: `DailyChallenge.Submit` 은 `OnDestroy` 에서 그대로 → 결과 화면의 「오늘 내 최고 기록」 · 순위 줄이 뜬다.
- 이어하기 · 튜토리얼: 무한 모드는 저장하지 않고 튜토리얼은 이야기 모드라 해당 없음. 체험판: 무한 모드가 잠겨 있어 닿지 않음(코드는 무해).
- 게임패드: 확인 창은 가상 커서 · B 로 취소(기존 `confirm != null → CloseConfirm`, `ESCmenu.cs:35`).
- 결과 화면이 뜨고 1초 보호(`QuickRestart` · `BuildRetry readyAt`)는 그대로 — 포기 직후 R 연타로 새 판이 시작되지 않음.

## 5. 「레벨업!」 대기 배지 · 「다시 뽑기」 배지를 클릭할 수 있게

**문제**
- 화면 아래 「레벨업! [Space] 카드 고르기 ×n」 배지는 `Image.raycastTarget = false` (`LevelShop.cs:225`) · 글자도 `false` (`241`) 라 **클릭해도 아무 일이 없고** 오직 상호작용 키(`131-137`)로만 열린다. 마우스 중심 플레이어는 손을 키보드로 옮겨야 하고, 배지가 버튼처럼 보여 눌러 보고 「고장인가」 한다.
- 레벨업 창의 「[R] 카드 다시 뽑기 (n)」 배지(`171-172`, `HintBadge.Make` → `RecommendGlow.cs:202-232`, rim · fill 모두 `raycastTarget = false`)도 키 전용(`158`). 마우스로 카드를 고르는 창에서 다시 뽑기만 키라 끊긴다.

**해결**
1. `LevelShop.cs UpdatePendingBadge` (`211-242`) — 배지를 만들 때:
   ```csharp
   bg.raycastTarget = true;
   Button b = pendingBadge.AddComponent<Button>();
   ColorBlock cb = b.colors; cb.highlightedColor = new Color(1f, 0.95f, 0.8f); cb.pressedColor = new Color(0.85f, 0.75f, 0.55f); b.colors = cb;
   b.onClick.AddListener(TryOpenPending);
   TooltipTrigger tip = pendingBadge.AddComponent<TooltipTrigger>();
   tip.hud = true;                                   // PlayerController.PointerOverUI(642-660)가 이 칸 위 조준을 막지 않게 (HUD 칸과 같은 규칙)
   tip.titleProvider = () => Loc.T("레벨업 카드");
   tip.bodyProvider = () => Loc.T("눌러서 카드를 고릅니다. 모아 두고 나중에 골라도 됩니다.");
   ```
   `Update` (`131-137`) 의 열기 조건을 함수로 빼서 둘이 같이 쓴다:
   ```csharp
   bool CanOpenPending => PendingLevels > 0 && !IsOpen && Time.timeScale == 1f && !ShopOpen && !ESCmenu.IsOpen && !StoryDirector.Playing;
   void TryOpenPending() { if (!CanOpenPending) return; PendingLevels--; chainIndex++; openLevelShop(); }
   ```
   클릭 순간 평타 한 발이 같이 나가는 것은 그대로 둔다(창이 열리며 멈추므로 무해).
2. `RecommendGlow.cs HintBadge.Make` — 매개변수 `bool clickable = false` 를 더해 `true` 면 `hb.rim.raycastTarget = true` 로 두고 `Button` 을 붙여 돌려준다(반환형은 그대로 `TMP_Text`, 버튼은 `t.transform.parent.GetComponent<Button>()` 로 꺼냄).
   `LevelShop.cs UpdateReroll` (`152-182`) — 다시 뽑기 동작을 함수로 빼고, 키와 버튼이 같이 부른다:
   ```csharp
   void TryReroll()
   {
       SpecialAbilities sp = SpecialAbilities.SharedInstance;
       if (sp == null || !IsOpen || !selectReady || sp.Rerolls <= 0 || !ShowRerollIntro || !sp.TryReroll()) return;
       UpdateLvShopContent(true); pendingSlot = -1; RefreshCards(); PlayRerollFx();
   }
   // 158 줄: if (open && selectReady && KeyBindings.Down(GameAction.Reroll)) TryReroll();
   // 171 줄: rerollText = HintBadge.Make(..., clickable: true); rerollText.transform.parent.GetComponent<Button>().onClick.AddListener(TryReroll);
   ```

**예외**
- 0.6초 잠금(`selectReady`) 중 클릭: 무시(키와 같음). 다시 뽑기가 0 이면 배지가 숨겨져 있음(`175`). 상점 가판대 옆(`ShopStall.PlayerNear`): 키는 상점이 먼저지만 배지 클릭은 카드 창을 연다 — 의도한 차이(플레이어가 배지를 골라 눌렀으므로).
- 보스 등장 연출 중: 배지가 숨겨짐(`205`). 일시정지 중: 숨겨짐. 레벨업 창이 열린 중: `!IsOpen` 으로 무시.
- 튜토리얼: 레벨업 단계가 `PendingBadge` 를 짚어 줌(`198`) — 클릭으로 열어도 같은 `openLevelShop` 을 타므로 단계가 정상 완료됨. 안내문은 「[Space]」를 가리키는데, 「배지를 눌러도 됩니다」는 넣지 않는다(튜토리얼 문구는 그대로).
- 이어하기: 복원된 `PendingLevels` 로 배지가 뜨고 바로 클릭 가능.
- 게임패드: 전투 중엔 가상 커서가 없으니(`GamePad.Combat`) A(상호작용) 그대로. 레벨업 창(멈춤)에서는 가상 커서로 다시 뽑기 배지를 누를 수도, X 를 눌러도 됨 — `GamePad.PadClickNow` 와 충돌 없음(배지는 카드가 아님).
- 키 바꾸기: 배지 글자는 이미 `KeyBindings.Name` 으로 바뀐 키를 보여 줌(`257`, `180`). 체험판: 포함.

## 6. 설정 「카드 한 번 클릭으로 확정」

**문제**

   - 숫자 키 (`115-125`): `if (OneClick) ConfirmSlot(quick); else if (quick == pendingSlot) …`

- 키 바꾸기: 설명의 `{INTERACT}` 가 바뀐 키 · 패드 A 로 바뀜. 체험판: 포함.

## 7. 떠돌이 상점 제단 화면 밖 방향 표시

**문제**
- 제단은 플레이어에서 5~8칸 떨어진 곳에 생기고(`Shop.cs:106-113`) 큰 알림 「떠돌이 상점이 나타났다! 15초 안에 다가가」(`116`)만 뜬다. 무리를 끌고 달리는 중이면 몇 초 안에 화면 밖(가로 반폭 약 26칸)으로 벗어나는데, `ShopStall.cs` (`38-143`) 에는 남은 시간 고리 · 머리 위 「상점 n」 글자만 있고 **화면 가장자리 방향 표시가 없다**. 어디 있는지 몰라 놓치면 다음 상점이 절반만 빨리 올 뿐(`Shop.cs:120`).
- 보물 상자는 이미 가장자리 표시가 있다 (`TreasureChest.cs:57-60` 만들기, `113-129` 위치 계산). 같은 코드를 쓰면 된다.

**해결**
1. `TreasureChest.UpdatePointer` (`113-129`) 의 계산을 공용으로 뺀다 — `Hostile` 또는 새 정적 클래스 `EdgePointer`:
   ```csharp
   // 카메라 안이면 false. 밖이면 화면 가장자리 안쪽(위 16% · 아래 14% · 옆 5%, 최소 1.2칸) 위치를 돌려줌
   public static bool EdgePoint(Vector3 target, out Vector3 at)
   ```
   `TreasureChest` 도 이 함수를 쓰게 바꾼다(동작 동일).
2. `ShopStall.cs`
   - 필드 `GameObject pointer; TextMeshPro pointerText;`
   - `Start` (`38-71`) 끝에: `pointer = SpecialAbilities.MakeSprite("StallPointer", StallSprite, transform.position, 0.8f, Color.white, "Effect", 40);` + 뒤 빛 `MakeSprite("StallPointerGlow", Hostile.Glow, …, 0.3f, new Color(1f, 0.85f, 0.4f, 0.75f), "Effect", 39)` 를 자식으로, 자식 `TextMeshPro`(label 과 같은 폰트 · 크기 5 · 가운데 · 위치 (0, -1.1)) 를 `pointerText` 로, `pointer.SetActive(false)`.
   - `Update` (`94-143`) 의 `label.text = …` 다음에:
     ```csharp
     bool outside = EdgePointer.EdgePoint(transform.position, out Vector3 at);
     pointer.SetActive(outside);
     if (outside)
     {
         pointer.transform.position = at;
         pointer.transform.localScale = Vector3.one * (0.8f + 0.1f * Mathf.Sin(Time.time * 8f));
         pointerText.text = Mathf.CeilToInt(left).ToString();
         pointer.GetComponent<SpriteRenderer>().color = left < 3f && Mathf.PingPong(Time.time * 6f, 1f) < 0.5f ? new Color(1f, 1f, 1f, 0.4f) : Color.white;   // 몸통과 같은 깜빡임(108)
     }
     ```
   - `OnDestroy` (`145-149`) 에 `if (pointer != null) Destroy(pointer);`
3. 큰 알림 문구는 그대로(새 그림 없음, 기존 제단 스프라이트 재사용).

**예외**
- 시간이 멈춘 동안(레벨업 · 상점 · 일시정지): `Update` 는 돌지만 `left` 가 줄지 않아 표시가 그 자리에 머무름(상자와 같음). 제단이 여러 개면 각자 표시(드묾).
- 보스 중: 제단이 생기면 같게 동작. 무한 모드 개발자 뒤로는 제단이 안 생김(`Shop.cs:99`). 이어하기: 제단은 저장하지 않으므로 해당 없음. 튜토리얼: 상점 단계가 없고 제단이 생기면 같게 동작.
- 게임패드 · 키 바꾸기: 무관. 체험판: 포함(1장에도 제단이 나옴).

**문구**: 새 문구 없음.
