# 공간 침식 · 통합 결계 게이지 · 개발자 / 엄마 결계 — 기획서 (2026-10-18)

- 읽은 코드: 배포판 작업 트리 `SoulSaver-hotfix` (브랜치 `hotfix-1.1.9`, 커밋 `0db5f91`). 줄 번호는 모두 이 커밋 기준이다. main 병합이 끝나면 줄 번호는 밀릴 수 있으니 **함수 이름으로 찾는다**.
- 코드는 고치지 않았다. 이 문서는 구현 지시서다.
- 사용자 요청 세 가지
  1. 보스가 여럿이면 필살기 게이지를 하나로 합친다. 가득 차면 각자의 결계 대신 거대한 결계 하나 「공간 침식」을 펼친다. 이 결계 안에는 필드의 모든 보스가 가진 결계 공격이 더 짧은 간격으로 쏟아진다.
  2. 어느 보스를 때려도 통합 게이지가 찬다. 보스가 하나만 남으면 남은 게이지를 그 보스가 그대로 받는다. 보스가 다시 둘 이상이 되면, 남아 있던 보스의 개별 게이지 값에서 통합 게이지를 시작한다.
  3. 개발자와 개발자 엄마에게도 결계를 준다. 내부 공격은 각자의 컨셉에 맞게 정한다.

## A. 지금 구조 (코드 그대로)

### A1. 필살기 게이지 — `BossUltimate.cs`

- 저장 위치: `static float[] gauge = new float[4]`, `refHp[4]`, `lastHit[4]`, `usedThisFight[4]`. **보스 종류(0 리치 왕 · 1 지옥의 군주 · 2 킹 슬라임 · 3 거울의 군주)마다 칸 하나**다(19~23행).
- 칸 초기화: `Start()`(47~61행)에서 새 보스가 나오면 그 종류의 게이지를 0으로 하고, `refHp` = 최대 체력(이어하기면 `restoreMaxHp`)으로 정한다. 이어하기로 되살린 보스가 이미 체력 40% 아래였으면 `usedThisFight = true`로 둔다. **게이지 자체는 저장하지 않는다.**
- 차는 방식: `OnBossHit(bosss b, float damage)`(70~79행). `bosss.TakeDamage`의 245행 `if (EnemyHealth > 0) BossUltimate.OnBossHit(this, damage);`에서 부른다(풍화 · 치명타 · 고유 스킬 배율이 모두 들어간 최종 피해).
  - `f = damage / refHp`
  - `gain = max(7·f^1.2, 3.5·f) × SoulWeight.BarrierGaugeMul` (영혼의 무게 3 이상은 1.35배. 이야기 모드 어려움 전용)
  - 한 대에 최대 +0.5, 게이지 최대 1
  - `Active`(결계 중) · 죽은 보스 · **`b.developer`면 바로 return** → 개발자 · 엄마는 게이지가 아예 차지 않는다.
- 줄어듦: `Update()`(83~94행). 3초 동안 맞지 않으면 초당 0.004씩 준다. `decayFrame`으로 한 프레임에 한 번만 깎는다(이 가드는 칸 구분 없이 **전역 하나**라서, 보스가 둘이면 먼저 Update를 돈 보스의 칸만 깎이고 다른 칸은 그 프레임에 깎이지 않는다. 지금도 있는 작은 버그다).
- 40% 규칙: 이번 보스전에 아직 결계를 펼치지 않았는데 체력이 40% 아래로 내려가면 게이지가 곧바로 1이 된다.
- 발동 조건(95~102행): 게이지 1 · 등장 4초 뒤 · `restUntil`(지난 결계 끝 + 15초, **전역 하나**) 지남 · `timeScale > 0` · 이야기 연출 아님 · `boss.casting` 아님 · 진화 · 선택 · ESC 창이 닫혀 있음 · 킹 슬라임은 가장 체력이 많은 개체(`IsStrongestSlime`, **부를 때마다 `new List<bosss>()`를 만든다**) · 플레이어가 살아 있음.

### A2. 결계 진행 — `Run()`(123~163행)

1. `Active = true`, 그 칸 게이지 0, `usedThisFight = true`, 펼치는 보스 `casting = true`, 플레이어 스킬 취소.

ESC가 열리면 연출 시계가 멈춘다(`CutDt`). 설정의 번쩍임 · 화면 흔들림을 따른다.
3. 중심 = `ClampArena(보스 위치)`. 플레이어 2초 무적. `HideWalls(true)`(태그 Wall 콜라이더 · 그림을 끔).
4. `Expand()`(291~338행, 0.8초): `domainRoot` 아래로 어둠 메시(구멍 반지름 34.8 · 테두리 36.8 · 바깥 400, **1.2.4부터 메시 · 머티리얼 하나를 같이 씀**), 고리 LineRenderer 둘, 룬, 보스 후광, 플레이어 발밑 빛 · 고리를 만든다. 반지름을 0.5에서 35로 키우면서 밖에 있는 플레이어를 안으로 끌어온다.

6. `Shatter()`(0.6초): 불꽃 36개 · 충격파 · 어둠이 사라짐. `EndNow()`: 리치 빔 정리 · 벽 되살림(벽 속이면 가까운 빈자리로 옮기고 1초 무적) · `restUntil = now + 15` · `domainRoot`와 후광 삭제 · `casting = false` · `Active = false`.
7. 업적: 결계 중 보스 처치(`BarrierBreak`) · 끝까지 버팀(`BarrierSurvive`) · 한 대도 안 맞음(`BarrierNoHit`, `PlayerController.HurtCount` 비교).

### A6. 보스바 — `bossbar.cs`

- 맨 위 줄은 `bosss.Primary`(Live 목록의 첫 생존 보스)가 매 프레임 `bossKind · MaxHealth · NowHealth · erosion`을 넣는다(`boss.cs` 180~189행).
- `LiveCount >= 2`면 보스마다 줄을 하나씩 만든다(164~174행). 아래 줄은 `Instantiate(backBar)`로 복제한다. 복제본 아래에는 MonoBehaviour가 없어야 하고(233행 주석, 1.2.0 렉 원인과 같은 길), 복제본에서는 `UltGauge`를 지운다(238행).
- 필살기 게이지(`UpdateUltGauge` 284~319행): 맨 위 줄 아래 596×10 막대, 오른쪽 끝에 「결계」 글자, 85% 넘으면 깜빡임. 값은 `BossUltimate.Gauge(bossKind)`. **개발자 · 엄마(`bossKind ≥ 9`)는 게이지째 숨긴다.**
- **지금 문제**: 보스가 둘이면 맨 위 줄 보스의 게이지만 보인다. 둘째 보스의 게이지는 화면에 없는데, 그 보스가 결계를 펼칠 수 있다(예고 없는 결계). 통합 게이지가 이 문제를 함께 해결한다.

| 적 탄 `Hostile.Shoot` → `HostileProjectile` | **풀** (1.2.4) · `HostileProjectile.Live` 목록 | 그대로 쓰고 상한은 `Live.Count`로 본다 |
| 어둠 메시 | 정적 메시 · 머티리얼 하나 (1.2.4) | **크기만 `localScale`로** 바꿔 같이 쓴다 |
| 리치 빔 | 처음 한 번 만들고 옮겨 씀 (1.2.4, `lichBeams[4]`) | 빔 배열을 결계 맥락(ctx)마다 하나씩 둔다 |
| 산성 덩어리 | 매번 `MakeSprite` + `Dress` + `AddComponent<DomainBall>` (최대 3) | 상한을 두고 그대로 쓴다(새 오브젝트이지 복제가 아님) |

### A8. 이번 작업과 엮이는 기존 문제 (같이 고친다)

1. **게이지 칸이 종류 번호 기준**이고 개발자 · 엄마도 `bossKind = 3`이다. 그대로 게이지를 열면 거울의 군주 칸을 같이 쓰게 되고, 업적 「거울의 군주를 결계 전에」(`SteamManager` 150행 `UsedThisFight(MirrorKind)`)까지 오염된다. → **칸(slot) 6개**로 나눈다: 0~3 일반, 4 개발자, 5 엄마.
2. `decayFrame`이 전역 하나라 보스가 둘이면 한 칸만 줄어든다(A1). 통합 모드에서는 칸이 하나라 문제가 없고, 개별 모드에서는 보스가 하나뿐이라 역시 문제가 없다. 다만 칸별 `decayFrame[slot]`으로 바꿔 두면 확실하다.
3. 보스바에 둘째 보스 게이지가 안 보인다(A6).
4. `IsStrongestSlime()`가 부를 때마다 `List`를 할당한다. 정적 리스트 하나로 바꾼다.
5. `AttackLabel.FromCaller`(32행)가 `f == "BossUltimate"`로 **파일 이름이 정확히 같을 때만** 「보스 결계」로 적는다. 새 partial 파일(`BossUltimate.Developer.cs` 등)이나 `SpaceErosion.cs`에서 쏜 탄은 이름이 「적 탄환」으로 나온다. → `StartsWith("BossUltimate")` + `"SpaceErosion"` 처리를 추가한다. `FromStack`(57행)도 `typeof(SpaceErosion)`을 추가한다.
6. `EndlessMode.Update` 172행의 `SpawnBoss` 조건에 `BossUltimate.Active`가 없어서, 결계 중에도 다음 보스가 나올 수 있다(나오자마자 밀려나고 인트로가 결계 화면 위에 뜰 수 있다). 공간 침식에서는 반드시 막는다.

## B. 통합 게이지

### B1. 용어

- **칸(slot)**: `SlotOf(b) = b.developer ? (b.developerMom ? 5 : 4) : Clamp(b.bossKind, 0, 3)`
- **참가 보스**: `bosss.Live` 가운데 `!IsDead`인 보스(쓰러지는 연출 1초 중인 보스는 제외). 개발자 · 엄마도 포함한다.
- **통합 모드**: 참가 보스가 2 이상. 정적 `shared`, `sharedGauge`, `sharedLastHit`, `sharedCount`.

### B2. 들어가고 나오는 규칙

`BossUltimate.SharedTick()` — 아무 `BossUltimate.Update`에서나 부르고, `sharedFrame == Time.frameCount`면 건너뛴다(한 프레임 한 번). 결계 · 공간 침식 중(`Active`)과 침식 대기 중(`Pending`)에는 **전환하지 않고 숫자만 센다**.

| 상황 | 처리 |
|---|---|
| 개별 모드이고 n = 1 | `soloSlot` = 그 보스의 칸을 기억해 둔다 |
| 개별 → 통합 (n ≥ 2가 됨) | `sharedGauge = soloSlot ≥ 0 ? gauge[soloSlot] : 0`. 새로 나온 보스의 칸은 `Start`에서 0이 되지만, 그 `Start`가 아직 안 돌았을 수 있어서 **max로 고르지 않고 `soloSlot` 값만 쓴다**(지난 판의 남은 값이 섞이지 않게). 둘이 한꺼번에 나오면(최후의 시간 4마리) `soloSlot = -1` → 0. `sharedLastHit = now`. 알림 토스트 「결계 게이지가 하나로 합쳐졌다!」(10초에 한 번까지) · 처음이면 도움말 `bossult.shared` |
| 통합 중 n이 바뀜 (3 → 2 등) | 값은 그대로 두고 `sharedCount`만 바꾼다 |
| 통합 → 개별 (n = 1이 됨) | 남은 보스 칸에 `gauge[slot] = sharedGauge`, `lastHit[slot] = now`. 둘 가운데 하나가 쓰러지는 그 프레임에 바로 일어난다(`IsDead`는 `Die`에서 곧바로 켜짐) |
| 통합 → 0 (n = 0) | `shared = false`, `sharedGauge = 0`, `soloSlot = -1` |
| 공간 침식이 끝남 | `sharedGauge = 0`, 참가했던 모든 칸 `gauge = 0`, `usedThisFight = true`. 그 뒤 n = 1이면 남은 보스는 0을 받는다 |
| 장면 시작 | `BossUltimate.ResetStatics()`를 `bossbar.Start`(지금 `HealthBarFeel.ResetStatics()`를 부르는 자리, 48행)에서 부른다. `shared · sharedGauge · soloSlot · pending · restUntil`을 비운다. `cutSeen`은 「이번 실행에서 본 적 있음」이라 비우지 않는다 |

### B3. 채우기

```
OnBossHit(b, damage):
  if (b == null || Active || b.IsDead || damage <= 0) return;         // 개발자 제외 조건은 지운다 (D0)
  slot = SlotOf(b);
  f = damage / max(1, refHp[slot] > 0 ? refHp[slot] : b.setEnemyHP);  // 맞은 보스 자기 최대 체력 기준
  gain = min(0.5, max(7·f^1.2, 3.5·f) × SoulWeight.BarrierGaugeMul × SlotMul(slot));
  if (shared)
      g = gain × (sharedCount >= 3 ? 0.55 : 0.7);
      if (gainFrame != frameCount) { gainFrame = frameCount; gainThisFrame = 0; }
      g = min(g, 0.25 - gainThisFrame);  gainThisFrame += g;           // 한 프레임 상한 (범위 공격 하나가 넷을 동시에 맞혀도 +0.25)
      sharedGauge = min(1, sharedGauge + max(0, g));  sharedLastHit = now;
      if (!usedThisFight[slot] && b.EnemyHealth < b.setEnemyHP × 0.4) sharedGauge = 1;   // B4
  else
      지금과 같음 (gauge[slot], lastHit[slot])
```

- `SlotMul`: 일반 1.0, 개발자 1.0, 엄마 1.0(D0에서 정한 이유: 게이지는 체력 비율로 차서 체력이 큰 보스라고 늦게 차지 않는다).
- 0.7 / 0.55의 근거: 보스를 하나만 노려도 단일 보스일 때와 같은 속도로 차고, 다른 보스까지 맞히면 그만큼 더 찬다. 즉 통합 게이지는 원래 개별 게이지보다 빨리 찬다. 공간 침식이 더 세니 같은 시간당 횟수가 조금 줄도록 낮췄다. 보스가 둘이고 범위 공격으로 둘을 같이 맞히면 개별 기준의 약 1.4배, 하나만 노리면 0.7배다.

### B4. 40% 규칙 · 줄어듦 · 쉬는 시간

- **40% 규칙(통합)**: 참가 보스 가운데 `usedThisFight[slot] == false`인 보스가 맞아서 40% 아래가 되면 통합 게이지가 곧바로 가득 찬다. 공간 침식이 끝나면 참가 보스 모두 `usedThisFight = true`가 된다 → 「보스전마다 적어도 한 번」이 그대로 지켜지고, 최후의 시간 4마리가 차례로 40%를 밟아도 첫 침식 한 번으로 정리된다. 이어하기로 되살린 40% 미만 보스는 이미 `true`(A1)라서 이어하자마자 침식이 펼쳐지지 않는다.
- **줄어듦**: 어느 보스든 3초 동안 맞지 않으면 초당 0.004씩. 개별 모드는 칸별 `decayFrame[slot]`.
- **쉬는 시간**: 개별 결계 뒤 15초(지금과 같음), 공간 침식 뒤 **20초**. 둘 다 정적 `restUntil` 하나를 쓴다.

### B5. 발동과 대기 (Pending)

통합 게이지가 1이 되면 바로 펼치지 않고 **대기**에 들어간다.

- 대기 중 `BossUltimate.HoldSkills = true` → `BossSkills.Update` 55행에서 새 스킬을 시작하지 않는다(개발자의 `DeveloperTurn`도 막힌다). 이미 돌던 스킬은 끝까지 간다.
- 시작 조건(모두 만족): 지금 발동 조건(A1)의 전역 항목(`timeScale` · 창 · 이야기 연출 · 플레이어 생존 · `restUntil`) + 모든 참가 보스가 등장한 지 4초 이상 + **아무도 `invulnerable`이 아님**(리치 왕 「망자의 의식」 중이면 기다림, 의식 도중 무적이 남지 않도록 코루틴을 끊지 않는다) + **아무도 `airborne`이 아님**(킹 슬라임 대점프) + (일반 보스는 `casting`이 꺼짐 **또는** 대기 3초가 지남) + (개발자 · 엄마는 `DevRunning == 0` **또는** 대기 3초가 지남).
- 대기 중에 보스가 쓰러져 n = 1이 되면 대기를 풀고 B2 규칙대로 남은 보스에게 1.0을 넘긴다 → 그 보스가 곧 자기 결계를 펼친다(남은 게이지를 그대로 받는다는 요청과 같은 동작).
- 개별 결계도 같은 대기를 쓴다(개발자 · 엄마 결계가 겹쳐 쓰는 영웅 필살기 위에 바로 덮이지 않게, D0). 일반 보스의 개별 결계는 지금처럼 `casting`이 꺼질 때까지만 기다린다(3초 상한 없음 → 지금 동작 유지).

### C3. 결계 공격 합치기

- 모든 참가 보스의 결계 공격(A3 · D)을 **동시에** 돌린다. 각 공격은 그 보스가 살아 있는 동안만 돈다(공격 루프 조건에 `src != null && !src.IsDead`).
- **간격 배율 `tempo`**: 참가 보스 수 n에 따라 2 → 0.6, 3 → 0.7, 4 이상 → 0.8. 1초마다 살아 있는 참가 보스 수로 다시 계산한다(하나만 남으면 0.85). 개발자 · 엄마 패턴에는 `max(tempo, 0.75)`.
- **바꾸는 것**: 「다음 공격까지의 간격」만 × tempo. **바꾸지 않는 것**: 예고 시간 · 판정 크기 · 탄 속도.
- 패턴별 세부(밀도 조정 포함):

| 공격 | 지금 | 공간 침식 (n = 2 기준, 괄호는 n ≥ 3) |
|---|---|---|

### C4. 공정성 장치 (모두 공간 침식에만 · 기존 개별 결계 수치는 그대로)

1. **예고 시간 유지**: 어떤 타격도 원래 예고보다 짧아지지 않는다. 침식 안 모든 땅 타격의 예고는 최소 **0.8초**(개발자 · 엄마 패턴의 0.75 · 0.85 등은 0.8로 올린다).
2. **고요의 눈** (안전 지대): 반지름 3.5인 옅은 흰 원(Glow 스프라이트 α 0.22 + 흰 점선 고리). 본 진행 1.5초에 플레이어로부터 7 ~ 11 떨어진 결계 안 자리에 생기고, 5초마다 새 자리(플레이어로부터 7 ~ 11)로 옮긴다. 옮기기 1초 전에 새 자리에 점선 고리를 미리 보이고, 0.6초 동안 미끄러져 간다. **땅을 치는 공격**(Spike · 브레이크포인트 · 등짝 스매싱 등 원형 타격)의 원이 눈과 겹치면 `at = eye + 방향 × (3.5 + r + 0.3)`으로 밀어낸다. 탄 · 회전 광선 · 거울 광선 · 튕기는 것은 막지 않는다(눈에 서 있어도 할 일은 남는다).
3. **노림 토큰**: 플레이어를 직접 노리는 타격(위 표의 「나를 노림」)은 침식 전체에서 **0.35초에 하나**만 플레이어 자리에 떨어진다. 그 사이 요청은 플레이어로부터 4 ~ 9 떨어진 무작위 자리로 바꾼다(밀도는 그대로, 한 자리에 겹쳐 떨어지지 않음).
4. **동시 수 상한**: 대기 중인 땅 타격 **96**(대기열 128칸. 넘으면 무작위 자리 타격부터 버리고, 나를 노린 타격은 버리지 않음) · 침식이 새로 쏘는 탄은 `HostileProjectile.Live.Count < 220`일 때만 · 튕기는 것 최대 4 · 리치 빔 최대 4 · 거울 광선 쌍 동시 최대 2.
5. **피해**: 침식 안 모든 피해 × **0.85**, 한 대 상한 = 최대 체력의 **25%**(`min(raw, PlayerMaxHealth × 0.25 / (DamageMul × HurtMul))`, 거울 군주 `Capped`와 같은 계산). 개발자 · 엄마 공격도 × 0.85를 곱하고, 한 대 상한은 그들 상한(D0: 16% · 32%)과 25% 가운데 낮은 쪽 하나만 쓴다(두 상한을 겹쳐 곱하지 않음). 그 뒤 `TryHit`의 보스전 상한 40%는 그대로 남는다.
6. **피격 무적 +0.25초**: `PlayerController.TryHit` 1296행 `invincibleUntil = Time.time + hurtInvincibleTime + BossUltimate.HurtGraceBonus;`. `HurtGraceBonus`는 평소 0, 침식 중 0.25, 개발자 · 엄마 결계 중 0.2. 탄 · 몸통 · 결계 모두에 고르게 걸리고 상태가 남지 않는다(정적 속성이 `Active`를 보고 값을 돌려줌).
7. **몸통**: 참가 보스는 제자리에 서지만 몸통 피해는 그대로다. 펼침 때 보스를 플레이어로부터 최소 6 떨어지게 놓는다(끌어오는 자리 고를 때).

### C6. 개발자 · 엄마가 함께 있을 때

- 지금 규칙에서는 생기지 않는다(A5). 이어하기 복원이나 앞으로의 이벤트로 생기면 아래를 따른다.
- 개발자 · 엄마도 참가 보스다. 그들의 결계 패턴(D)도 섞인다. 간격은 `max(tempo, 0.75)`.
- 개발자 「강제 종료」 · 엄마 「통금 시간」(결계 반지름이 줄어듦)은 침식에서는 쓰지 않는다. 결계 크기를 바꾸면 다른 보스 패턴의 기준이 흔들리고, 거대 X자는 다른 공격과 겹치면 피할 자리가 없다. 대신 그 시간에 「잔소리 폭격」 · 「무한 루프」를 한 번 더 쓴다.
- 침식 컷신 이름 줄에 「개발자」 · 「개발자 엄마」를 넣고, 대사 밑에 작은 글씨로 「…엄마, 지금 결계 쓰는 중이라니까요.」를 넣는다(개발자와 엄마가 둘 다 있을 때만. 4개 언어는 G4).
- 피해: C4-5대로 × 0.85를 곱하고, 한 대 상한은 개발자 16% · 엄마 25%(32%와 25% 가운데 낮은 쪽)다.

### C7. 구조 (코드 모양)

- **`DomainCtx`** (새 클래스, `BossUltimate.Domain.cs`): 결계 하나의 맥락. `center, radius, root, until, tempo, erosion(bool), color, src(bosss)`, `lichBeams[4]`, `bouncers`(공유 목록 참조), `eye` 정보, 대기열 참조. 결계를 시작할 때 **미리 만든 것을 `Reset()`해서 다시 쓴다**(개별용은 `BossUltimate`마다 하나, 침식용은 `SpaceErosion`이 보스 수만큼 최대 6개를 처음에 만들어 둠).
- **결계 공격을 ctx 기반으로**: `LichBarrage(DomainCtx d)` 등 지금 인스턴스 메서드에서 `boss → d.src`, `center → d.center`, `Radius → d.radius`, `domainRoot → d.root`, `running → d.Live`, `StartCoroutine(Spike(…)) → d.Strike(…)`, 간격 상수 `x → x * d.tempo`로 바꾼다. 개별 결계는 `tempo = 1`, `erosion = false`라 **결과가 지금과 같다**(검증: H1).
- 공격 코루틴은 `d.runner.StartCoroutine(...)`으로 돌린다. 개별은 `runner = 그 BossUltimate`, 침식은 `runner = SpaceErosion`. 그래서 침식 공격은 보스 오브젝트가 지워져도 끊기지 않고, 루프 조건(`src` 생존)으로 스스로 멈춘다. 공격 메서드는 `this`의 `transform` · `gameObject`를 만지지 않는다(정적 메서드로 만들면 실수가 안 생긴다 → **`static IEnumerator`로 만든다**).
- **땅 타격 대기열 `DomainStrikes`** (정적, 구조체 배열 128칸 링 버퍼): `Strike(at, r, warn, color, dmg, fx, aimed, ctx)` → 결계 안으로 당기기 · 눈 밀어내기 · 노림 토큰 · 상한 검사 → `Hostile.Circle` 두 겹 + 느낌표(풀) → `{at, r, fireAt, dmg, color, fxId}` 저장. `SpaceErosion.Update`(침식)와 `BossUltimate.Update`(개별)가 `DomainStrikes.Tick()`을 부르고(프레임 가드), `Time.time >= fireAt`이면 이펙트 둘 + 피해. 코루틴 · `WaitForSeconds`를 타격마다 만들지 않는다. 결계가 끝나도 남은 타격은 끝까지 처리한다(지금 동작과 같음). 장면 전환 때 비운다.
- **`SpaceErosion`** (새 `MonoBehaviour`, `SpaceErosion.cs`): 처음 필요할 때 `new GameObject("SpaceErosion")` + `AddComponent` 한 번(복제 · `Instantiate` 아님). 장면에 하나. 하는 일: 대기(B5) · 컷신 · 펼침 · 본 진행(Confine · RepelMobs · Animate · 눈) · 파열 · 정리. `BossUltimate`의 정적 도우미(`Cutscene` · `DarkMesh` · `SetDark` · `HideWalls` · `PlaySfx` · `Warn` · `EdgeInArena`)를 `internal static`으로 열어 같이 쓴다.
- `BossUltimate`는 `partial`로 바꾼다: `BossUltimate.cs`(게이지 · 개별 진행), `BossUltimate.Domain.cs`(ctx · 대기열 · 지금 네 결계 공격), `BossUltimate.Developer.cs`(개발자 · 엄마 결계와 장식).

## F. 성능 (지난 렉 원인과 같은 일이 생기지 않게)

1. **매 프레임 할당 0**
   - 참가 보스 목록은 정적 `List<bosss> participants`(용량 8) 하나를 `Clear()`해서 다시 쓴다. LINQ · 람다 캡처를 쓰지 않는다(`bosss.LiveCount`의 `RemoveAll` 람다는 캡처가 없어 할당이 없고 그대로 써도 된다).
   - 색 섞기 · 남은 시간 · 눈 위치는 계산만 한다. 보스바 글자는 `n` · 언어가 바뀔 때만 만든다.
   - `IsStrongestSlime`의 `new List` → 정적 리스트(A8-4).
   - 땅 타격은 구조체 대기열(C7)이다. 타격마다 코루틴 · `WaitForSeconds`를 만들지 않는다. 결계 공격 루프 안의 `WaitForSeconds`는 박자 단위(초당 1 ~ 2개)라 그대로 두되, 자주 쓰는 값(0.16 · 0.12 · 0.14 등)은 `static readonly WaitForSeconds`로 둔다(tempo가 곱해지는 값은 시간 비교 루프 `while (Time.time < t) yield return null;`로 바꾼다).
2. **경고 느낌표 풀**: `Warn()`의 `Fx.Play` + `AddComponent<WarnPop>` → `Fx.Spawn` + `FxAnim.pop` 표시로 바꾼다. `FxAnim`에 `public bool pop; Vector3 popBase;`를 두고 `Tick`에서 `WarnPop`과 같은 크기 계산(0.15초 동안 1.8 → 1, 그 뒤 1 + 0.12·sin(18t))을 한다. `Fx.Setup`에서 `pop = false`로 되돌린다(풀로 돌아간 이펙트가 다른 용도에서 튀지 않게). **`WarnPop` 컴포넌트를 풀 오브젝트에 붙이면 안 된다** — 풀은 모든 이펙트가 같이 써서 붙은 컴포넌트가 다른 이펙트에서 계속 돈다(쌓임).
3. **스크립트 붙은 오브젝트 `Instantiate` 금지**: 이번 작업에는 `Instantiate`가 없다. `SpaceErosion` · 버그 · 덩어리는 모두 `new GameObject` + `AddComponent`다. 보스바 아래 줄 복제(`Instantiate(backBar)`)는 지금 그대로이고, `UltGauge` · `UltLabel`에는 스크립트를 붙이지 않는다(새 글자도 `TextMeshProUGUI` 컴포넌트만).
4. **쌓이는 것 금지**
   - 결계 · 침식에서 만든 모든 오브젝트(고리 · 금 · 격자 · 코드 글자 · 후광 · 눈 · 결계 전용 캔버스)는 `domainRoot` 또는 컷신 캔버스 아래에 두고, 끝날 때 한 번에 지운다. 후광처럼 `domainRoot` 밖에 두는 것은 목록에 담아 `EndNow`에서 지운다(지금 `aura` 방식).
   - 어둠 메시 · 머티리얼은 지금 정적 하나를 같이 쓴다. 크기는 `localScale`로만 바꾼다(통금 · 침식).
   - `DomainCtx`는 미리 만든 것을 `Reset()`한다(결계마다 새로 만들지 않음). `lichBeams`는 ctx마다 4칸.
   - 정적 상태(`shared` · 대기열 · `participants` · `Pending` · `HoldSkills` · `restUntil`)는 장면마다 `ResetStatics()`.
   - 튕기는 것은 침식 전체 최대 4, 개별 결계는 지금 3(엄마 4). `!Active`면 스스로 사라진다(지금 `DomainBall` 규칙).
5. **탄 · 경고는 기존 풀**: `Hostile.Shoot`(풀) · `Hostile.Circle/Line`(풀) · `Fx.Spawn`(풀). 상한: 침식 탄 220 · 결계 탄 160 · `DevBulletCap` 400 · 대기 타격 96.
6. **찾기 질의**: `RepelMobs`의 `FindObjectsByType`(0.2초마다)는 침식에서도 **한 곳**(SpaceErosion)에서만 돈다. 개별 결계가 침식 중에 함께 돌 일은 없다(`Active` 하나).
7. **예상 부하**: 침식 n = 4에서 초당 땅 타격 약 12, 탄 약 60발. 지금 개발자전(탄 400 · 필살기 8개 겹침)보다 가볍다.

static void SharedTick()
{
    if (sharedFrame == Time.frameCount) return;
    sharedFrame = Time.frameCount;
    participants.Clear();
    foreach (bosss b in bosss.Live) if (b != null && !b.IsDead) participants.Add(b);

    sharedCount = n;
    if (Active || Pending) return;                         // 결계 · 대기 중에는 전환하지 않음
    if (!shared)
    {
        if (n == 1) soloSlot = SlotOf(participants[0]);
        else if (n >= 2)
        {
            shared = true;
            sharedGauge = soloSlot >= 0 ? gauge[soloSlot] : 0f;
            sharedLastHit = Time.time;
            NotifyMerged();                                // 토스트 10초 한 번 · 도움말 한 번
        }
        if (n == 0) soloSlot = -1;
        return;

    shared = false;
    if (n == 1) { int s = SlotOf(participants[0]); gauge[s] = sharedGauge; lastHit[s] = Time.time; soloSlot = s; }

## H. 검증 (실행해서 확인할 것 · 캡처나 일괄 실행 없이 손으로)

1. **이야기 모드 회귀**: 리치 왕 · 지옥의 군주 · 킹 슬라임 · 거울의 군주 결계를 하나씩 펼쳐 보고, 예고 · 간격 · 피해 숫자가 지금과 같은지 본다(ctx · 대기열 리팩터링 확인). 결계가 끝난 뒤 예고된 타격이 떨어지는 것도 지금처럼 보이는지 본다.
2. **겹침 2마리**: 무한 3분 뒤 둘째 보스가 나올 때, 첫 보스 게이지 값(예: 60%)이 그대로 「공간 침식 ×2」로 이어지는지 본다. 둘째를 때려도 차는지, 하나를 쓰러뜨리면 남은 보스 「결계」 막대가 같은 값으로 바뀌는지 본다.
3. **공간 침식**: 컷신(보스 비추기 · 이름 빨려 듦) → 펼침(보스 고리 → 큰 고리) → 15초 → 파열 순서. 고요의 눈 안에 땅 타격이 떨어지지 않는지, 플레이어 자리에 0.35초보다 촘촘히 떨어지지 않는지 본다. 침식 중 한 보스를 쓰러뜨리면 그 공격만 멈추는지, 모두 쓰러뜨리면 바로 끝나는지 본다.
4. **최후의 시간 4마리**: 증가가 지나치게 빠르지 않은지, 탄 220 상한, 프레임(`FpsCounter`)이 개발자전보다 떨어지지 않는지 본다.
5. **개발자 · 엄마**: 게이지가 보이고 차는지, 40%에서 가득 차는지, 대기(최대 3초) 뒤 컷신이 뜨는지, 결계 동안 영웅 필살기가 멈추고 끝나고 2초 뒤 다시 쓰는지 본다. 한 줄씩 실행의 주석 줄 · 강제 종료 미룸 · 통금 축소와 되돌림 · 청소기 끌림(걸어서 빠져나갈 수 있는지)을 확인한다.
6. **상황**: 침식 중 ESC · 메뉴로 나가 이어하기 · 1분 자동 저장 · 플레이어 사망 · 진화 창. 이어한 뒤 바로 침식이 다시 펼쳐지지 않는지 본다.
7. **이름**: 침식 · 개발자 결계에 맞고 쓰러졌을 때 「쓰러진 곳」 글자가 「공간 침식」 · 「개발자」로 나오는지 본다(A8-5).
8. **규칙 2 확인**: 커밋 전 `git grep -nE "using UnityEditor|UnityEditor\.|System\.Drawing" -- "Assets/*.cs" ":!Assets/**/Editor/**" ":!Assets/Editor/**"`.

## I. 정해 두었지만 바꿀 수 있는 것

- 침식 반지름 48 대신 아레나 사각형 전체(`ClampArena`로 가둠)를 쓸 수도 있다. 다만 둥근 어둠 메시 · 고리 · 금을 모두 사각형으로 다시 그려야 해서, 지금 자원을 그대로 쓰는 원형을 골랐다.
- 「고요의 눈」이 너무 편하면 반지름 3.5 → 2.8, 또는 본 진행 마지막 4초에는 눈을 없앤다.
- 엄마 「통금 시간」은 결계 반지름을 바꾸는 유일한 패턴이다. 다른 보스 패턴이 섞이는 침식에서는 쓰지 않는다(C6).
