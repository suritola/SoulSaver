## 1. 빈틈 (급소) — 「직접 조준한 공격만 빈틈을 맞힌다」

### 1-1. 왜 이 모양인가

- 자동 조준 게임에는 「어디를 맞혔나」가 없다. 빈틈은 「자동 조준 없음」이 보스전 매 초 의미가 있게 만드는 **게임 안 증거**다(전략 3절).
- 사용자 결정대로 잡몹에는 넣지 않는다 → 화면 혼잡 · 성능(한 화면 20~41마리) 걱정이 사라지고, 보스전이 「피하면서 노리는」 싸움이 된다.
- 기본 피해는 그대로 두고 **보너스만** 준다. 패드 · 공격 고정 · 조준이 서툰 사람이 손해 보지 않는다.

### 1-2. 코드 구조 (새 파일 `Assets/Scripts/WeakSpot.cs`)

지금 피해가 들어가는 길은 두 가지다.
1. 탄: `PlayerController.CreateBullet`(`PlayerController.cs:673`) → `Bullet.Hit`(`Bullet.cs:420~`) → `EnermyController.TakeDamage` / `bosss.TakeDamage`
2. 직접 피해: 검사 베기(`CharacterKit.cs:374`) · 유령 손길(`CharacterKit.Ghost.cs:75`) · 잉크 획(`CharacterKit.Cartographer.cs:108`) · 플라스크 폭발 등 → `Specials.Damage`(`SpecialObjects.cs:12`) → `TakeDamage`

빈틈은 **부르는 쪽(탄 · 근접 · 투척)이 모양을 넘기고, 배율을 곱한 피해로 `TakeDamage` 를 부르는** 방식으로 넣는다. `boss.cs` · `EnermyController.cs` 의 `TakeDamage` 는 건드리지 않는다(기억하는 보스 갈래 B 가 `boss.cs` 를 맡기 때문 · 5절).

```csharp
// WeakSpot.cs (A 갈래) — 뼈대
public class WeakSpot : MonoBehaviour            // 보스 · 중간 보스에 하나 (자식 그림 1개)
{
    public static readonly List<WeakSpot> Active = new List<WeakSpot>(8);   // OnEnable 추가 · OnDisable 제거 (판이 갈수록 쌓이지 않음)
    public bool Open { get; }                    // 지금 열려 있는지
    public Vector2 Center { get; }               // 월드 좌표 (그림 기준 위치 · flipX 따라 뒤집음)
    public float Radius { get; }                 // 월드 반지름 = 몸 반지름(EnemyHitbox.BodyWorldRadius) × 0.32, 최소 0.5 (킹 슬라임 0.42 · 최소 0.7)
    public bool BackOnly { get; }                // 지옥의 군주 등 비늘: 보스 뒤쪽에서 온 공격만

    public static WeakSpot Attach(GameObject host, WeakKind kind);           // 이미 있으면 그대로
}

public enum WeakShapeKind : byte { Ray, Segment, Point, Arc }
public readonly struct WeakShape                  // 할당 없는 값 타입
{
    public static WeakShape Ray(Vector2 from, Vector2 dir, float halfWidth, float mul);
    public static WeakShape Segment(Vector2 a, Vector2 b, float halfWidth, float mul);
    public static WeakShape Point(Vector2 at, float slack, float mul);
    public static WeakShape Arc(Vector2 origin, Vector2 dir, float halfDeg, float reach, float mul);
}

public static class WeakHit
{
    // 빈틈에 맞았으면 늘린 피해 (상한 적용) + 이번 한 대 표시를 켬, 아니면 damage 그대로
    public static float Apply(GameObject target, in WeakShape shape, float damage);
    // TakeDamage 를 부른 바로 뒤 반드시 (무적 · 죽음으로 피해가 안 들어가도 다음 숫자에 빈틈 표시가 새지 않게)
    public static void End();
}
```

- `Apply` 안에서: 대상의 `WeakSpot`(없으면 `GetComponent` 한 번, 보스 · 중간 보스만이라 드묾) → 열림 확인 → 모양 판정 → 상한 → `DamagePopup.NextWeak = true` · 소리 · 반짝임 · 카운터. `bosss.invulnerable`(망자의 의식) · `IsDead` 면 아무것도 안 함.
- **붙이는 곳**: 보스는 `WeakSpot.cs` 안의 관리자가 0.25초마다 `bosss.Live`(이미 있는 정적 목록 · `boss.cs`)를 훑어 `WeakSpot` 이 없는 보스에 붙인다(`boss.cs` 수정 없음). 중간 보스는 `MidBossMark.Attach` 에서 `prefix == true` 일 때 붙인다(`MidBossMark.cs:13`).
- **그림**: 자식 `new GameObject("WeakSpotRing")` + `SpriteRenderer` 하나(`Resources/FX/fx_target_rune` 첫 프레임, 정렬 레이어 Effect · 순서 39 → 피해 숫자 40 · 45 아래, 보스 몸 위). 보스 · 중간 보스 오브젝트를 `Instantiate` 로 복제하는 코드는 지금 없고(검색 결과 0), 앞으로도 이 그림 때문에 복제하지 않는다.
- **매 프레임**: 위치 · 크기 · 알파만 바꾼다(문자열 · 목록 · LINQ 없음). 열림/닫힘이 바뀌는 순간에만 0.2초 커지는 연출.

### 1-3. 「직접 조준」 판정 — 공격 종류별

공통 규칙: **조준 범위(AimScope)** 안에서 만들어진 탄 · 공격만 빈틈 후보다. 범위는 평타 · 조준 무기 발사 함수 둘레에 `using (WeakHit.AimScope(mul))` 로 친다. 탄은 만들 때 `Bullet.aimMul`(0 = 후보 아님)에 값을 받는다.

추가 규칙
- 탄의 방향이 **커서 방향에서 25° 넘게** 벗어나면 0(카드가 덤으로 흩뿌리는 탄은 빠지고, 멀티샷 3~4발 부채꼴은 들어감).
- 패드 「스틱을 놓고 RT 만 누른 보조 조준」(`GamePad.cs:215~224`, 가장 가까운 적의 몸 중심을 겨눔)으로 쏜 탄은 0 → `GamePad.AssistAiming`(새 정적 bool) 이 참이면 `CreateBullet` 이 `aimMul = 0`.
- 풀링: `Bullet.Revive`(`Bullet.cs` 「꺼낼 때」)에서 `aimMul = 0` · `perfect = false` 로 되돌린다(안 하면 다시 쓴 탄이 빈틈 자격을 물려받음).
- 관통 탄은 보스마다 한 번(이미 `hitOnce` · 「들어올 때만」 규칙 그대로).
- 「지난 자리 → 지금 자리」는 `Sweep` 의 `from` · `way` 를 `Hit` 에 넘겨 쓴다(`Bullet.cs` Sweep). 한 번에 30칸 넘게 옮겨진 탄(`TeleportDist`)은 방향을 `transform.right` 로.

### 1-4. 보스마다 빈틈 — 위치 · 열리는 때

위치는 그림 틀(스프라이트 bounds) 안의 비율(가로 0 = 왼쪽, 1 = 오른쪽 · 세로 0 = 발, 1 = 머리 꼭대기, flipX 면 가로를 뒤집음)로 정한다. 모두 `bosss` · `BossSkills` 의 **이미 공개된 상태**(`casting` · `airborne` · `EnemyHealth`)만 읽으므로 `BossSkills*.cs` 는 고치지 않는다.

| 보스 | 빈틈 | 위치(가로, 세로) | 열림 | 닫힘 | 근거 |

### 1-6. 게임패드 · 공격 고정 · 접근성

- **오른쪽 스틱 조준은 직접 조준이다**(사람이 방향을 정함) → 빈틈 후보. 단, 스틱은 마우스보다 정밀하지 않으므로 **빈틈 끌림**을 넣는다: 스틱을 기울인 방향에서 10° 안 · 14칸 안에 열린 빈틈이 있으면 조준 방향을 그쪽으로 60% 당긴다(`GamePad.UpdateAim` 의 `m > AimOn` 갈래 · `WeakSpot.Active` 를 훑음, 많아야 6개). 사람이 그쪽으로 기울였을 때만 도우므로 「자동 조준」이 아니다.
- **스틱을 놓고 RT 만 누른 보조 조준**(가장 가까운 적 몸 중심)은 자동 → 빈틈 제외(1-3).
- **공격 고정**(`GameSettings.cs:169` · 누르고 있기를 대신함)은 조준을 바꾸지 않으므로 그대로 후보.
- 마우스 감도 · 커서 스킨과는 무관. 설정 항목은 새로 만들지 않는다.

- 일일 도전 「같은 시드 공정성」: 빈틈 위치 · 열림은 시드가 아니라 보스 상태로 정해져 같은 날 모두 같다.

## 2. 기억하는 보스 — 「체력이 정해진 값에 닿으면, 이번 판에 가장 많이 맞은 공격을 기억해 막는다」

### 2-1. 발동 조건 — 보스별 체력 값

지난 판 기록이 아니라 **이번 보스전 체력**만 본다. 이미 있는 체력 단계(분노 50% · 결계 강제 40% · 지옥의 군주 66% · 33% · 리치 왕 의식 50% · 킹 슬라임 뱉기 50%)와 겹치지 않게 골랐다.

| 보스 | 발동 체력 | 횟수 | 지속(보통 · 어려움 / 쉬움) | 피하는 이유 |
|---|---|---|---|---|
| 킹 슬라임 | 60% | 1 | 10초 / 10초 · 약하게(×0.5) | 첫 보스 · 배우는 보스라 한 번만, 부드럽게. 50% 뱉기 · 40% 결계와 떨어짐 |
| 리치 왕 | 75% · 30% | 2 | 12 / 10 | 50% 의식 사이 |
| 지옥의 군주 | 50% · 20% | 2 | 12 / 10 | 66% 날개 · 33% 분노 사이 (분노 50% 알림은 지옥의 군주에게 원래 없음 `boss.cs` TakeDamage) |
| 거울의 군주 | 75% · 30% | 2 | 12 / 10 | 50% 「되비친 기억」(`BossSkills.cs:61~70`) 앞뒤 |
| 개발자 | 66% · 33% | 2 | 12 / 10 | 체력이 닳을수록 간격 10초 → 1초 (`BossSkills.Developer.cs`) — 중간 지점 |
| 개발자 엄마 | 75% · 50% · 25% | 3 | 10 / 10 | 「엄마는 다 기억한다」 · ×2 컨셉으로 한 번 더 |

- **미뤄지는 때**: 결계 중(`BossUltimate.Active`) · 결계 외침 연출 중 · 이야기 연출 중(`StoryDirector.Playing`) · 의식 무적 중 · 다른 보스의 기억이 진행 중(무한 모드 동시 보스: **한 번에 하나**, 앞 기억이 끝나고 3초 뒤) → 조건이 풀리는 첫 프레임에 발동. 체력 값을 여러 개 한꺼번에 넘으면(센 한 방) 하나만 발동하고 나머지는 차례로 미룸.
- **이어하기**: 되살린 보스(`restoreHp` · `restoreMaxHp`)는 지금 체력보다 높은 값을 이미 쓴 것으로 친다(저장 칸 없음 · `RunSave.Version` 그대로).
- **끄는 곳**: 튜토리얼(`TutorialRun.Active`). 일일 도전 · 무한 · 순위표 판에서는 **켠다**(지난 판을 안 보므로 모두에게 같다).

### 2-2. 무엇을 기억하나

- `BossMemory` 가 보스마다 `Dictionary<string, float>`(출처 → 이 보스에게 준 피해)를 **보스가 생길 때 한 번** 만들고, `bosss.TakeDamage` 가 `RunStats.Dealt` 옆에서 같은 열쇠(`DamageSource.Current`)로 더한다(문자열은 이미 있는 상수 · 능력 이름이라 할당 없음). 보스가 지워지면 같이 사라진다(판이 갈수록 쌓이지 않음).
- 첫 기억: 보스전 시작부터 지금까지 1위. 두 번째부터: **지난 기억이 끝난 뒤부터** 1위(모아 둔 값을 기억이 끝날 때 0 으로) → 다른 공격으로 바꾸면 보스가 그것을 배운다. 그 사이 피해가 최대 체력 1% 미만이면 보스전 전체 1위.
- 「기타」(`DamageSource.Other`)는 고르지 않는다. 출처가 하나뿐이면(평타만) 평타를 고른다 — 평타는 2-3 의 **방패**라 돌아서 맞히면 되므로 막다른 길이 없다.
- **평타 종류**로 보는 것: `DamageSource.Basic`(「평타」) + 지금 든 거너 특수 무기 · 영웅 전용 무기의 이름(`SpecialAbilities.CurrentWeapon` 의 출처 이름과 같으면). 그 밖(필살기 · 특수 능력 이름 · 고유 스킬 · 영혼 트리)은 **기술**로 본다.

### 2-3. 막는 법 · 무력화

| | 기억의 방패 (평타 종류) | 기억의 결 (기술) |
|---|---|---|
| 막는 것 | 보스 **정면 120°**(방패가 향한 쪽 ±60°) 에서 들어온 그 출처의 피해 ×0.2 | 그 출처의 피해 ×0.35 (방향 무관) |
| 방향 | 기억한 순간 플레이어 쪽에 고정 → **4초마다** 방패가 0.8초 깜빡인(경고) 뒤 지금 플레이어 쪽으로 다시 돎 | — |
| 보이는 것 | 보스 몸 둘레(몸 반지름 × 1.35) 120° 반원 띠 · 보스별 색 · 막힌 탄 자리에 회색 불꽃 + 회색 숫자 | 보스 몸에 그 출처 색의 옅은 막 · 막힌 피해는 회색 숫자 |
| 판정 위치 | 「들어온 방향」 = 보스 → 플레이어 방향(탄 · 근접 모두 같은 기준, 투척은 떨어진 자리 → 보스 방향) | — |
| 빈틈과의 관계 | 지옥의 군주(등 비늘)처럼 **뒤쪽 빈틈 + 앞 방패**가 겹치면 돌아가는 길이 정답이 된다. 갈래 A 가 없어도 성립 | 기억된 출처로 빈틈을 맞혀도 ×0.35 가 같이 곱해짐 |
| 쉬움 | ×0.4 · 경고 1.0초 | ×0.5 |
| 어려움 | ×0.15 | ×0.3 |

- **지속**: 2-1 표의 초. 결계 중에는 시간이 멈춘다(결계가 기억을 먹지 않게).
- **기억 깨기**: 기억하지 않은 출처(방패면 옆 · 뒤에서 들어온 같은 평타도 포함)로 **최대 체력의 5%(쉬움 3% · 엄마 4%)** 를 깎으면 즉시 깨짐 → 「기억이 깨졌다!」 · 1.5초 휘청(`bosss` 새 칸 `memoryTakenMul = 1.25` · 보스 몸 하얗게 깜빡) · 소리 `shatter` 피치 0.8.
- **끝까지 버티면**: 「기억이 흐려졌다.」 토스트만(휘청 없음).
- **답답하지 않게** — 막는 동안에도 맞은 숫자가 회색으로 뜨고(무시당한 느낌이 아니라 「막혔다」는 정보), 보스바에 「기억: 평타 8초」가 남은 초와 함께 떠서 끝이 보이며, 부제가 해법(돌아가라 / 다른 공격)을 문장으로 말한다. 다른 공격으로 바꾼 사람에게는 휘청 보너스가 돌아간다.

### 2-5. 연출 순서 (게임을 멈추지 않음)

1. 발동: 보스 몸 0.6초 흰빛 · `Hostile.Shake` 약하게 · 소리 `shimmer` 피치 0.55 볼륨 0.7.
2. 큰 알림 `Notice.Big(대사, 부제, NoticeIcon.Boss, 3초, Urgent)` — 대사는 보스별 틀에 기억한 공격의 이름말(2-6), 부제는 규칙 문장.
3. 보스바: 이름 아래 「기억: {공격} {n}초」(초가 바뀔 때만 글자 갱신 · 0~15 초 문자열은 미리 만들어 둠). 체력바에 **기억 눈금**(청록 마름모)을 2-1 의 값 자리에 · 지나면 회색.
4. 깨짐 / 흐려짐 알림.
- 보스의 `casting` 은 건드리지 않는다(BossSkills 의 기술 진행과 엉키지 않게).

### 2-7. 밸런스 · 공정성

- 기억 동안 손해: 1위 출처 몫이 70% 인 사람이 바꾸지 않으면 12초 동안 피해 0.7 × 0.35 + 0.3 = 0.545 → 보스전마다 약 5.5초 × 2회 = **+11초**. 바꾸면 4~6초 안에 깨고 1.5초 휘청(+25%)으로 일부 돌려받아 **+3초 안팎**.
- 빈틈(1-7) 의 −2~−15% 와 합치면 익숙한 손 기준 보스전 길이는 1.2 와 비슷하다. **보스 체력 · 공격 수치는 바꾸지 않는다.**
- 측정: balance_log `memory_trig` · `memory_break`(깬 비율), 보스전 사망률(`last_hit`) — 깬 비율이 30% 아래면 깨기 몫을 5% → 4% 로.
- 영혼의 무게 · 각인과 겹침: 무게 3(결계 게이지 +35%)과 상관없음. 무게로 기억을 세게 하지 않는다.

### 2-8. 코드 구조

- 새 `BossMemory.cs`: `bosss.Start` 에서 `BossMemory.Attach(this)` (튜토리얼 제외). 체력 값 · 지속 · 배율 표(2-1 · 2-3), 집계 사전, 방패 각도 · 재조준 타이머, 깨기 누적, 전역 「진행 중 하나」 정적 참조(씬이 바뀌면 비움), 방패 띠는 `Hostile.NewLine` + `Hostile.SetArc`(이미 있는 공개 함수 · 점 버퍼 재사용 `Hostile.PointBuffer`).
- `boss.cs` `TakeDamage`:
  1. `damage *= erosionMul;` 다음 줄에 `damage *= memory != null ? memory.Incoming(DamageSource.Current, dir) : 1f;` 그리고 `damage *= memoryTakenMul;` (망자의 의식이 덮어쓰는 `damageTakenMul` 과 따로)
  2. `RunStats.Dealt(...)` 줄 옆에 `memory?.Tally(DamageSource.Current, 실제로 깎인 양)`
  3. 체력이 줄어든 뒤 `memory?.OnHealth(before, EnemyHealth)` (발동 판정 · 깨기 누적)
  4. 새 칸 `[System.NonSerialized] public BossMemory memory; [System.NonSerialized] public float memoryTakenMul = 1f;` — 직렬화하지 않아 프리팹 · 복제에 섞이지 않음(이미 쓰는 방식 `spawnedAt` 과 같음)
- `bossbar.cs`: `TicksOf(kind)` 옆에 기억 눈금 배열(`BossMemory.Thresholds(kind)` · 개발자 · 엄마 포함), 눈금은 기존처럼 **이름으로 다시 찾아 씀**(줄을 복제하면 눈금도 복제되므로 · `bossbar.cs:102`), 이름 아래 「기억: …」 한 줄.
- `RunStats.cs` `Hurt`: 거울 조각 되쏘기를 맞으면 `"BossMemory" => "기억의 방패"` 로 기록(지금은 「기타」로 빠짐).

### 4-3. 캡슐 이미지 명세

**글자 규칙 충돌 — 결정**: 스팀 그래픽 에셋 규칙은 캡슐에 **게임 이름(로고)과 공식 부제 말고 다른 글자를 넣지 못하게** 한다. 이 저장소도 이미 그렇게 정해 두었다(`docs/steam/README.md` 「캡슐: 로고 말고는 글자 없음」). 「조준 · 장전 · 진화」는 공식 부제가 아니라 홍보 문구이고, 공식 부제로 만들면 스팀 전체에서 게임 이름이 바뀐다(전략 4-C ⑤ 개명 금지). 그래서 **캡슐에는 글자를 넣지 않고 세 동사를 그림으로** 보여 준다: 조준 = 커서 십자선과 조준선, 장전 = 허공에 흩어지는 탄피 셋, 진화 = 리볼버 총구에서 갈라지는 금빛 진화 빛. 문구 「조준 · 장전 · 진화 / AIM. RELOAD. EVOLVE.」는 트레일러 끝 카드 · 짧은 설명 · 본문 맨 위 그림(본문 그림은 글자 허용) · 이벤트 표지에 둔다.

**구도(모든 크기 공통)**: 인물 하나(거너) — 몸은 왼쪽 아래에서 오른쪽 위를 향해 리볼버를 겨눔, 커서 십자선 → 조준선(금빛 선) → **결계 고리 안의 보스**(지옥의 군주 · 불빛 대비가 가장 좋음) 몸의 **빛나는 빈틈**에 닿는 순간. 결계 고리는 보스 둘레 타원(룬 고리 · 청록 안쪽 빛 · 바깥 어둠). 무리는 뒤에 실루엣(어둡게 0.38배). 로고는 위 왼쪽.

## 5. 구현 묶음 — 서로 다른 파일 3갈래

규칙(세 갈래 공통)
- 게임 스크립트에 `using UnityEditor…` · `System.Drawing` 금지. 확인: `git grep -nE "using UnityEditor|UnityEditor\.|System\.Drawing" -- "Assets/*.cs" ":!Assets/**/Editor/**" ":!Assets/Editor/**"` 가 0. (`TrailerDirector.cs` 는 이미 `#if UNITY_EDITOR` 로 감싸져 있음 · `tools/` 는 빌드 밖)
- **`RunSave.Version` 을 올리지 않는다.** 새 상태는 저장하지 않거나(빈틈) 지금 체력에서 다시 계산한다(기억).
- 스크립트가 붙은 오브젝트를 `Instantiate` 로 자기 복제하지 않는다 · 매 프레임 할당 금지(문자열 합치기 · LINQ · `new List` · 람다 캡처) · 판이 갈수록 쌓이는 정적 목록 금지(씬이 바뀌면 비우거나 OnDisable 에서 뺌).
- 새 문구는 4개 언어 · 설명은 완결 문장(`docs/review/2026-10-16-문구-다듬기-지침.md` 0절 · 5절). 새 번역은 **새 부분 파일**에만(같은 키를 `LocTable.cs` 에 두 번 넣으면 게임이 켜지지 않음 — 지침 1-2).
- 커밋은 한글 「타입: 내용」 + 끝 두 줄(`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` · `Claude-Session: https://claude.ai/code/session_01NnVnGrahRDbCYpVxsnZsAv`). **push 하지 않는다.**
- 갈래끼리 **컴파일 의존이 없다**: A 는 B 의 문구를 `Loc.Has` 로만, C 는 A · B 의 타입을 리플렉션으로만 본다. 어느 순서로 합쳐도 빌드가 된다.
