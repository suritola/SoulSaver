## 1. 빈틈 (급소) — 「직접 조준한 공격만 빈틈을 맞힌다」

### 1-1. 왜 이 모양인가

- 자동 조준 게임에는 「어디를 맞혔나」가 없다. 빈틈은 「자동 조준 없음」이 보스전 매 초 의미가 있게 만드는 **게임 안 증거**다(전략 3절).
- 사용자 결정대로 잡몹에는 넣지 않는다 → 화면 혼잡 · 성능(한 화면 20~41마리) 걱정이 사라지고, 보스전이 「피하면서 노리는」 싸움이 된다.
- 기본 피해는 그대로 두고 **보너스만** 준다. 패드 · 공격 고정 · 조준이 서툰 사람이 손해 보지 않는다.

### 1-2. 코드 구조 (새 파일 `Assets/Scripts/WeakSpot.cs`)

지금 피해가 들어가는 길은 두 가지다.
1. 탄: `PlayerController.CreateBullet`(`PlayerController.cs:675`) → `Bullet.Sweep`(`Bullet.cs:328`, 지난 자리 `from` → 지금 자리 스윕) → `Bullet.Hit(Collider2D)`(`Bullet.cs:420`, 적 갈래 450 · 보스 갈래 486) → `EnermyController.TakeDamage` / `bosss.TakeDamage`. 스윕 판정이 없는 탄은 `OnTriggerEnter2D`(`Bullet.cs:412`) → `Hit`
2. 직접 피해: 검사 베기(`CharacterKit.cs:374`) · 유령 손길(`CharacterKit.Ghost.cs:75`) · 잉크 획(`CharacterKit.Cartographer.cs:108`) · 샷건 부채꼴(`SpecialAbilities.Weapons.cs:217`) · 플라스크 폭발(`CharacterKit.cs:243` DamageCircle) 등 → `Specials.Damage`(`SpecialObjects.cs:13`) → `TakeDamage`

빈틈은 **부르는 쪽(탄 · 근접 · 투척)이 모양을 넘기고, 배율을 곱한 피해로 `TakeDamage` 를 부르는** 방식으로 넣는다. `boss.cs` · `EnermyController.cs` 의 `TakeDamage` 는 건드리지 않는다(기억하는 보스 갈래 B 가 `boss.cs` 를 맡기 때문 · 5절).

```csharp
// WeakSpot.cs (A 갈래) — 뼈대
public class WeakSpot : MonoBehaviour            // 보스 · 중간 보스에 하나 (자식 그림 1개)
{
    public static readonly List<WeakSpot> Active = new List<WeakSpot>(8);   // OnEnable 추가 · OnDisable 제거 (판이 갈수록 쌓이지 않음)
    public bool Open { get; }                    // 지금 열려 있는지
    public Vector2 Center { get; }               // 월드 좌표 (그림 기준 위치 · flipX 따라 뒤집음)
    public float Radius { get; }                 // 월드 반지름 = 몸 반지름(EnemyHitbox 컴포넌트의 BodyWorldRadius, 붙일 때 GetComponent 한 번) × 0.32, 최소 0.5 (킹 슬라임 0.42 · 최소 0.7)
    public bool OutsideBody { get; }             // 개발자 · 엄마의 「버그」처럼 몸 밖을 도는 빈틈 (탄 판정 길이를 짧게 · 1-3 추가 규칙)
    public float MaxHp { get; }                  // 상한 계산용: bosss / EnermyController 의 setEnemyHP

    public static WeakSpot Attach(GameObject host, WeakKind kind);           // 이미 있으면 그대로
}

public enum WeakShapeKind : byte { Ray, Segment, Point, Arc }
public readonly struct WeakShape                  // 할당 없는 값 타입
{
    public static WeakShape Ray(Vector2 from, Vector2 dir, float halfWidth, float mul);
    public static WeakShape Segment(Vector2 a, Vector2 b, float halfWidth, float mul);
    public static WeakShape Point(Vector2 at, float slack, float mul);
    public static WeakShape Arc(Vector2 origin, Vector2 dir, float halfDeg, float reach, float mul);
}

public static class WeakHit
{
    // 빈틈에 맞았으면 늘린 피해 (상한 적용) + 이번 한 대 표시를 켬, 아니면 damage 그대로
    public static float Apply(GameObject target, in WeakShape shape, float damage);
    // TakeDamage 를 부른 바로 뒤 반드시 (무적 · 죽음으로 피해가 안 들어가도 다음 숫자에 빈틈 표시가 새지 않게)
    public static void End();
}
```

- `Apply` 안에서: 대상의 `WeakSpot`(`TryGetComponent` · 할당 없음, 보스 · 중간 보스 태그일 때만 부름) → 열림 확인 → 모양 판정 → 상한 → `DamagePopup.NextWeakTarget = target.transform` · 소리 · 반짝임 · 카운터. `bosss.invulnerable`(망자의 의식) · `IsDead` 면 아무것도 안 함.
  - 표시 깃발을 **대상 Transform** 으로 두는 까닭: `bosss.TakeDamage` 는 `DamagePopup.Show` 보다 먼저 `SignatureSkills.Hit` · `BossUltimate.OnBossHit` 를 부르므로(`boss.cs:253~255`), 그 안에서 다른 적이 맞으면 bool 깃발은 엉뚱한 숫자가 먹는다. `Show(target, …)` 가 `target == NextWeakTarget` 일 때만 읽고 끈다.
  - 상한은 `TakeDamage` 에 넘기기 **전** 값에 건다. 그 뒤 `GameMode.PlayerDamageMul` · 치명타(`RollCrit`, 보스만) · `SignatureSkills.Outgoing` 이 전체에 곱해지므로 실제로 깎이는 보너스는 이 배율만큼 함께 움직인다(공정성 문제 없음 · 모두 같은 규칙).
- **붙이는 곳**: 보스는 `WeakSpot.cs` 안의 관리자(`SceneManager.sceneLoaded` 로 「GameScene」에서만 `new GameObject("WeakSpots")` 하나)가 0.25초마다 `bosss.Live`(이미 있는 정적 목록 · `boss.cs:105`, 죽은 보스가 남아 있을 수 있어 `IsDead` 는 건너뜀)를 훑어 `WeakSpot` 이 없는 보스에 붙인다(`boss.cs` 수정 없음 · `LiveCount` 는 람다 `RemoveAll` 이라 쓰지 않고 목록을 직접 돈다). 중간 보스는 `MidBossMark.Attach` 에서 `prefix == true` 일 때 붙인다(`MidBossMark.cs:16`, 엘리트도 `EnemySpawner.SpawnMidBoss` → `EnemySpawn.cs:255` 같은 길).
- **그림**: 자식 `new GameObject("WeakSpotRing")` + `SpriteRenderer` 하나(`Resources/FX/fx_target_rune` 첫 프레임, 정렬 레이어 Effect · 순서 39 → 피해 숫자 40 · 45 아래, 보스 몸 위). 보스 · 중간 보스 오브젝트를 `Instantiate` 로 복제하는 코드는 지금 없고(검색 결과 0), 앞으로도 이 그림 때문에 복제하지 않는다.
- **매 프레임**: 위치 · 크기 · 알파만 바꾼다(문자열 · 목록 · LINQ 없음). 열림/닫힘이 바뀌는 순간에만 0.2초 커지는 연출.

### 1-3. 「직접 조준」 판정 — 공격 종류별

공통 규칙: **조준 범위(AimScope)** 안에서 만들어진 탄 · 공격만 빈틈 후보다. 범위는 평타 · 조준 무기 발사 함수 둘레에 `using (WeakHit.AimScope(mul))`(readonly struct · 할당 없음 · `DamageSource.As` 와 같은 모양)로 친다. 탄은 만들 때 `Bullet.aimMul`(0 = 후보 아님)에 값을 받는다. 범위 안에서 **명중 콜백(`onHitEnemy`)이 새로 만드는 탄**(튕기는 톱니 · 갈라지는 화살 등)은 콜백이 나중 프레임의 `Bullet.Hit` 에서 돌기 때문에 저절로 범위 밖 → 0. 0.15초 뒤 코루틴으로 나가는 덤 공격(도적 「메아리」 `EchoThrow` · 궁수 `EchoArrow`)도 범위 밖이라 제외된다(덤 피해 60% · 50% 라 의도에 맞음).

### 1-6. 게임패드 · 공격 고정 · 접근성

- **오른쪽 스틱 조준은 직접 조준이다**(사람이 방향을 정함) → 빈틈 후보. 단, 스틱은 마우스보다 정밀하지 않으므로 **빈틈 끌림**을 넣는다: 스틱을 기울인 방향에서 10° 안 · 14칸 안에 열린 빈틈이 있으면 조준 방향을 그쪽으로 60% 당긴다(`GamePad.UpdateAim` 의 `m > AimOn` 갈래 · `WeakSpot.Active` 를 훑음, 많아야 6개). 사람이 그쪽으로 기울였을 때만 도우므로 「자동 조준」이 아니다.
- **스틱을 놓고 RT 만 누른 보조 조준**(가장 가까운 적 몸 중심)은 자동 → 빈틈 제외(1-3).
- **공격 고정**(`GameSettings.cs:170` `AttackLock` · `GameInput.AttackLocked`, 패드 · 튜토리얼 · 자동 조종에서는 꺼짐)은 누르고 있기만 대신하고 조준을 바꾸지 않으므로 그대로 후보.
- 마우스 감도 · 커서 스킨과는 무관. 설정 항목은 새로 만들지 않는다.

- 계산식: 증가 ≈ 몫 × 열림 × 명중 × 0.75. 기억하는 보스(2절)가 보스전마다 +3~11초를 되돌려 놓으므로 익숙한 손 기준 **보스전 길이는 거의 그대로**, 손이 좋은 사람만 빨라진다.
- **보스 체력은 바꾸지 않는다.** 빈틈 · 기억 빌드를 올린 뒤 balance_log 의 새 칸 `weak_share`(빈틈으로 더한 피해 ÷ 빈틈이 붙은 보스 · 중간 보스에게 준 피해)의 중앙값이 15% 를 넘으면 탄 배율을 1.75 → 1.5 로 내린다.
  - 분모를 세는 법: `bosss.TakeDamage` 는 B 갈래 파일이라 A 가 손댈 수 없고, `RunStats.DamageDealt` 는 대상 구분이 없다. 그래서 **`WeakSpot` 이 붙을 때 그 대상의 체력을 적어 두고, 꺼질 때(OnDisable) · 판 기록을 쓸 때 「적어 둔 체력 − 지금 체력」(죽었으면 적어 둔 체력 전부)을 정적 합계에 더한다.** 보너스는 `RunCounters.Add("weak.bonus", 반올림한 보너스)`(정수 카운터), 분모는 `WeakSpot.DealtTotal`(float · 판 시작 때 0). 이어하기로 되살린 보스는 되살린 체력부터 셈(저장 칸 없음 · 판 전체 비율이라 오차 작음).
- **순위표**(무한 · 일일 도전 · 점수 = 버틴 시간, `SteamManager.cs:355` 자세한 값 순서): 같은 버전의 모든 사람에게 같은 규칙이고, 자세한 값 4번에 판 버전(`VersionCode()`, 예 1.2.6 → 10206)이 이미 들어간다 → 따로 끄지 않는다. 패치노트에 「무한 · 일일 순위표 기록은 빈틈 · 기억 규칙이 더해진 판입니다」 한 줄.
- 일일 도전 「같은 시드 공정성」: 빈틈 위치 · 열림은 시드가 아니라 보스 상태로 정해져 같은 날 모두 같다.

## 2. 기억하는 보스 — 「체력이 정해진 값에 닿으면, 이번 판에 가장 많이 맞은 공격을 기억해 막는다」

### 2-1. 발동 조건 — 보스별 체력 값

지난 판 기록이 아니라 **이번 보스전 체력**만 본다. 이미 있는 체력 단계(분노 50% · 결계 강제 40% · 지옥의 군주 66% · 33% · 리치 왕 의식 50% · 킹 슬라임 뱉기 50%)와 겹치지 않게 골랐다.

| 보스 | 발동 체력 | 횟수 | 지속(보통 · 어려움 / 쉬움) | 피하는 이유 |
|---|---|---|---|---|
| 킹 슬라임 | 60% | 1 | 10초 / 10초 · 약하게(막는 몫 절반, 2-3) | 첫 보스 · 배우는 보스라 한 번만, 부드럽게. 50% 뱉기(`SlimeTurn` 의 `Enraged`) · 40% 결계와 떨어짐 |
| 리치 왕 | 75% · 30% | 2 | 12 / 10 | 50% 의식 사이 |
| 지옥의 군주 | 50% · 20% | 2 | 12 / 10 | 66% 날개 · 33% 분노 사이 (분노 50% 알림은 지옥의 군주에게 원래 없음 `boss.cs` TakeDamage) |
| 거울의 군주 | 75% · 30% | 2 | 12 / 10 | 50% 「되비친 기억」(`BossSkills.cs:61~70`) 앞뒤 |
| 개발자 | 66% · 33% | 2 | 12 / 10 | 체력이 닳을수록 간격 10초 → 1초 (`BossSkills.Developer.cs`) — 중간 지점 |

- **미뤄지는 때**: 결계 중(`BossUltimate.Active`) · 결계 외침 연출 중(`BossUltimate.CutscenePlaying`) · 이야기 연출 중(`StoryDirector.Playing`) · 의식 무적 중(`bosss.invulnerable`) · 다른 보스의 기억이 진행 중(무한 모드 동시 보스: **한 번에 하나**, 앞 기억이 끝나고 3초 뒤) → 조건이 풀리는 첫 프레임에 발동. 체력 값을 여러 개 한꺼번에 넘으면(센 한 방) 하나만 발동하고 나머지는 차례로 미룸.
- **이어하기**: 되살린 보스(`restoreHp` · `restoreMaxHp`, `boss.cs:62~63` · `Start` 가 148~149 에서 체력에 넣음)는 지금 체력보다 높은 값을 이미 쓴 것으로 친다(저장 칸 없음 · `RunSave.Version` 그대로). `BossUltimate` 가 「되살린 체력이 40% 아래면 결계를 이미 쓴 것으로」 하는 방식(`BossUltimate.cs:58`)과 같다.
- **끄는 곳**: 튜토리얼(`TutorialRun.Active`). 일일 도전 · 무한 · 순위표 판에서는 **켠다**(지난 판을 안 보므로 모두에게 같다).

### 2-2. 무엇을 기억하나

- `BossMemory` 가 보스마다 `Dictionary<string, float>`(출처 → 이 보스에게 준 피해)를 **보스가 생길 때 한 번** 만들고, `bosss.TakeDamage` 가 `RunStats.Dealt` 옆에서 같은 열쇠(`DamageSource.Current ?? DamageSource.Other` — `RunStats.Dealt` 와 같은 규칙, `RunStats.cs:134`)로 더한다(문자열은 이미 있는 상수 · 능력 이름이라 할당 없음 · 처음 보는 열쇠만 사전 칸이 하나 늘어남). 보스가 지워지면 같이 사라진다(판이 갈수록 쌓이지 않음).
- 거울의 군주의 50% 「되비친 기억」(`BossSkills.cs:61~70` · `TopSource` 837)은 **판 전체**(`RunStats.DamageDealt`) 1위를 쓴다. 기억하는 보스는 **이번 보스전 · 이 보스** 1위라 같은 판에서 둘이 다른 공격을 고를 수 있다 — 거울의 군주에게는 「판 전체를 비추는 거울 · 이번 싸움을 배우는 방패」로 둘 다 살린다(2-4).
- 첫 기억: 보스전 시작부터 지금까지 1위. 두 번째부터: **지난 기억이 끝난 뒤부터** 1위(모아 둔 값을 기억이 끝날 때 0 으로) → 다른 공격으로 바꾸면 보스가 그것을 배운다. 그 사이 피해가 최대 체력 1% 미만이면 보스전 전체 1위.
- 「기타」(`DamageSource.Other`)는 고르지 않는다. 출처가 하나뿐이면(평타만) 평타를 고른다 — 평타는 2-3 의 **방패**라 돌아서 맞히면 되므로 막다른 길이 없다.
- **평타 종류**로 보는 것: `DamageSource.Basic`(「평타」) + 지금 든 거너 특수 무기 · 영웅 전용 무기의 출처 이름. 무기 출처는 `SpecialAbilities.SourceOf(CurrentWeapon)`(`SpecialAbilities.cs:980`, **private**)이 `abilities[id].name` 을 돌려주는 것이므로, B 는 공개 칸으로 같은 값을 만든다: `var sa = SpecialAbilities.SharedInstance; int w = sa != null ? sa.CurrentWeapon : -1; string weapon = w >= 0 && sa.abilities[w] != null ? sa.abilities[w].name : null;`(발동 순간에만 · `SpecialAbilities.cs` 수정 없음). 그 밖(필살기 · 특수 능력 이름 · 고유 스킬 · 영혼 트리)은 **기술**로 본다.

### 2-7. 밸런스 · 공정성

- 기억 동안 손해: 1위 출처 몫이 70% 인 사람이 바꾸지 않으면 12초 동안 피해 0.7 × 0.35 + 0.3 = 0.545 → 보스전마다 약 5.5초 × 2회 = **+11초**. 바꾸면 4~6초 안에 깨고 1.5초 휘청(+25%)으로 일부 돌려받아 **+3초 안팎**.
- 빈틈(1-7) 의 −2~−15% 와 합치면 익숙한 손 기준 보스전 길이는 1.2 와 비슷하다. **보스 체력 · 공격 수치는 바꾸지 않는다.**
- 측정: balance_log `memory_trig` · `memory_break`(깬 비율), 보스전 사망률(`last_hit`) — 깬 비율이 30% 아래면 깨기 몫을 5% → 4% 로.
- 영혼의 무게 · 각인과 겹침: 무게 3(결계 게이지 +35%)과 상관없음. 무게로 기억을 세게 하지 않는다.

### 4-3. 캡슐 이미지 명세

**글자 규칙 충돌 — 결정**: 스팀 그래픽 에셋 규칙은 캡슐에 **게임 이름(로고)과 공식 부제 말고 다른 글자를 넣지 못하게** 한다. 이 저장소도 이미 그렇게 정해 두었다(`docs/steam/README.md` 「캡슐: 로고 말고는 글자 없음」). 「조준 · 장전 · 진화」는 공식 부제가 아니라 홍보 문구이고, 공식 부제로 만들면 스팀 전체에서 게임 이름이 바뀐다(전략 4-C ⑤ 개명 금지). 그래서 **캡슐에는 글자를 넣지 않고 세 동사를 그림으로** 보여 준다: 조준 = 커서 십자선과 조준선, 장전 = 허공에 흩어지는 탄피 셋, 진화 = 리볼버 총구에서 갈라지는 금빛 진화 빛. 문구 「조준 · 장전 · 진화 / AIM. RELOAD. EVOLVE.」는 트레일러 끝 카드 · 짧은 설명 · 본문 맨 위 그림(본문 그림은 글자 허용) · 이벤트 표지에 둔다.

## 5. 구현 묶음 — 서로 다른 파일 3갈래

규칙(세 갈래 공통)
- 게임 스크립트에 `using UnityEditor…` · `System.Drawing` 금지. 확인: `git grep -nE "using UnityEditor|UnityEditor\.|System\.Drawing" -- "Assets/*.cs" ":!Assets/**/Editor/**" ":!Assets/Editor/**"` 가 0. (`TrailerDirector.cs` 는 이미 `#if UNITY_EDITOR` 로 감싸져 있음 · `tools/` 는 빌드 밖)
- **`RunSave.Version` 을 올리지 않는다.** 새 상태는 저장하지 않거나(빈틈) 지금 체력에서 다시 계산한다(기억).
- 스크립트가 붙은 오브젝트를 `Instantiate` 로 자기 복제하지 않는다 · 매 프레임 할당 금지(문자열 합치기 · LINQ · `new List` · 람다 캡처) · 판이 갈수록 쌓이는 정적 목록 금지(씬이 바뀌면 비우거나 OnDisable 에서 뺌).
- 새 문구는 4개 언어 · 설명은 완결 문장(`docs/review/2026-10-16-문구-다듬기-지침.md` 0절 · 5절). 새 번역은 **새 부분 파일**에만(같은 키를 `LocTable.cs` 에 두 번 넣으면 게임이 켜지지 않음 — 지침 1-2).
- 커밋은 한글 「타입: 내용」 + 끝 두 줄(`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` · `Claude-Session: https://claude.ai/code/session_01NnVnGrahRDbCYpVxsnZsAv`). **push 하지 않는다.**
- 갈래끼리 **컴파일 의존이 없다**: A 는 B 의 문구를 `Loc.Has` 로만, C 는 A · B 의 타입을 리플렉션으로만 본다. 어느 순서로 합쳐도 빌드가 된다.

## 검토 기록 (2026-10-18 · 2차 · main `42c5c6e` 기준)

3. **상한을 최종 피해 기준으로** — 상한이 `Apply`(배율 전)에 걸려 치명타 · 난이도 · 기억 방패/휘청 · 고유 스킬 배율이 그 위에 곱해졌고, 거너 평타(쏠 때 치명타)와 다른 영웅의 기준이 달랐다 → `Apply` 는 보너스만 적어 두고, `bosss` · `EnermyController.TakeDamage` 가 모든 배율 뒤 `WeakHit.Settle` 을 불러 최종 피해를 같은 비율로 나눈 뒤 빈틈 몫만 2.5%(중간 보스 6%)로 자른다.
4. **유탄 직격점이 보스를 두 번 때림** — `PointBonus` 가 빈틈 몫을 따로 `Specials.Damage` 해서 치명타 · 결계 게이지 · 소환 수 · 고유 스킬 명중 · 숫자가 한 번씩 더 생겼다 → `Explode(…, weakMul)` 이 폭발 피해가 그 보스에게 들어갈 때 `WeakHit.Hit` 으로 늘림(연금술사 `DamageCircle` 과 같은 방식). `PointBonus` 삭제.
5. **기록 칸 기준 통일** — `weak_hits` 는 `RunCounters` 「weak.hit」, `weak_share` 는 「weak.bonus」 ÷ 「weak.dealt」(새 카운터 · 둘 다 배율 뒤 실제 값, 소수는 모았다가 정수로). 판 저장(counters)이 되살려 이어하기도 판 전체 · 기억 칸 · 계약 weak30 과 같은 기준. `RunLog.Row` 가 쓰기 직전 `WeakSpot.FlushAll`. `RunSave.Version` 그대로(카운터 문자열에 열쇠만 늘어남).
6. **빈틈 숫자 합치기** — 빈틈 숫자가 한 대마다 따로 떠 연사 · 관통 때 `MaxActive`(80)를 채웠다 → 대상별 빈틈 숫자 사전(`byWeak`)으로 같은 창(보스 · 적 합산 창) 안에서 합침. 일반 숫자와는 따로, 치명타는 그대로 따로. 「완벽한 빈틈!」이 끼면 머리 글자만 올림.
7. **반짝임 간격** — `fx_sparkle` 을 빈틈마다 0.08초에 하나로(고리 번쩍은 그대로).
8. **패드 「커서 자리」 판정** — 가상 커서가 늘 5칸 앞이라 우체부 「빈틈 지정」 · 연금술사 첫 병 · 유탄 직격점이 거의 안 맞았다 → 스틱 직접 조준 중(보조 조준 아님)이면 「플레이어에서 조준 방향 30칸 반직선이 빈틈 원을 지나는가」도 통과(`WeakSpot.PadRayHits` · `GamePad.AimDir`).
9. **문구** — `weak.rule` 에 투척 직격점 60% · 「완벽!」 · 「정각」 → 「완벽한 빈틈!」, 「커서 쪽」 → 「조준한 쪽(커서 · 오른쪽 스틱)」(4개 언어). 도감 보스 탭 카드 높이 400(본문 4~5문단이 다음 카드 위로 넘쳤음) · 본문 줄임표는 모든 카드에.

**기억하는 보스**
10. 기억할 출처가 없을 때(피해가 모두 「기타」) 체력 값이 발동 없이 사라졌다 → `pending` 을 그대로 두고 출처가 생기면 발동.
11. 거울의 군주 되쏘기는 2-4 대로 **막힌 평타 탄만**(`BossMemory.FromBullet` — `Bullet.Hit` 이 보스 `TakeDamage` 앞뒤로 켜고 끔, `Incoming` 이 읽자마자 끔).
12. 2-5 ① · 2-3 의 몸 흰빛 — 발동 때 보스 몸 0.6초 흰빛, 깨진 뒤 휘청 1.5초 동안 0.25초 간격 깜빡임(`bosss.MemoryWhite` · `SpriteOutline` 의 `_Flash` 공유 재질 `Juice.SetFlash`, 설정 「번쩍임 효과」가 꺼져 있으면 이펙트만). 피격 빨강(`spriteRenderer.color`)과 따로 돈다.
13. 개발자 큰 알림 영어 제목 `Patch Notes: "{0}" nerfed` (소문자 일반명사가 들어가도 어색하지 않게).

**트레일러**
14. `SpawnBoss` 의 체력은 `bosss.Start` 가 다시 가득 채운다 → `MemoryCut` 은 Start 뒤에 62% 를 넣고 날개 단계(66%) 전환이 끝날 때까지 녹화 · 사격 없이 기다린 뒤 50.5% 로. `SpawnBoss` 자체는 그대로(다른 장면이 75~80% 로 시작하면 리치 왕 75% 기억이 장면 중에 터질 수 있음). `WeakCut` 의 리치 왕은 지금처럼 가득에서 시작.
