## 1. 공통 규칙 (모든 항목에 적용)

1. **겉모습 불변이 기본**. 「높음」(기본) 에서는 보이는 것 · 타이밍 · 판정 · 피해가 한 픽셀도 달라지지 않는다. 꾸밈을 줄이는 것은 오직 「그래픽 품질 = 낮음」(항목 60) 에서만.
2. **풀 반환 체크리스트**: 풀에서 꺼낼 때 상태를 하나라도 빠뜨리면 이전 것의 효과가 남는다. 각 풀 항목에 「되돌릴 필드 목록」을 적었다. 반환은 `SetActive(false)` + `Stack.Push`, 꺼낼 때 `while (pool.Count > 0 && x == null) x = pool.Pop();` 로 씬 전환 뒤 죽은 참조를 건너뜀 (FadeSprite.Spawn:601~603 과 동일).
3. **공용 버퍼 재진입 규칙**: 공용 `List<Collider2D>` 를 돌며 피해를 주면 피해 콜백(처치 → 폭발 → 또 질의)이 같은 버퍼를 덮어쓴다. **피해를 주는 루프는 반드시 복사본(두 번째 공용 List 로 `AddRange`) 을 돈다** — SpecialAbilities.Passives.cs:36~38 `orbHitsCopy` 방식.
4. **비교 후 쓰기**: `RectTransform` · `Transform` · `Graphic.color` · `TMP_Text.text` 는 값이 같아도 쓰면(Transform · RectTransform) 캔버스가 더럽혀지거나(1.1.9 AbilityHUD.cs:158 관찰) TMP 메시가 재생성된다(text). 반드시 `if (x != want) x = want;`.
5. **화면 밖 생략**: 적 · 탄의 `SpriteRenderer.isVisible` 이 false 면 꾸밈(잔상 · 불꽃 · 핏방울)을 만들지 않는다. 보이지 않으니 겉모습 동일. 판정 · 피해는 그대로.
6. **에디터 전용 코드 금지**(AGENT.md 규칙 2). 에디터 검증은 `Assets/Editor/` 에만.
7. **측정은 가볍게**(규칙 5): 캡처 · 배치 테스트 대신 설정 「프레임 표시」 + Unity Profiler(CPU 모듈 GC Alloc 열 · Rendering 모듈 Batches · Memory 모듈 Object Count) 로 전 · 후 비교. 각 항목의 「확인」 은 그 기준으로 적었다.

## 3. 확인 방법 (전체 · 가볍게)

1. **기준선 기록**: 1.2.3 빌드에서 설정 「프레임 표시」 켜고 (a) 2장 묘역 뭉침 (b) 거너 연사 + 멀티샷 (c) 무한 모드 15분 개발자전 (d) 리치 왕 결계 — 네 장면의 FPS 최소값을 적어 둔다.
2. **묶음마다**: 같은 네 장면에서 FPS 최소값 + Unity Profiler(에디터 플레이 · Deep Profile 끔) CPU 모듈의 `GC Alloc` 열이 전투 중 0 에 가까운지, Rendering 모듈 `Batches` · `SetPass calls`, Memory 모듈 `Mesh · Material · Texture2D · GameObject` 수가 판 중에 늘지 않는지.
3. **겉모습 비교**: 각 항목의 「확인」 에 적은 장면을 1.2.3 창과 나란히 띄워 눈으로 비교(캡처 · 영상 녹화는 하지 않음 — 규칙 5).
4. **누수 재검**: 무한 모드 20분 뒤 일시정지 상태에서 FPS 가 판 시작 때와 같은지(1.2.0 증상의 직접 검사).
5. **빌드 전**: AGENT.md 규칙 2 명령으로 에디터 전용 코드 검사 + 항목 7 의 복제 금지 검사.
