# 편의성 · 사용자 경험(UX) 개선 기획 2차 (2026-10-16 · 검토판)

1차(`2026-10-16-편의성-사용자경험-개선.md`, 7개 항목 · **커밋 9e7f0f5 로 구현 완료**)와 겹치지 않고, 지난 점검(첫구매자 81건 · 시각 버그 점검)에서 이미 고친 것을 뺀 뒤, 1차에서 덜 본 곳(메뉴 → 판 시작 동선, 로딩, 이야기, 결과 · 기록, 저장, 접근성, 화면 · 모니터, 보스 정보, 일시정지 중 정보 열람, 도감)을 코드로 훑었다.
기준은 **품질 · 사용자 경험 효과**다. 작업량 제한은 두지 않았고, 효과가 확실하면 큰 것도 넣었다. 코드는 고치지 않았다. 모든 근거 줄 번호는 **1차가 들어간 지금 작업 트리(9e7f0f5)** 기준이다.

**3차**(`2026-10-16-편의성-흥행작-참고-3차.md`)는 2차 뒤에 구현되며 2차가 만드는 장치 위에 얹는다 — 설정 탭 6개(접근성 · 「표시」) · 기록 창 · `BuildView` 섹션 API · 일시정지 중 툴팁 `PauseInspect`. 3차와 맞춘 지점은 항목 4 · 10 · 11 · 15 와 「검토 기록 — 3차 연동」에 적었다.

항목마다 「밸런스 · 방향 영향」 줄을 넣었다. 난이도 곡선 · 포인트 경제 · 직접 조작의 손맛을 건드리는 것은 옵션(기본 꺼짐 · 접근성 탭) · 첫 번째는 그대로 · 수집률 제외 같은 장치로 막았다. 맨 끝 「검토 기록」에 이 판에서 무엇을 왜 바꿨는지 적었다.

## 번역 방식 (모든 항목 공통)

- 1차와 같다: 한국어 문장이 열쇠, `Loc.T()` · `UIKit.Text` · `UIKit.MakeButton` 이 자동 번역. 키 표시는 `{ULT}` `{INTERACT}` `{ATTACK}` `{RELOAD}` `{UPGRADE}` 처럼 쓰면 `KeyBindings.Apply` (`KeyBindings.cs:165-186`) 가 바꾼 키 · 패드 버튼으로 바꾼다.
- 1차가 `Assets/Scripts/LocTable.Ux.cs` 를 만들었으므로(`AddUx` · `C(key, ko, en, ja, zh)` · 중복 키 건너뜀), 2차 문구는 **새 파일 `Assets/Scripts/LocTable.Ux2.cs`** 에 같은 꼴(`AddUx2`)로 넣는다. 1차 파일은 건드리지 않는다.
- `{0}` 자리표시가 있는 문장은 `Loc.T(key).Replace("{0}", …)` (`LeaderboardUI` · `ResultScreen` 과 같은 방식).
- **문구 규칙은 `2026-10-16-문구-다듬기-지침.md` 를 따른다**: 설명 · 툴팁 · 안내는 완결 문장 + 마침표(ko 「~합니다.」 · en 문장 · ja です/ます + 「。」 · zh 「。」), 이름 · 버튼 · 탭 · 라벨 · 키 안내는 짧게(마침표 없음 · en Title Case). 가운뎃점은 ko/zh 「 · 」, ja 「・」. 영웅은 「영웅/hero/英雄/英雄」.
- **이미 있는 키를 쓸 것**: 「영혼 각인」 = `brand.title` (`LocTable.SoulBrand.cs:14`), 「새 기록!」 = `weight.newrecord` (`LocTable.Weight.cs:15`), 「유물」 (`LocTable.Relics.cs:13`), 「불러오는 중…」 (`LocTable.cs:1013`), 「레벨업 카드」 「특수 능력」 「무기 진화」 「스킬 진화」 「영혼 트리」 「능력치」 「기본 무기」 「닫기」 「확인」 「취소」 「보통」 「색각 이상 모드」 「도움말」 「클리어!」 「{0}장」. 아래 표에는 **새 키만** 적었다.
- 체험판: `Demo.On` 분기가 필요한 곳만 따로 적음. 나머지는 체험판 빌드(`SOULSAVER_DEMO`)에 그대로 들어간다. 체험판 영웅은 **거너 · 검사 둘**(`Demo.cs:28`).
- 저장 형식: 모든 항목이 `Prefs` 키를 **더하기만** 하고(`hero.guide.*` · `boss.intro.seen.*` · `ending.seen.*` · `best.*` · `settings.*` · `deck.applied`), `RunSave.Data` 는 바꾸지 않는다(버전 그대로 · 옛 저장 호환).

## 1. 씬 전환 공용 로딩 화면 (멈춘 채 기다리던 1~3초를 보이게)

**문제**
- 씬 전환 **21곳**이 모두 동기 `SceneManager.LoadScene` 이다 (`MenuManager.cs:20,29,53` · `RunSave.cs:282` · `ESCmenu.cs:178,192,201` · `PlayerController.cs:1360` · `ResultScreen.cs:194,204,212` · `RunStats.cs:581` · `GameOverManager.cs:22,27`(씬 버튼 — `ResultScreen.BuildRetry` 가 숨기지만 코드는 남음) · `StoryDirector.cs:394` · `TutorialRun.cs:71,141,146,466` · `DailyChallenge.cs:86` · `Demo.cs:75`). `GameScene.unity` 는 33만 줄짜리 큰 씬이라 「게임 시작」을 누르면 **메뉴가 그대로 굳은 채** 로딩이 끝날 때까지 아무 반응이 없다. 버튼 눌림 색도 되돌아오지 않고, 음악도 끊긴다. 처음 사는 사람은 「멈췄나?」 하고 다시 누른다.
- 게임 안에는 장 전환용 검은 막(`StageManager.cs:36 fade`, `900-907`)이 있지만 씬 사이에는 아무것도 없다. 「불러오는 중…」 문구는 순위표에만 있다 (`LocTable.cs:1013`).

**해결**
1. 새 정적 클래스 `SceneFlow` (`Assets/Scripts/SceneFlow.cs`), DontDestroyOnLoad 캔버스(ScreenSpaceOverlay · **sortingOrder 32000** — 이야기 연출 캔버스 31000 · 툴팁 1000 보다 위 · `UiScaler.Fit`):
   ```csharp
   public static void Go(string scene)           // 모든 LoadScene 을 이것으로
   {
       if (GameInput.Auto || Application.isBatchMode || GameInput.TrailerRunning) { SceneManager.LoadScene(scene); return; }   // 테스트 · 트레일러는 즉시
       if (loading) return;                                                        // 두 번 누름 · 겹친 호출 무시
       Ensure().StartCoroutine(Run(scene));
   }
   static IEnumerator Run(string scene)
   {
       loading = true;
       Time.timeScale = 0f;                        // ★ 떠나는 씬을 얼림 (일시정지 · 엔딩에서 왔어도 막이 내리는 동안 게임이 풀리지 않게)
       Application.backgroundLoadingPriority = ThreadPriority.High;
       yield return Fade(0f, 1f, 0.25f);           // 검은 막 (unscaled)
       AsyncOperation op = SceneManager.LoadSceneAsync(scene);
       if (op == null) { Time.timeScale = 1f; yield return Fade(1f, 0f, 0.2f); loading = false; Debug.LogWarning("[SceneFlow] 씬 없음: " + scene); yield break; }
       op.allowSceneActivation = false;
       float t0 = Time.unscaledTime;
       while (op.progress < 0.9f) { if (Time.unscaledTime - t0 > 0.4f) ShowLoading(scene); yield return null; }   // 0.4초 넘게 걸릴 때만 글자 (짧으면 검은 막만)
       Time.timeScale = 1f;                        // 새 씬은 늘 1 로 시작 (지금 호출처들이 각자 1f 로 두던 것을 한곳에)
       op.allowSceneActivation = true;
       yield return null;                          // 새 씬 Awake · sceneLoaded 핸들러(MenuExtras.Install 등) 끝나기
       HideLoading();
       Application.backgroundLoadingPriority = ThreadPriority.BelowNormal;
       yield return Fade(1f, 0f, 0.3f);
       loading = false;
   }
   ```
   - **timeScale 을 처음에 1 이 아니라 0 으로 두는 까닭**: 비동기 로딩 동안 떠나는 씬의 `Update` 가 계속 돈다. 일시정지에서 「메인 메뉴로」 · 「다시 시작」, 엔딩 뒤 결과 화면으로 갈 때 1 로 풀면 막이 내리는 0.25초 + 로딩 시간만큼 적이 움직이고 플레이어가 맞는다(지금 동기 로드는 그 틈이 없다). 0 으로 얼리면 `Hints` · 자동 저장 · `PauseFromOutside` · 커서 가두기가 모두 「멈춤」으로 보고 가만히 있는다(`RunSave.cs:434`, `ESCmenu.cs:69`, `CursorSkin.cs:67`). 음악은 timeScale 과 무관하게 계속 난다.
   - 로딩 글자 배치(1920×1080 기준, 가운데): 「불러오는 중」 36pt Gold + 점 세 개가 0.4초마다 하나씩 늘어나는 애니메이션(`…` 글자를 `maxVisibleCharacters` 로), 그 아래 60px에 팁 한 줄 24pt Parch 폭 1200(자동 크기 최소 16). 팁은 `CodexUI.Hints` 12줄(`CodexUI.cs:36-50`, `internal` 로 열기 — 키형 `codex.tab.*` 도 `Loc.T` 가 번역)을 재사용하고 아래 새 팁 4줄을 더한 16개 중 무작위 하나. 왼쪽 아래(40, 40)에 영웅 초상 `CharacterUI.Portrait(CharacterData.Selected)` 120px — GameScene 으로 갈 때만(이어하기 · 일일 도전은 `Override` 가 `Go` 전에 잡혀 있어 그 영웅이 나옴 — `RunSave.cs:278`, `DailyChallenge.cs:84`).
   - 새 그림 없음. 검은 막은 `Image` 단색.
2. 호출처 21곳을 `SceneFlow.Go(...)` 로 바꾼다. 호출처가 `LoadScene` 바로 앞 · 뒤에서 하던 `Time.timeScale = 1f` (`ESCmenu.cs:179,190,199`, `ResultScreen.cs:193,203,211`, `PlayerController.cs:1359`, `StoryDirector.cs:389`, `TutorialRun.cs:140,145,465`, `Demo.cs:74`, `DailyChallenge.cs:85`) 는 **지운다** — `Go` 가 얼리고 되돌리므로 남겨 두면 막이 내리는 동안 게임이 풀린다. `ESCmenu.GoMainMenu` 의 `LoadScene` **뒤** 줄(`ESCmenu.cs:179`)도 같이 지움.
3. `PlayerController.cs:1360` 쓰러짐 연출 끝: 1.1초 슬로모션 뒤 `SceneFlow.Go("GameOver")` — 검은 페이드가 쓰러짐 연출의 마지막 0.25초와 자연히 이어짐(`Time.timeScale = 1f` 줄은 `Go` 가 대신).
4. 호출처가 `LoadScene` 앞에서 하던 일(`RunSave.Save()` · `RunSave.Delete()` · `RunStats.GaveUp = true` · `RunStats.MarkCleared()` 등)은 그대로 `Go` 앞에 둔다. `Go` 뒤에는 아무 줄도 두지 않는다(지금도 없음).

**예외**
- 보스 중 · 레벨업 창 · 일시정지에서 메인 메뉴로: `Go` 가 0 으로 얼리고 로딩 코루틴은 unscaled 라 멈춘 화면에서도 돈다. 이야기 연출 중에는 씬 전환 호출이 없다(ESC 막힘).
- 이어하기: `RunSave.Continue` → `Go("GameScene")`, `Pending` 은 정적이라 비동기 로딩에도 그대로. `Restore` 는 새 씬 `Opening` 에서 돈다.
- 튜토리얼: `TutorialRun.Begin` 도 `Go`. 중간 「그만두기」(`466`) 도 같음. `TutorialRun.Boot` 의 sceneLoaded 되돌림(`TutorialRun.cs:78-85`)은 그대로 동작.
- 결과 화면 1초 보호(`readyAt`)는 그대로. 로딩 중 R 연타는 `loading` 으로 무시. `GameOverManager.cs:22,27` 도 바꿔 둠(씬 버튼은 숨겨져 있지만 코드는 남음).
- 게임패드: 막이 내리는 동안 timeScale 0 이라 `GamePad.Combat` 이 false → 가상 커서 그림이 0.25초 보일 수 있음(검은 막 위라 눈에 띄지 않음 · 허용). 가상 커서는 `GamePad.SceneChanged` 가 씬 이름으로 전투/메뉴를 다시 판단하므로 그대로.
- GameSettings: 새 설정 없음. 키 바꾸기 무관. 체험판: 포함(`Demo.ShowEnd` 의 「메인 메뉴로」도 `Go`).
- 메모리: 비동기 로딩 중 두 씬이 잠깐 함께 있는 것은 동기 로드와 같다.

**밸런스 · 방향 영향**: 없음 (연출만 · 게임 시간은 흐르지 않음).

## 2. 메인 메뉴에 지금 영웅 보이기 · 캐릭터 창 「선택하고 시작」 (판 시작까지 5클릭 → 2클릭)

**문제**
- 메인 메뉴는 **지금 고른 영웅을 어디에도 보여 주지 않는다**. `MenuExtras.InstallMainMenu` (`104-188`)에 `CharacterData.Selected` 를 읽는 곳이 없고, 왼쪽 큰 그림은 씬에 박힌 고정 `Image` (`MainMenu.unity:985-1024` — 가운데 기준 (-600, -170) · 460×460 · raycastTarget 0, 즉 x -830 ~ -370 · y -400 ~ 60)다. 어제 유령으로 하다 끝낸 사람이 오늘 「게임 시작」을 누르면 무슨 영웅인지 판에 들어가서야 안다. 난이도는 버튼 색으로 보이지만 영웅은 캐릭터 창을 열어야 「선택됨」 글자로만 확인된다.
- 영웅을 바꿔 시작하는 동선: 캐릭터 → 카드 → 「선택」(상세가 닫히고 목록만 다시 그림, `CharacterUI.cs:249-255`) → 「닫기」 → 게임 시작 = **5번**. 결과 화면 「캐릭터 바꿔 다시」(`ResultScreen.cs:199-205` → `MenuExtras.cs:187`)로 왔을 때도 같다.

**해결**
1. `MenuExtras.InstallMainMenu` — 왼쪽 고정 그림 자리에 **영웅 패널** `HeroPanel` (가운데 기준 (-610, -120) · 440×560 → x -830 ~ -390 · y -400 ~ 160, 뒤판 `Image` (0.08, 0.06, 0.11, 0.6) 모서리 `ButtonSprite` 슬라이스). 오른쪽 끝 -390 은 난이도 줄 「쉬움」 버튼 왼끝(-300 − 92 = -392, y 79 ~ 137)과 2px 떨어져 겹치지 않고, 아이콘 칸 왼끝(-282 − 88 = -370)보다 왼쪽이다.
   - 맨 위 (0, 262 · 400×26) 18pt Dim 「지금 영웅」 라벨. 초상 `CharacterUI.Portrait(CharacterData.Selected)` 320×320 (패널 안 (0, 90), preserveAspect, 거너는 `CharacterUI.cs:118-126` 과 같은 권총 덧그림 (80, -30) 90×45), 그 아래 이름 40pt Gold (0, -110 · 400×50) · 칭호 22pt Dim (0, -148 · 400×30) · 숙련 `Mastery.Label` + `SoulWeight.CardTag` 18pt (0, -178 · 400×26, `CharacterUI.cs:134-140` 과 같은 글 · 색).

## 3. 영웅 첫 판 안내 카드 (평타 · 필살기 · 머리 위 막대를 싸우기 전에 한 번)

**문제**
- 새 영웅을 처음 고르면 바로 판이 시작된다. 이야기 연출(`StoryDirector.RunIntro`)은 서사만 말하고 조작은 말하지 않는다. 영웅마다 평타 방식(활 당기기 · 불안정도 · 세 획 삼각형 · 정각 톱니 · 편지 받는 이 · 냉기 쌓기, `CharacterData.cs:16-17 weapon · attack · skill · skillDesc`)과 필살기가 전혀 다른데, 그 설명은 **캐릭터 상세 창에만** 있고 판 안에서는 볼 수 없다. 머리 위 막대 이름표(「숨」 「불안정」 「눈금」 「다음 획」 「배달」 「표식」 「영혼」, `CharacterKit.Rules.cs:92-144`)는 뜻을 짚어 주지 않는다.
- 도움말(`Hints`)에 영웅별 키는 없다(`Hints.Keys` 17개 중 영웅 전용 없음, `RunStats.cs:492-494`). 첫구매자 점검에서 「새 영웅 전용 도움말도 없습니다」(1.0.4 에서는 막대 이름표만 추가).

**해결**
1. 새 정적 클래스 `HeroGuide` (`Assets/Scripts/HeroGuide.cs`), `Prefs "hero.guide.<id>"`.
   - **언제**: `StageManager.Opening` (`StageManager.cs:153-201`) 에서 `yield return StoryDirector.Intro(endless);` (`187`) 바로 뒤, `PickEndlessSpecials` (`189`) · `SoulBrand.RunStart` (`190`) 전에 `yield return HeroGuide.Show(this);`. 조건: `RunSave.Pending == null && !GameInput.Auto && !Application.isBatchMode && !GameInput.TrailerRunning && Prefs.GetInt(key) == 0` (튜토리얼은 `166-173` 에서 먼저 `yield break` 하므로 닿지 않음 · 이어하기도 `175-184` 에서 끝남). 시작 카드 창(`LvshopPanel`)은 `RunIntro` 가 되살려 놓은 상태(`StoryDirector.cs:351`)이므로 보여 주는 동안 `SetActive(false)` 하고 닫을 때 되돌림. 시간은 `float before = Time.timeScale; Time.timeScale = 0f;` → 닫을 때 `before` 로(첫 카드 창이 열려 있으면 0 이 맞으므로 1 로 고정하지 않음).
   - **창**: `UIKit.Modal(UIKit.HudCanvas().transform, "HeroGuide", 1180×680)` (`Demo.ShowEnd` 가 쓰는 방식, `Demo.cs:55`), `SoulTreeUI.OnTop(blocker, 620)` (레벨업 창 · 알림판보다 위).
     - 왼쪽: 초상 300px (x -380, y 60) · 이름 40pt Gold (y -120) · 칭호 22pt Dim.
     - 오른쪽(x 120, 폭 760) 세 칸, 칸마다 제목 26pt Gold + 본문 22pt Parch(자동 크기 최소 16, 줄바꿈):
       1. 「기본 무기」 — `Loc.T(d.weapon) + " — " + Loc.T(d.attack)` (y 230, 높이 130)
       2. 「{ULT}」 제목 — `Loc.T(d.skill) + " — " + Loc.T(d.skillDesc)` (y 80, 높이 130) — `UIKit.Text(…, "{ULT}", …)` 가 `CharacterUI.cs:244` 처럼 바꾼 키 · 패드 LT 로 바뀜
       3. 「머리 위 막대」 — 아래 표의 영웅별 한 줄 (y -70, 높이 90). 막대가 없는 영웅(거너 · 검사 · 도적)은 이 칸을 숨기고 2번 칸을 아래로 늘림.
     - 아래 가운데 「시작!」 300×72 (y -280) · 그 아래 18pt Dim 「일시정지 메뉴의 「영웅 안내」에서 언제든 다시 볼 수 있습니다.」
     - 소리: 열릴 때 `Hostile.Play("chime", 0.5f)`.
   - 닫으면 `Prefs.SetInt(key, 1); Prefs.Save()`.
2. **다시 보기**: 항목 4 의 요약 패널 발 버튼 「영웅 안내」 → `HeroGuide.Open(root, false)` (일시정지 상태라 timeScale 건드리지 않음 · 닫아도 Prefs 안 씀). 설정 「도움말 다시 보기」(`MenuExtras.cs:891-897` → `Hints.ResetAll`, `RunStats.cs:496-500`)가 `hero.guide.<id>` 도 함께 지움 — `ResetAll` 은 `"hint." + key` 만 지우므로 `CharacterData.All` 을 돌며 `Prefs.DeleteKey("hero.guide." + i)` 하는 줄을 더함.
3. 캐릭터 상세 창(`CharacterUI.ShowDetail`)에도 같은 「머리 위 막대」 한 줄을 넣는다. **배치를 다시 재면 지금 간격으로는 안 들어간다**: 스탯 7줄(y 200 부터 46 간격, `Stat`/`StatText`) 뒤 `Info` 두 줄(78 간격)이 끝나는 자리가 y ≈ -288 이고 선택 버튼 위끝이 -295 라, 새 줄(높이 70)을 더하면 버튼을 덮는다. 그래서 함께 바꾼다: `Stat`/`StatText` 간격 46 → **42**(7줄 294), `Info` 간격 78 → **72**, 세 번째 `Info` 는 한 줄짜리 상자 680×**44**(자동 크기 최소 14) → 마지막 글 상자 아래끝 ≈ -298, 버튼은 항목 2 처럼 y -330 → **-345**(위끝 -310) → 12px 여유. 「높을수록 빨리 참」 보조 글(y-20)과 다음 줄 막대(y-42 ±9) 사이 4px — 겹치지 않음. 막대 없는 영웅은 줄을 생략.

**예외**
- 이어하기: 안 띄움(이미 하던 판). 튜토리얼: 안 띄움(자기 안내 · `Opening` 이 먼저 끝남). 일일 도전: 고정 영웅이 처음이면 띄움(싸우기 전이 맞음). 무한 모드: 띄움(`PickEndlessSpecials` 전).

- 키 바꾸기: `{ULT}` 자동. GameSettings: 「도움말 안내」가 꺼져 있어도 **띄운다**(도움말이 아니라 영웅 설명 · 영웅마다 한 번뿐).
- 스킨: 초상이 낀 스킨을 따름(`Portrait`).
- 보스 등장 연출 · 레벨업 창과 겹칠 일 없음(판 시작 직후 한 번).

**밸런스 · 방향 영향**: 없음 (정보만 · 영웅마다 한 번 · 시간 멈춤).

## 4. 「빌드 자세히 보기」 창 (일시정지 · 결과 화면 — 지금 가진 카드 · 능력 · 유물의 설명을 한눈에)

**문제**
- 일시정지 오른쪽 요약(`RunStats.ShowSummary`, 440×560)은 **이름만** 쉼표로 이어 쓰고(`Summary`, `RunStats.cs:244-245` 「특수 능력」 · 「레벨업 카드」), 넘치면 말줄임(`464-466`). 판 후반엔 카드 15~20장 · 특수 능력 · 스킬 진화가 다 들어가지 못한다. 설명은 아예 없다 — 「처참한 일격이 뭐였지」는 HUD 칸 위에 마우스를 올려(전투 중엔 0.35초 머물러야, `TooltipTrigger.cs:19, 48`) 하나씩 봐야 하고, 레벨업 카드(왼쪽 위 `AbilityHUD` 10칸)는 다 담기지도 않는다. (일시정지 중 HUD 칸 툴팁을 **그 자리에서** 읽게 하는 것은 항목 15 — 이 항목은 「한 화면에 모두」.)
- 결과 화면도 같은 `Summary(false)` 글(`MenuExtras.cs:47`)이라 「이번 판에 뭘 모았나」를 돌아볼 수 없다.

**해결**
1. 새 정적 클래스 `BuildView` (`Assets/Scripts/BuildView.cs`) — `UIKit.Modal(root, "BuildView", 1500×900)`, `WindowFit.Attach`, 안에 `ScrollRect`(뷰포트 1420×700 · y -40) + 세로 레이아웃. `SoulTreeUI.OnTop(blocker, 620)`. 제목 「이번 판 빌드」 44pt Gold(y 400) · 왼쪽 위에 영웅 · 난이도 · 시간 · 레벨 · 처치(`Summary` 첫 두 줄) · 오른쪽 위 「닫기」(690, 400 · 150×58).
   섹션(제목 28pt Gold + 줄들). 줄 하나 = 아이콘 64 + 이름 24pt + 단계 칸(`LevelPips`) + 설명 20pt Parch(폭 1100, 자동 크기 최소 14, 줄바꿈), 높이는 설명 줄 수에 맞춤(`ContentSizeFitter`). 비어 있으면 섹션 제목 옆에 「아직 없음」 Dim.
   **설명 글은 새로 만들지 않고 HUD 툴팁이 쓰는 함수를 그대로 쓴다** (같은 글이 두 자리에서 다르게 보이지 않게):
   - **레벨업 카드**: `LevelShop.ability_level[i] > 0` 인 i — 이름 · 단계는 `AbilityHUD.AbilityName(id)` 꼴(`AbilityHUD.cs:211-217`), 설명은 `LevelShop.GetAbilityTooltip(id)` 를 `LevelShop.HudView = true` 로 감싸서(「지금 값 + 최대」, `AbilityHUD.cs:219-226` 과 같게) — 두 함수를 `internal` 로. 아이콘 `AbilityHUD.GetIcon(id)` (`37-49`, public). 성장 카드(`GrowthName(k)` · `GrowthLevel(k)`) · 초월 카드(`TranscendName(k)` + 단계 — `LevelShop.Transcend.cs` 에 단계 접근자 `TranscendLevel(k)` 하나 추가).
   - **스킬 진화**: `shop.EvoLog` — 이름 `Loc.T(e.name)` · 시각 · 설명 `LevelShop.EvoTooltip(e, CharacterData.Selected)` (`LevelShop.Signature.cs:516`, public).
   - **무기 · 특수 능력 · 유물 · 패시브**: `SpecialAbilities.Hud` 의 `TileTitle(id)` · `TileBody(id)` (`SpecialAbilities.Hud.cs:444-490`, 종류 · 진화 · 상태 · 쿨타임 · 키까지 들어 있음) 를 `internal` 로 열어 `sp.EquippedIds` 순서로 — 유물(`sp.IsRelic(id)`)이면 보라 「유물」 꼬리표(`RunStats.cs:192` 와 같은 규칙).
   - **무기 진화**: `TileBody(EvoRow)` 가 1차 · 2차 이름 + 설명을 이미 묶어 줌(`455-466`) → 그대로 한 줄, 시각은 `sp.EvolutionLog`.
   - **영혼 각인**: `SoulBrand` 의 이번 판 목록(`static run`, `SoulBrand.cs:21`) 을 `internal static IReadOnlyList<SoulBrandDef> Run` 으로 열어 `b.Name` · `b.Desc` · 아이콘 `ChoiceUI.IconPath(b.Icon)` (일시정지 왼쪽 패널 `Hud.Build` 와 같은 자료, `259-269`).
   - **영혼 트리**: 가지별 배운 칸 수(`sp.OwnedPerBranch()`) + 배운 칸 이름(`sp.BuildSoulTree()` 중 `sp.OwnsNode(n.key)`, `SpecialAbilities.Evolution.cs:215, 248`), 가지 색.
   - **능력치**: `StatsHUD.Refresh` (`StatsHUD.cs:206-256`) 가 13줄 값을 바로 글칸에 넣으므로, 값 계산을 `internal string[] ValueTexts()` 로 꺼내 `Refresh` 와 `BuildView` 가 같이 쓴다(두 열).
2. 들어가는 자리
   - 일시정지: 요약 패널(`RunStats.ShowSummary`) 글 상자 아래 여백 `offsetMin.y` 22 → 92 로 늘리고 패널 바닥에 버튼 둘: 「빌드 자세히 보기」(-100, 36 · 210×52) · 「영웅 안내」(115, 36 · 190×52, 항목 3) — 패널 폭 440(±220) 안. 패널 `Image.raycastTarget` 은 **true 로 바꾼다**(항목 15 가 「요약 패널 위에서는 HUD 툴팁을 띄우지 않는다」로 쓰는 판정 · 버튼이 아닌 곳을 눌러도 아무 일 없음). 단축키는 두지 않는다(Tab 은 순위 창 · 도움말 닫기에 이미 쓰임).
   - 결과 화면: 왼쪽 결과 글(x 60 왼쪽 기준, 480×520 → y -260 ~ 260, `MenuExtras.cs:43-51`) 아래 **(60, -300)** 왼쪽 기준 300×60 「빌드 자세히 보기」(위끝 -270 · 아래끝 -330) — 획득 포인트 글(아래에서 90 → 캔버스 -450, 높이 50)과 겹치지 않고, 무한 모드 기록 글(가운데 폭 880 → x 520 ~ 1400 절대 좌표)과도 x 가 다름. 결과 씬에는 `LevelShop` · `SpecialAbilities` · `StatsHUD` 가 없으므로 **게임 씬을 떠나기 전에 스냅샷**을 떠 둔다: `RunStats.Capture()` (0.5초마다, `RunStats.cs:156-214`) 가 섹션별 (아이콘 Sprite · 제목 · 본문) 문자열 목록 `BuildSnapshot` 을 함께 만들고, 정확히 떠난 순간을 잡기 위해 `PlayerController.DeathSequence` 첫 줄(`1341`) · `ESCmenu.GiveUp` · `StoryDirector.RunEnding` 끝에서 `RunStats.Capture()` 를 한 번 더 부른다(이미 public). 아이콘은 Resources 스프라이트라 씬이 바뀌어도 살아 있음.
3. 언어를 바꾸면 `LocRefresh` 로 다시 그림(일시정지 중 설정에서 바꿀 수 있음). 결과 화면 스냅샷은 번역된 글이라 언어를 바꾸면 그대로(결과 화면에는 설정 버튼이 없어 바뀔 일이 없음).
4. **3차 9 연동**: 3차가 이 창에 「준 피해 막대」 · 「받은 피해」 · 「진화 진행」 섹션을 덧붙이므로 섹션은 `BuildView.AddSection(string titleKo, IEnumerable<BuildRow> rows)` 꼴의 **목록 API** 로 만들어 바깥 파일에서 더할 수 있게 한다(`BuildRow { Sprite icon; string title, body; int level, max; Color? tag; }`). `RunStats.DamageDealt` · `DamageTaken` 은 정적이라 결과 씬까지 살아 있으므로(`RunStats.cs:26-27`, GameScene 로드 때만 비움) 스냅샷에 따로 복사하지 않아도 된다.

## 5. 보스 등장 대사 「처음만」 (로그라이크 반복에 맞춘 연출 길이)

**문제**
- 보스 등장 연출(`StoryDirector.RunBossIntro`, `461-515`)은 **판마다** 보스마다 한 번 나온다(`introduced` 는 씬이 바뀌면 비움, `445-451`). 길이: 띠 0.7초 + 이름 0.3초 + 대사 2줄(글자 0.035초×약 20자 + 1.7초 머무름)×2 ≈ **6~7초**, 시간은 멈춤. 한 판에 보스 4명이면 25초, 50판이면 20분이다. 시작 이야기는 이미 「두 번째 판부터 생략」(`278-279`)인데 보스 대사만 매번이다.
- 건너뛰려면 ESC 두 번 또는 오른쪽 아래 「건너뛰기」 버튼 — 매 보스마다 손을 옮겨야 한다.

**해결**
1. `Prefs "boss.intro.seen.<kind>"` — `RunBossIntro` 에서 `yield return Lines(info.lines);` (`498`) 바로 뒤, `skip = false` (`503`) **전에** `if (!skip) Prefs.SetInt(key, 1)` (시작 이야기의 `watched` 규칙과 같게 — 건너뛴 사람은 다음에 다시 본다). 이 기록은 항목 6(도감 「이야기」)도 쓴다.
2. `GameSettings.BossIntroAlways` (키 `settings.bossIntroAlways`, `DefBossIntroAlways = false` = 「처음만」 · `Load()` · `ResetAccess()` 에 함께).
3. `RunBossIntro` 짧은 길: `seen && !GameSettings.BossIntroAlways` 이면 — 띠 0.5초(0.7 → 0.5) + 포효 + 이름표 페이드 0.3 + **0.9초 머무름** + 돌아오기 0.4 ≈ 2.1초, 대사 없음(`voice` 설정 · `Lines` 생략). 카메라 홀드 · timeScale 0 · 포효 소리는 그대로(「보스가 왔다」는 신호는 유지). 안내 글(`skipHint`) · 「건너뛰기」 버튼 숨김(ESC 두 번은 짧은 길에서도 통함 — `skip` 검사 그대로).
4. 설정 **「접근성」 탭**(항목 10)에 `CycleRow("보스 등장 대사", …, names: { "처음만", "항상" })`. (게임 탭은 9줄로 꽉 차 있어 자리가 없다 — 항목 10 의 탭을 먼저 만든다.)
5. 체험판: 1장 보스(리치 왕)만 — 같은 규칙.

**예외**
- 무한 모드: 보스가 돌아가며 나오므로 효과가 가장 큼. 개발자 · 엄마(kind 9 · 10)는 `Bosses` 표(4개)에 없어 이 연출을 안 탐(`455` 범위 검사 · `boss.cs:142` `!developer`) — 그대로.
- 보스 등장 순간 레벨업 대기 배지 · HUD 숨김은 `Playing` 으로 그대로(`LevelShop.cs:228`).
- 게임패드 · 키 바꾸기: 무관. 이어하기: 보스전 중 저장은 장 시작점부터라 보스가 다시 나오며 연출도 다시(짧게).
- 저장 호환: 키만 추가.

**밸런스 · 방향 영향**: **있음(연출 정체성)** → 대응: 보스마다 **첫 번째는 반드시 전체**(설정과 무관) · 끝까지 본 것만 「봤음」 · 설정 「항상」으로 되돌릴 수 있음 · 포효 · 이름표 · 카메라는 그대로. 게임 시간은 멈춰 있어 전투 유불리 없음. 대사 글은 항목 6 의 도감에서 언제든 다시 읽을 수 있다.

## 6. 도감 「이야기」 탭 (본 이야기를 글로 다시 읽기)

**문제**
- 시작 이야기는 영웅마다 다르고(`IntroFor` · `MeadowIntroFor` · `EndlessLines`, `StoryDirector.cs:19-175`) 끝까지 보면 **다시는 안 나온다**(`341-352`). 엔딩(`EndingFor`, `177-252`)은 클리어 때 한 번, 보스 대사(`Bosses`, `436-442`)는 연출 중에만. 다시 읽을 방법이 어디에도 없다(첫구매자 점검 「다시 보기 기능은 없습니다」 — 1.0.4 에서도 안 함). 항목 5 로 보스 대사도 「처음만」이 되면 더 필요하다.
- 도감(`CodexUI`)은 적 · 보스 · 캐릭터 · 무기 … 12탭이지만 이야기 탭이 없다.

**해결**
1. `StoryDirector` 에 읽기 전용 접근자(지금 `static` 표를 그대로 돌려줌): `internal static string[] IntroLinesFor(CharacterId id, bool classic)` (classic 이면 `IntroFor`, 아니면 `MeadowIntroFor`) · `EndlessIntroLines` · `(string name, string title, string[] lines) BossLines(int kind)` · `EndingLinesFor(CharacterId id)`.
2. 「봤음」 기록
   - 시작: 기존 `intro.seen.{e|c|m}.<id>` (끝까지 본 것만 — 그대로, `278`).
   - 보스: 항목 5 의 `boss.intro.seen.<kind>` (항목 5 를 미루더라도 이 기록 줄은 넣는다).
   - 엔딩: `RunEnding` 에서 `lines == true` 일 때(이야기 모드 — 무한 모드 클리어는 대사가 없음, `358`) 들어가며 `ending.seen.<id> = 1` (대사를 건너뛰어도 클리어는 한 것이므로 열어 줌).
3. `CodexUI.Tabs` 끝에 「이야기」 추가(13번째, `TabStory = 12` → 기존 상수 안 바뀜). 탭 폭 `w` 122 → 108, 간격 10 → 8 (양 끝 ±750 ≤ 창 안쪽 ±808). 탭 글자 자동 크기(최소 14)는 이미 있음(`176`). `Hints` 배열에 `codex.tab.story` 추가, `Show` 의 `CardH` 줄을 `tab == 2 || tab == TabStory ? HeroCardH : BaseCardH` 로.

   - 순서: 「시작 이야기」 영웅 9명(보여 줄 것은 `Chapters.IsClassic` 쪽 하나) + 무한 모드 1장(초상 없이 `fx_warn` 아이콘) → 「보스 등장」 4장(보스 스프라이트 `SpriteOf(data.bosses[i])` · 거울의 군주는 `AbyssStage.Frames("mirrorlord")[0]`, `Bosses()` 와 같은 자료) → 「엔딩」 9장. 꼬리표(tag)에 섹션 이름(「시작 이야기」 · 「보스 등장」 · 「엔딩」) + 영웅 칭호 / 보스 이명.

## 7. 저장 안전성 — 선택 직후 바로 저장 · 「저장됨」 표시 · 마지막 저장 시각

**문제**
- 저장 시점은 1분 자동 · 장 입장 · 메인 메뉴로 · 종료 (`RunSave.cs:422-440`). 자동 저장 사이에 **레벨업 카드 3장 · 보스 보상 · 무기 진화 · 영혼 트리 5칸 · 상점 구매**를 하고 튕기면 그 선택이 다 사라진다. 자동 저장은 `Time.timeScale == 0f` 이면 건너뛰므로(`434`) 카드 창을 오래 열어 두는 플레이 습관일수록 더 자주 놓친다.
- 저장이 됐는지 어디에도 표시가 없다. ESC 안내(`ESCmenu.SaveNote`, `147-152`)는 「저장되어 이어할 수 있습니다」라고만 하고 언제 저장했는지는 말하지 않는다. 저장 실패(디스크 꽉 참 · 권한)는 `Prefs.Save` 가 `Debug.LogWarning` 만 하고 삼킨다(`Prefs.cs:168-188`).

**해결**
1. `RunSave.MarkDirty()` — **호출처를 여섯 곳 고르지 않고 `RunSave.Record(entry)` (`131-136`) 안에서 부른다.** 저장에 남는 모든 선택(레벨업 · 시작 카드 `LevelShop.cs:767` · 보물 상자 카드 `LevelShop.Chest.cs:43,71` · 초월 `LevelShop.Transcend.cs:121,158` · 무기 진화 · 각성 `StageManager.cs:404` · 보스 보상 `StageManager.cs:494` · 영혼 트리 `SpecialAbilities.Evolution.cs:730` · 정련 `791` · 상점 `Shop.cs:274` · 상자 「생명」 `ChestRewards.cs:330` · 저주 제단 `Curse.cs:37` · 각인 `SoulBrand.cs:162,170` · `AddBaseAttack`)이 이 한 함수를 지난다. `Replaying` 중엔 `Record` 가 먼저 돌아가므로 이어하기 재적용은 자동으로 빠진다. 기록이 안 남는 선택 세 곳만 따로: 보물 상자를 연 끝(`TreasureChest.OpenChest`, `TreasureChest.cs:89`) · 상점을 닫는 순간(`Shop.StartGameCountdown`, `Shop.cs:332`) · 유물 장착(`SpecialAbilities.EquipRelic`, `SpecialAbilities.Relics.cs:18`).
   `Watcher.Update`: `dirty && Time.timeScale > 0f && !StoryDirector.Playing && !sm.IsMenuOpen && CanSaveNow && Time.unscaledTime >= dirtySince + 0.5f` 이면 `Save()` (창이 닫혀 시간이 다시 흐른 뒤 0.5초 — 연속 선택(레벨업 이어 고르기 `LevelShop.Chain`)을 한 번에 묶음). 1분 자동 저장은 그대로. `Save()` 비용: `FindFirstObjectByType` 다섯 번 + JSON 수십 KB 파일 쓰기(`File.WriteAllText` + `File.Replace`) — 0.5초 묶음이라 체감 없음.
2. `Prefs.Save()` 의 `catch` 에서 `public static string LastError` 를 남기고 성공하면 지움. `RunSave.Save()` 끝에 `LastSavedAt = Time.unscaledTime; Saved?.Invoke();`, `Prefs.LastError != null` 이면 `Notice.Toast(NoticeIcon.Warn, Loc.T("저장하지 못했습니다. 저장 폴더를 확인해 주세요."), 5f)` — 같은 판에서 한 번만.
3. 「저장됨」 표시: HUD 캔버스 **오른쪽 위**, 포인트 배지(`Points`, (-30, -132) · 420×42 → 아래끝 -174)와 영혼 트리 버튼(`SpecialUpgradeButton`, (-30, -222), `StageManager.cs:604` · 위에서 222~266) 사이 빈 48px 에 `Pin((1,1), (-30, -198))` 220×26 18pt Dim 오른쪽 맞춤 「저장됨」. 저장 때 알파 0 → 0.9 (0.15초) → 1.2초 머무름 → 0 (0.5초), unscaled. 아이콘 없음(새 그림 없음). 자동 저장 · 선택 저장 모두 표시. 설정 「도움말 안내」와 무관하게 늘(짧고 작아 방해 없음). (오른쪽 아래는 탄창 패널 `AmmoPanel` (-24, 24) 300×104 · 능력치 패널 `StatsPanel` (-24, 178) 300×222 가 있어 비어 있지 않다.)
4. ESC 안내: `ESCmenu.Confirm` 은 `note` 를 `UIKit.Text` 에 키로 넘겨 번역하므로(`163`) 숫자를 끼운 글은 키와 맞지 않는다 → `Confirm(name, question, note, okLabel, ok, string extra = null)` 에 넷째 글칸을 더해(y -34 · 720×30 · 20pt Dim · `UIKit.Forget`) `extra` 를 그대로 쓴다: `CanSaveNow && LastSavedAt > 0` 이면 `Loc.T("마지막 저장: {0}초 전").Replace("{0}", Mathf.RoundToInt(Time.unscaledTime - LastSavedAt))`. 기존 `SaveNote()` 문구는 그대로. 「메인 메뉴로」 · 「게임 종료」는 어차피 그 자리에서 저장하므로 안내 뜻은 그대로.

**예외**
- 무한 모드 · 일일 도전 · 체험판 · 튜토리얼: `Savable` 이 false 라 `Record` 가 일찍 끝나 `MarkDirty` 가 안 불림, 「저장됨」도 안 뜸.
- 보스전 중: `Save()` 는 지금처럼 장 시작점 기준으로 저장(`212-237`) — 카드 선택 기록은 남음.
- 쓰러지는 중(`IsDying`) · 마지막 보스 처치 뒤(`FinalBossDown`): `CanSaveNow` false → 저장 안 함(지금 규칙).
- 레벨업 창 위에서 ESC → 「메인 메뉴로」: `GoMainMenu` 가 `Save()` 를 직접 부름(그대로).
- 게임패드 · 키 바꾸기 · GameSettings: 무관. 저장 형식: `Data` 변경 없음.

**밸런스 · 방향 영향**: 없음 (저장 빈도만 · 이어하기 규칙 그대로).

## 8. 화면 설정 — 「모니터」 선택 · 「최대 프레임」

**문제**
- 모니터가 둘 이상일 때 게임을 **어느 모니터에 띄울지 고를 수 없다** (`Display.displays` · `MoveMainWindowTo` · `GetDisplayLayout` grep 0건). 전체 화면(`FullScreenWindow`)은 창이 있는 모니터를 덮으므로, 보조 모니터에서 열렸으면 창 모드로 바꿔 끌어다 놓고 다시 전체 화면을 눌러야 한다. 1차 커서 가두기도 「모니터 두 대」를 전제로 했다.
- 수직 동기화를 끄면 `Application.targetFrameRate = -1` (`GameSettings.cs:288`) 로 **프레임 무제한**. 2D 게임이라 수백 fps 가 나오며 노트북은 발열 · 팬 소음, 데스크톱은 코일 노이즈가 난다. 상한 설정이 없다.
- 덤: 「전체 화면」 버튼(`MenuExtras.cs:806-813`)은 `Display.main.systemWidth/Height` — **주 모니터** 해상도다. 보조 모니터(다른 해상도)에서 켜면 그 모니터에 맞지 않는 해상도로 전체 화면이 된다.

**해결**
1. `GameSettings`
   ```csharp
   const string FpsKey = "settings.maxFps", DisplayKey = "settings.display";
   public static readonly int[] FpsCaps = { 60, 120, 144, 240, -1 };
   public static readonly string[] FpsNames = { "60", "120", "144", "240", "무제한" };
   const int DefFps = 4, DefDisplay = 0;           // 기본 무제한(지금과 같음) · 주 모니터
   public static int FpsIndex { get {…} set { …; ApplyVSync(); } }
   static void ApplyVSync() { QualitySettings.vSyncCount = vsync ? 1 : 0; Application.targetFrameRate = vsync ? -1 : FpsCaps[fpsIndex]; }
   public static int DisplayIndex { get { 저장값 } set { …; ApplyDisplay(); } }
   // 지금 창이 실제로 있는 모니터 (끌어다 옮겼을 수도 있어 저장값이 아니라 Screen.mainWindowDisplayInfo 로)
   public static int CurrentDisplayIndex(List<DisplayInfo> list) => list.FindIndex(d => d.Equals(Screen.mainWindowDisplayInfo));
   ```
   `ApplyDisplay()` (Unity 2022.3.28 — `Screen.GetDisplayLayout` · `Screen.MoveMainWindowTo` · `Screen.mainWindowDisplayInfo` 모두 2022.2+ 에 있음):
   ```csharp
   List<DisplayInfo> list = new List<DisplayInfo>(); Screen.GetDisplayLayout(list);
   if (displayIndex >= list.Count) return;
   DisplayInfo d = list[displayIndex];
   bool full = Screen.fullScreenMode != FullScreenMode.Windowed;
   // 전체 화면은 모니터 사이 이동이 들쭉날쭉 → 창 모드로 잠깐 바꾸고 옮긴 뒤 그 모니터 해상도로 다시 전체 화면
   if (full) Screen.SetResolution(Mathf.Min(Screen.width, d.width - 80), Mathf.Min(Screen.height, d.height - 80), FullScreenMode.Windowed);
   Vector2Int at = new Vector2Int((d.width - Screen.width) / 2, (d.height - Screen.height) / 2);
   AsyncOperation op = Screen.MoveMainWindowTo(d, at);
   if (full && op != null) op.completed += _ => Screen.SetResolution(d.width, d.height, FullScreenMode.FullScreenWindow);
   ```
   `Boot()` 에서 `displayIndex > 0` 이고 지금 모니터와 다르면 첫 프레임 뒤 한 번 적용(`MoveMainWindowTo` 는 첫 프레임 전엔 실패).
2. `MenuExtras.BuildDisplay` — 9줄 · 60 간격 · `rowH 54` (`rowH = (tab == 1 || tab == 4) ? 54f : 64f` — 화면 · 접근성 탭만 54, 탭 번호는 항목 10 의 6탭 배치 기준, y = 235, 175, 115, 55, -5, -65, -125, -185, -245):
   화면 모드 · **모니터** · 해상도 · **최대 프레임** · UI 크기 · 안내 메시지 크기 · 수직 동기화 · 화면 흔들림 · 번쩍임 효과.
   - 「모니터」: `CycleRow` 이름은 「모니터 1 (1920×1080)」 식 — `Loc.T("모니터 {0}").Replace("{0}", (i+1)) + " (" + w + "×" + h + ")"` (`DisplayInfo.name` 은 드라이버 이름이라 쓰지 않음). 표시값은 **`CurrentDisplayIndex`**(실제 자리), 누르면 다음 모니터로 `DisplayIndex = …`. **모니터가 하나면(`list.Count <= 1`) 이 줄을 빼고** 나머지 8줄을 같은 60 간격으로 위에서부터 놓는다 — 줄 목록을 `List<System.Action<float>>` 로 만들어 y 를 차례로 배정하면 숨김 · 표시가 한 코드.
   - 「전체 화면」 버튼 · 해상도 「<」「>」 는 `Display.main.systemWidth/Height` 대신 **`Screen.mainWindowDisplayInfo.width/height`** 를 쓴다(보조 모니터 해상도 버그 함께 고침).
   - 「최대 프레임」: 수직 동기화가 켜져 있으면 버튼 글자 뒤에 「(수직 동기화 켜짐)」 Dim 을 붙이고 버튼 색 `Off` (눌리긴 함 — 끄면 바로 반영). 수직 동기화 토글을 바꾸면 이 줄 글자를 다시 쓰도록 두 줄이 같은 `refresh` 를 공유.
   - 해상도 목록(`Resolutions()`, `Screen.resolutions`)은 창이 있는 모니터 기준이라 모니터를 바꾼 뒤 자동으로 그 모니터 것이 됨 — 줄을 다시 그리기 위해 모니터 변경 뒤 `ShowTab(1)`.
3. 「이 탭 기본값으로」(`GameSettings.ResetDisplay`)는 **최대 프레임만** 되돌림(무제한). 모니터는 사용자가 놀라지 않게 **되돌리지 않음**(화면 모드 · 해상도를 안 되돌리는 1차 규칙과 같게) — 툴팁 문구에도 적음.

**예외**
- 게임 중 일시정지 → 설정에서 모니터를 바꾸면 창이 옮겨지며 한 프레임 깜빡임 — 멈춘 상태라 안전. 커서 가두기(1차)는 `Application.isFocused` · `SettingsUI.IsOpen` 을 보므로 옮긴 뒤 자동 복구.
- 모니터가 빠진 뒤 켜면(`displayIndex >= list.Count`) 주 모니터 그대로 두고 설정값은 유지(다음에 꽂으면 다시 적용).
- macOS · Linux: `MoveMainWindowTo` 가 Windows · macOS 지원, 실패하면 `op == null` → 무시. 스팀 덱: 모니터 하나라 줄 숨김(항목 9).
- 게임패드: `CycleRow` 버튼이라 가상 커서. 키 바꾸기: 무관. 체험판: 포함.

**밸런스 · 방향 영향**: 없음.

## 10. 설정 「접근성」 탭 — 공격 고정 · 필살기 누르면 토글 · 대사 속도 (+ 색각 모드 · 보스 등장 대사 이사 · 「표시」 탭 뼈대)

**문제**
- 마우스 플레이어는 **좌클릭을 판 내내 누르고** 있어야 한다(`PlayerController.cs:402, 415 GameInput.FireHeld`, 궁수는 `CharacterKit.cs:419, 475`). 20~40분 판에서 손가락 · 손목 부담이 크고, 쥐는 힘이 약한 사람은 플레이 자체가 어렵다. 게임패드는 오른쪽 스틱을 기울이면 자동 발사된다(`GamePad.cs:31 AimFireOn`, `202 stickFire`) — 키보드 · 마우스에는 같은 선택지가 없다.
- 필살기는 **누르고 있어야** 조준되고 떼면 발동(`PlayerController.cs:425-479`, 영웅 키트 9명 모두 `GameInput.UltDown/UltHeld/UltUp` 를 읽는 홀드형 — `CharacterKit.cs:637-640, 798-820, 1032-1047`, `Cartographer.cs:309-334`, `Clockmaker.cs:237-248`, `Postman.cs:273-324`, `Ghost.cs:358-384`). 길게 누르기가 어려운 사람에게 접근성 벽이다.
- 대사 글자 속도는 0.035초/자 고정(`StoryDirector.cs:16 CharTime`) — 빨리 읽는 사람은 매 줄 클릭해야 하고, 느리게 읽는 사람도 고를 수 없다.
- 설정 「게임」 탭은 1차 뒤 9줄로 꽉 찼다(`MenuExtras.cs:886-916`). 접근성 항목을 더 넣을 자리가 없다.

**해결**
1. **탭 6개(3차와 같은 배치를 2차가 미리 만든다)** — `SettingsUI.TabNames` = { 일반, 화면, 조작, 게임, **접근성**, **표시** }. 탭 버튼 폭 250 → **180**, x = **-475 + 190·i**(−475 … 475, 양 끝 ±565 ≤ 창 안쪽 ±578), 글자 28 → 24pt 자동 크기 최소 16(「Accessibility」 · 「アクセシビリティ」가 들어감). `ShowTab`: `tab == 4 → BuildAccess()` · `tab == 5 → BuildHud()`, `ResetTab`: 4 → `GameSettings.ResetAccess()` · 5 → `GameSettings.ResetHud()`, **`rowH = (tab == 1 || tab == 4) ? 54f : 64f`**(화면 · 접근성만 9줄).
   - 게임 탭에서 **「색각 이상 모드」는 접근성으로, 「피해 숫자」 · 「내 이펙트 불투명도」는 「표시」로 옮긴다** → 게임 탭은 **6줄 · 75 간격 · rowH 64**(y = 200, 125, 50, -25, -100, -175: 도움말 안내(+다시 보기) · 게임 커서 · 커서를 창 안에 가두기 · 레벨업 바로 열기 · 카드 한 번 클릭으로 확정 · 도감 모두 보기). `ResetGameplay` 에서 `ColorBlind` 는 `ResetAccess` 로, `DamageNumbers` · `MyFxAlphaIndex` 는 새 `ResetHud` 로 옮김.
   - 접근성 탭은 **9줄 · 60 간격 · rowH 54**(게임 탭이 쓰던 `y = 235, 175, 115, 55, -5, -65, -125, -185, -245` 배열 재사용): ① 색각 이상 모드 ② **공격 고정** ③ **필살기 누르면 토글** ④ **대사 속도** ⑤ **보스 등장 대사**(항목 5) — ⑥~⑨ 는 비워 둠(3차 6 「움직임 줄이기」 · 7 「빠른 연출」 자리 · 두 줄 예비).
   - 「표시」 탭은 75 간격 · 64 높이(y = 200, 125, 50, -25, -100): ① 피해 숫자 ② 내 이펙트 불투명도 — ③~⑤ 는 비워 둠(3차 2 전투 통계 · 3 획득 범위 표시 · 8 화면 밖 표시 자리). 2차에서는 두 줄만 옮겨 두는 **빈 탭 뼈대**지만, 3차가 그대로 채우므로 설정 창을 두 번 뜯지 않는다.
2. `GameSettings`: `AttackLock`(기본 false) · `UltToggle`(기본 false) · `DialogueSpeed`(0 보통 · 1 빠름 · 2 즉시, 기본 0) · `BossIntroAlways`(항목 5). 넷 모두 `Def*` · `Load()` · `ResetAccess()`. (`GameInput.AutoFire` 는 트레일러 자동 조종 플래그라 「자동」이라는 이름은 쓰지 않는다.)
3. **공격 고정** — 초안의 「자동 발사(적이 화면에 있으면 게임이 쏨)」가 아니라 **누르고 있는 상태를 걸어 두는 것**: 공격 키를 한 번 누르면 손을 떼도 계속 쏘고, 다시 누르면 멈춘다. 쏘기 시작 · 멈춤 · 조준을 모두 사람이 정하고 손만 쉰다(아래 밸런스 줄). `GameInput`:
   ```csharp
   static bool attackLocked;
   public static bool FireHeld => Auto ? AutoFire : KeyBindings.Held(GameAction.Attack) || AttackLockNow;
   public static bool FireKeyHeld => Auto ? AutoFire : KeyBindings.Held(GameAction.Attack);        // 키만 (툴팁 지연 판정이 씀)
   public static bool AttackLockNow => attackLocked && GameSettings.AttackLock && !GamePad.Active && !TutorialRun.Active && Time.timeScale > 0f && !StoryDirector.Playing
                                       && Hostile.Player != null && !Hostile.Player.IsSkillUsing && !Hostile.Player.IsDying
                                       && !(CharacterKit.Instance != null && CharacterKit.Instance.DrawsBow && CharacterKit.Instance.Breathless);   // 궁수: 숨이 찼으면 쉼
   public static void ResetAttackLock() => attackLocked = false;
   // 걸기 · 풀기: 설정이 켜져 있고 패드가 아니며 PointerOverUI 가 아닐 때, 공격 키 FireDown 마다 attackLocked 를 뒤집음 (PlayerController.Update 의 발사 처리 앞에서 한 번)
   ```
   - 풀리는 때: 다시 누름 · 쓰러짐(`DeathSequence`) · 씬 전환 · 이야기 연출 시작 · 설정을 끔. 레벨업 창 · 상점 · 일시정지(`timeScale 0`)에서는 **걸린 채 멈추고** 닫으면 이어서 쏨(걸어 둔 사람의 뜻). `PointerOverUI()` 검사는 호출처에 그대로(HUD 위를 가리키는 동안만 안 쏨). `FireDown` · `FireUp` 은 키만 봄.
   - 궁수(`CharacterKit.UpdateBow`, `414-517`): 이미 있는 `autoRelease` 판정(`439`, 「순식간에 가득 당기는 버프 · 자동 조작은 가득 차면 저절로 쏨」)에 `|| GameInput.AttackLockNow` 를 더하면 가득 당겨진 프레임에 저절로 놓고(`475`), **「완벽!」 판정이 자동으로 빠진다**(`482 perfect = !autoRelease && …` — 보너스 300% 대신 가득 당김 220%). 숨은 그대로 닳고(`441 ConsumeBreath`), 숨이 바닥나면(`Breathless`) 위 `AttackLockNow` 가 false 가 되어 당기기를 멈추고 숨이 30 이상 차면(`Rules.cs:35`) 다시 당긴다 — 사람이 숨을 고르는 리듬. `487` 의 `Breathless && !autoRelease` 절반 규칙은 고정일 때도 적용되게 `(!autoRelease || GameInput.AttackLockNow)` 로(트레일러 자동 조종만 예외).

   ```csharp
   static bool ultLatched;
   public static bool UltDown => Auto ? Time.frameCount == UltDownFrame : GameSettings.UltToggle ? (!ultLatched && KeyBindings.Down(GameAction.Ultimate) && Latch()) : KeyBindings.Down(GameAction.Ultimate);
   ```

**예외**
- 공격 고정: 레벨업 · 상점 · 트리 · 일시정지(timeScale 0) · 이야기 · 보스 등장 · 결계 컷신(`BossUltimate.CutscenePlaying` 은 timeScale 0) → 안 쏨(걸림은 유지). 필살기 조준 중(`IsSkillUsing`) → 안 쏨(지금 키 입력도 막힘, `425`). 탄창이 비면 자동 재장전은 지금 규칙 그대로. 패드가 활성이면 걸리지 않음(스틱 자동 발사가 이미 있고, 스틱 기울임도 `FireDown` 으로 읽혀 토글이 튄다). 튜토리얼 「조준 · 공격」 단계는 `TutorialRun.Active` 면 고정 불가(직접 눌러야 통과). 레벨업 배지(1차 `BadgeClick`) · 상점 제단 옆 클릭은 UI 위라 `PointerOverUI()` 일 때는 토글하지 않음. 쓰러지면 풀림.
- 필살기 토글: 게임패드 LT 도 같은 규칙(`KeyBindings.Down(Ultimate)` 가 LT 를 읽음). 조준 중 메뉴를 열면 키트는 `CancelUltAim` (`627`), 거너는 `CancelSkill` 이 돌아 걸림이 풀림(지금 홀드형도 ESC 에 조준이 취소됨 · 같음). 즉발형 필살기(`IsInstantUlt`, `430-443`) 도 `UltHeld && !UltUp` 를 보므로 같은 규칙.

## 11. 결과 화면 「내 최고 기록」 비교 · 메인 메뉴 「기록」 창 (지난 판 · 영웅별 통계)

**문제**
- 결과 화면은 이번 판 숫자만 보인다(`RunStats.Summary(false)`: 시간 · 레벨 · 처치). **이 영웅 · 이 난이도의 내 최고가 얼마인지**, 이번이 기록인지 알 수 없다. 최고 기록은 무한 모드(`EndlessMode.BestSeconds`) · 일일 도전만 있다(`MenuExtras.cs:73-101`). 이야기 모드 50판을 해도 「전보다 잘했나」를 느낄 장치가 없다 — 로그라이크의 핵심 동기다.
- 판마다 `balance_log.csv` 한 줄(머리줄 `RunStats.cs:381`: date · version · character · difficulty · endless · result · seconds · level · kills · shards · 진화 · 가지 · cards · stage · 피해 · last_hit · chapter_secs · weight · brands · relics · skill_evos, `375-425`)이 **이미 디스크에 쌓이는데** 게임 안에서 볼 수 없다.

**해결**
1. **최고 기록** — `Prefs "best.<char>.<diff>.level|kills|secs|clearsecs"` (이야기 모드 쉬움 · 보통 · 어려움만: `!GameMode.IsEndless && !DailyChallenge.Active && !TutorialRun.Active && !Demo.On`). `secs` = 쓰러진 판의 **최장** 생존 시간, `clearsecs` = 클리어 판의 **최단** 시간, `level` · `kills` 는 결과와 무관하게 최대.   - **순서 주의**: `RunStats.Boot` 의 `sceneLoaded` 핸들러(`46-77`, 기록 쓰기)와 `GameSettings.Boot` 의 핸들러(`309-315` → `MenuExtras.InstallGameOver`, 결과 화면 그리기)는 둘 다 `AfterSceneLoad` 에 등록돼 **어느 쪽이 먼저 도는지 보장되지 않는다**. 그래서 갱신을 `RunStats.CommitBest()` 로 만들어 **두 곳에서 모두 부르되 한 판에 한 번만 실행**(정적 플래그)되게 하고, 비교용 옛값은 `RunStats.PrevBest` (level · kills · secs · clearsecs) 정적 필드에 남긴다. `WriteBalanceLog` 직전과 `InstallGameOver` 첫 줄에서 부른다.
   - 결과 글: `Summary(false)` 는 ESC 요약과 공용이라 건드리지 않고, `InstallGameOver` 에서 두 번째 줄을 바꿔 쓴다 — 「플레이 시간 12:40 <size=80%><color=#A89C86>(최고 15:02)</color></size>   레벨 32 <…(최고 35)>   처치 1,204 <…(최고 1,500)>」. 클리어 판(`RunStats.Cleared`)의 시간 괄호는 「(최단 클리어 15:02)」. 이번이 최고면 괄호 대신 <color=#F5D478>「새 기록!」</color>(`weight.newrecord`) + 결과 화면이 뜬 0.6초 뒤 `chime`(1.3배 높이) 한 번 — 결과 씬은 `SharedFx` 가 없으므로 `CharacterUI.cs:27-33` 처럼 `SpecialFeedback` 하나를 캔버스에 붙여 `Init(UIKit.Font, UIKit.FontMaterial)` 뒤 냄. 셋 다 새 기록이어도 소리는 한 번. 첫 판(최고 없음)은 괄호 생략. 결과 글 폭 480 자동 크기(최소 14)는 그대로.

   - **지난 판** (기본): `balance_log.csv` 와 머리줄이 바뀌어 밀려난 **`balance_log_*.csv` 도 함께** 읽는다(머리줄은 1.1.2 스킬 진화 칸 · 1.2 무게 · 각인 · 유물 칸으로 이미 바뀐 적이 있어(`RunStats.cs:381` 주석, 밀어내기 `383-388`) 오래 한 플레이어 폴더에는 옛 파일이 여럿 있음). 파일마다 **자기 머리줄로 열 번호를 찾아 이름으로** 읽고(없는 열은 빈값 — `sealed` 가 없는 옛 줄도 정상), `date` · `character` · `result` 열이 없는 파일은 건너뜀. 모두 합쳐 날짜순으로 정렬해 마지막 30줄, 최신이 위. 줄 = 날짜(월/일 시:분) · 영웅 초상 48(`character` 열은 `CharacterId` 이름 → `System.Enum.TryParse`) · 영웅 이름 · 난이도(`Difficulty` 이름 → `GameMode.Name`) (+ 무게 `weight`) · 결과 꼬리표(초록 「클리어」 · 회색 「쓰러짐」 · 노랑 「포기」 = clear / death / quit) · 시간 · 레벨 · 처치 · 쓰러진 원인(`AttackLabel.Translate(last_hit)`, `RunStats.SourceName`) 또는 도달 장(`stage`). 줄을 누르면 아래 펼침: 무기 진화 2단계(`evo1` · `evo2` + 시각) · 스킬 진화(`skill_evos` "키@초|…") · 각인 · 유물(saveCode → `ContentRegistry` 이름) · 준/받은 피해 상위 3(`dealt_by` "이름:양|…"). 펼친 줄 오른쪽 끝 160×44 는 비워 둔다(3차 10 「복사」 버튼 자리).

## 12. 보스전 정보 — 체력바 눈금 · 「분노!」 알림 · 보스바 툴팁

**문제**
- 보스는 체력 절반 아래에서 `Enraged` (`boss.cs:52`) 가 되어 소환이 잦아지고(`175-178`) 특수 스킬을 쓰는데(리치 왕 「망자의 의식」 `BossSkills.Reborn.cs:99`, 킹 슬라임 뱉기 `:56`, 거울의 군주 「되비친 기억」 `BossSkills.cs:62`), **화면에는 아무 표시가 없다**. 도감 보스 탭 힌트(「체력이 절반 아래면 특수 스킬」, `CodexUI.cs:39`)에만 적혀 있어, 싸우는 중에 「갑자기 패턴이 바뀐」 느낌만 남는다. 지옥의 군주는 다르게 66% · 33% 단계로 움직이고 33% 에는 이미 배너가 있다(`BossSkills.Reborn.cs:363-370` 「지옥의 군주가 분노한다! 공격이 빨라진다!」).
- 보스 체력바(`bossbar.cs`)에는 눈금이 없고, 마우스를 올려도 설명이 없다(결계 게이지 이름표 · 도움말은 1.0.4 에서 넣음, `bossbar.cs:274-310`).

**해결**
1. `bossbar` — 채움 막대(`bar`)와 같은 부모에 세로 눈금 `Image` 3×(BarY+8) (1, 0.9, 0.7, 0.75): **리치 왕 · 킹 슬라임 · 거울의 군주는 50% 하나, 지옥의 군주(kind 1)는 66% · 33% 둘**(실제 단계 자리 — `HellTurn` 의 `HpFrac <= 0.66 / 0.33`). 자리 x = 막대 왼끝 + `MaxBarX × 비율`. 보스가 그 눈금을 지나면 눈금이 빨강 (1, 0.4, 0.35) 으로 바뀌고 체력바 뒤판 `backColor` 를 (0.35, 0.08, 0.08) 쪽으로 0.3초 Lerp. 아래로 쌓는 복제 줄(`ShowExtraBars`, `187-222`)은 `backBar` 를 통째로 복제하므로 눈금도 같이 복제됨 — 복제 줄의 보스 종류에 맞게 `SetBar` 에서 눈금 수 · 자리를 다시 맞춤. 개발자 · 엄마(`bossKind >= DeveloperKind`)는 눈금 없음.
2. **「분노!」 알림** — `bosss.TakeDamage` 에서 `EnemyHealth -= damage` (`221`) 뒤: `if (!enragedFired && Enraged && EnemyHealth > 0f && !developer && bossKind != 1) { enragedFired = true; Notice.Big(Loc.T("분노!"), Loc.T("{0}의 체력이 절반 아래입니다. 이제 특수 스킬을 씁니다.").Replace("{0}", bossbar.BossName(bossKind)), NoticeIcon.Boss, 2.4f, NoticeLevel.Urgent); Hostile.Play("roar", 0.6f, 1.2f); }` + 보스 이름표 글자 0.4초 붉게(`bossbar` 에 `FlashName()`). **지옥의 군주는 제외**(66% · 33% 자기 배너가 있어 50% 배너까지 겹치면 소음) · 개발자 · 엄마 제외(`Enraged` 를 다른 뜻으로 씀, `BossSkills.Developer.cs:43`). 보스마다 한 번(보스 인스턴스 필드).
3. 보스바 뒤판(`backBar` = 씬 `BossBarBackground`)에 `TooltipTrigger { hud = true }`: 제목 `bossbar.BossName(kind)` · 본문 = 도감 보스 설명 `CodexUI.BossDesc[kind]`(`CodexUI.cs:84-90`, 이미 번역 · `internal` 로 열기 — 3차 1 의 적 설명도 같은 배열을 씀) + 줄바꿈 + 「체력이 절반 아래로 내려가면 특수 스킬을 쓰고, 결계 게이지가 차면 결계를 펼칩니다.」(지옥의 군주는 「체력 66% · 33%에서 단계가 오르고, …」 변형 한 줄). 개발자 · 엄마는 제목만. 뒤판 `Image.raycastTarget` 을 true 로 — `PlayerController.PointerOverUI` 는 `TooltipTrigger.hud` 인 칸을 발사 차단에서 빼므로(`PlayerController.cs:654-658`) 평타가 막히지 않음. 전투 중엔 0.35초 머물러야 뜨는 기존 HUD 규칙, **일시정지 중에는 항목 15 로 바로** 읽힘.

## 13. 확인 창 키보드 조작 — 기본 버튼 선택(Enter · Space 확정) · 방향키 이동

**문제**

2. 호출처: 버튼을 만든 뒤 한 줄 — `MenuManager.OnPressStart` 「새 게임」(`26`) · `SuggestTutorial` 「튜토리얼」(`45`) · `SaveNotice` 「확인」(`255`) · `LanguagePicker` 미리 고른 언어(`1186`) · `ESCmenu.Confirm` 의 `okLabel` 버튼(`164`: 메인 메뉴로 · 다시 시작 · 포기하고 결과 보기) · `TutorialRun.AskQuit` 「메인 메뉴로」(`463`). **「게임 종료」 확인 둘(`MenuManager.OnPressExit` `69`, `ESCmenu.onPressQuit`)은 선택하지 않는다** — Enter 한 번에 게임이 꺼지는 사고를 막기 위해(클릭 또는 ←→ 로 골라 Enter). 레벨업 「이번 레벨업 포기」 · 설정 「이 탭 기본값으로」 · 캐릭터 「구매」 는 두 번 누르기라 제외.
3. **게임패드가 활성이면 선택하지 않는다**(`GamePad.Active`): 패드는 가상 커서 A 가 클릭이고, Submit(A) 이 선택된 버튼까지 누르면 **한 번에 두 번 실행**될 수 있다(「새 게임」 두 번 등). 패드로 바뀌는 순간(`GamePad.SetActive(true)`)에도 `Deselect`.
4. 확인 창 아래 18pt Dim 「[Enter] 확인   [ESC] 취소」 — 패드가 활성이면 숨김(패드는 A · B 가 이미 됨).

**예외**

   ```csharp
   public static System.Func<Vector2, (string title, string body)?> WorldProvider;   // 3차 1 EnemyPeek 가 등록 (적 · 보스 몸 위)
   void Update()
   {
       bool on = ESCmenu.IsOpen && !ESCmenu.ConfirmOpen && !SettingsUI.IsOpen && !CodexUI.IsOpen && !SkillEvoCodexUI.IsOpen;   // IsOpen 둘은 3차 1 이 더함

       Vector2 at = GameInput.PointerPosition;                              // 패드 가상 커서도 같은 자리 (TooltipUI.Follow 와 같은 기준)
       es.RaycastAll(pointer at, hits);                                     // 깊이 순 — ESC 패널이 맨 앞이지만 건너뜀
       foreach (RaycastResult h in hits)
       {
           if (h.gameObject.transform.IsChildOf(escMenu.transform)) continue;        // ESC 패널 · 그 버튼 · 안내 글
           TooltipTrigger t = h.gameObject.GetComponentInParent<TooltipTrigger>();
           if (t != null && t.isActiveAndEnabled) { ShowMine(t.titleProvider?.Invoke() ?? t.title, t.bodyProvider?.Invoke() ?? t.body); return; }
           break;                                                                      // 툴팁 없는 UI(요약 · 각인 패널 바탕, 확인 창)가 가리면 그 아래는 안 봄
       }
       var w = WorldProvider?.Invoke(at);                                   // UI 가 없으면 세상(적) — 3차 1
       if (w.HasValue) { ShowMine(w.Value.title, w.Value.body); return; }
       HideMine();
   }
   ```
   - `ESCmenu` 에 `public static bool ConfirmOpen => confirm != null` 꼴의 접근자 추가. 요약 패널(`RunStats.ShowSummary`, `450`) · 각인 패널(`SoulBrand.Hud.Build`, `256`) 바탕 `raycastTarget` 을 **true** 로(둘은 `SetAsLastSibling` 이라 레이캐스트에서 ESC 패널보다 앞) — 그 위에서는 HUD 툴팁이 뜨지 않음(항목 4 와 같은 변경).
   - `TooltipUI.Show` 는 `Loc.T` 를 한 번 더 거치지만 번역표에 없는 글은 그대로(`Loc.cs:19-31`) · 위치는 `Follow()` 가 포인터 옆에 띄우고 화면 밖이면 뒤집고 안으로 밀어 넣음(`TooltipUI.cs:149-166`) · 패널 캔버스 정렬 1000 이라 ESC 패널 위(`47`) — **그대로 쓰면 된다**(새 창 없음).

**해결 방법이 코드 구조와 맞지 않던 곳**
4. **항목 1 `SceneFlow` — timeScale 을 처음에 1 로 두면 안 된다.** 비동기 로딩 동안 떠나는 씬의 `Update` 가 계속 돌므로 일시정지 → 「메인 메뉴로」 · 「다시 시작」, 엔딩 → 결과 화면에서 막이 내리는 동안 게임이 풀려 적이 움직이고 플레이어가 맞는다. 「얼림(0) → 활성화 직전에 1」로 바꾸고, 호출처의 `Time.timeScale = 1f` 줄을 **지우라**고 명시. 정렬은 1000 → 32000(이야기 캔버스 31000 위). `op == null` · `backgroundLoadingPriority` 처리 추가.
5. **항목 3-3 캐릭터 상세의 「머리 위 막대」 줄** — 초안은 「들어간다」고 했지만 재면 마지막 `Info` 가 y -288 에서 끝나고 버튼 위끝이 -295 라 새 줄(70)이 버튼을 덮는다 → 스탯 간격 46→42 · `Info` 78→72 · 새 줄 44 높이 · 버튼 -330→-345 로 좌표를 다시 잡음(항목 2 의 세 버튼도 같은 y).
