# 빌드 갈래 — 영웅 효과 구현 안내 (2026-10-19)

- 기획서: `docs/review/2026-10-19-빌드-시너지-기획.md` (먼저 3장 자기 영웅 표 · 4장 밸런스 · 6-3 위험을 읽을 것)
- 이 문서는 기획서 6-1 의 **2 · 3단계(영웅별 입문 · 공명 · 극의 · 새 교차 효과)** 를 영웅 담당 아홉 명이 **동시에** 구현하기 위한 안내다.
- 0 · 1단계(틀 · 카드 창 규칙)는 이미 들어가 있다. 규칙은 켜져 있고, 효과 훅이 비어 있어도 판은 정상 진행된다 (입문 카드를 고르면 그 갈래 카드만 나오는 데까지).
- 줄 번호 대신 함수 이름으로 적는다. 파일은 모두 `Assets/Scripts/` 기준.

## 2. 고칠 파일 (영웅별) · 공유 파일 수정 금지

**아래 「고칠 파일」 밖은 고치지 않는다.** 아홉 명이 동시에 일하므로 공용 파일을 고치면 서로의 작업이 깨진다. 공용 쪽에 꼭 필요한 것이 생기면 고치지 말고 보고에 「필요한 공용 변경」으로 적는다 (지휘 쪽이 모아서 한 번에 넣음).

| 영웅 | 고칠 파일 |
|---|---|
| 거너 | `Paths/Paths.Gunner.cs` · `Paths/LocTable.Paths.Gunner.cs` · `SignatureSkills.Gunner.cs` · `SpecialAbilities.GunCards.cs` · `PlayerController.cs` 의 **거너 사격 · 장전 · 탄창 부분만** (`Shoot` 계열 · `UltShots` 를 켜고 끄는 곳) |
| 검사 | `Paths/Paths.Swordsman.cs` · `Paths/LocTable.Paths.Swordsman.cs` · `SignatureSkills.Swordsman.cs` · 새 파일 `CharacterKit.Swordsman.cs` (partial) · `CharacterKit.cs` 의 **검사 전용 줄만** (`Swing` · `SwingCards` 의 검사 분기 · `TakenMul`) |
| 도적 | `Paths/Paths.Rogue.cs` · `Paths/LocTable.Paths.Rogue.cs` · `SignatureSkills.Rogue.cs` · 새 파일 `CharacterKit.Rogue.cs` · `CharacterKit.cs` 의 **도적 전용 줄만** (`BleedDash` · `DashEnd` · 도적 `UpdateUlt` 분기 · `Shuriken` · `ShadowClone`) · `CharacterKit.Forms.cs` 의 `RogueThrow` |
| 궁수 | `Paths/Paths.Archer.cs` · `Paths/LocTable.Paths.Archer.cs` · `SignatureSkills.Archer.cs` · 새 파일 `CharacterKit.Archer.cs` · `CharacterKit.cs` 의 **궁수 전용 줄만** (`UpdateBow` · `ArrowRain` · `UpdateRainAim` · 궁수 `Attack` 분기) |
| 연금술사 | `Paths/Paths.Alchemist.cs` · `Paths/LocTable.Paths.Alchemist.cs` · `SignatureSkills.Alchemist.cs` · 새 파일 `CharacterKit.Alchemist.cs` · `CharacterKit.cs` 의 **연금술사 전용 줄만** (`ThrowReagent` · `Homunculus` · `StickyAcid` · 연금술사 `Attack` 분기) |
| 지도 제작자 | `Paths/Paths.Cartographer.cs` · `Paths/LocTable.Paths.Cartographer.cs` · `CharacterKit.Cartographer.cs` · `SignatureSkills.Cartographer.cs` |
| 시계공 | `Paths/Paths.Clockmaker.cs` · `Paths/LocTable.Paths.Clockmaker.cs` · `CharacterKit.Clockmaker.cs` · `SignatureSkills.Clockmaker.cs` |
| 우체부 | `Paths/Paths.Postman.cs` · `Paths/LocTable.Paths.Postman.cs` · `CharacterKit.Postman.cs` · `SignatureSkills.Postman.cs` |
| 유령 | `Paths/Paths.Ghost.cs` · `Paths/LocTable.Paths.Ghost.cs` · `CharacterKit.Ghost.cs` · `SignatureSkills.Ghost.cs` |

- **아이콘**: 위 파일 말고 `Assets/Resources/Icons/Paths/<IconKey>_*.png` (+ `.meta`) 를 새로 만들 수 있다 (5절).
- **`CharacterKit.cs` 는 검사 · 도적 · 궁수 · 연금술사 넷이 같이 쓰는 파일이다.** 새 코드는 되도록 자기 새 partial 파일(`CharacterKit.<영웅>.cs`)에 두고, `CharacterKit.cs` 안에서는 자기 영웅 분기에 **한두 줄 부르는 줄만** 넣는다. 고치기 직전에 그 부분을 **다시 읽고** 고친다 (다른 담당이 방금 고쳤을 수 있음). 다른 영웅 분기 · 공용 메서드(`Attack` 의 앞부분 · `UpdateUlt` 의 공통 줄 · `Projectile` · `DamageCircle` 등)는 고치지 않는다.
- **고치지 않는 공용 파일 (예)**: `Paths/Paths.cs` · `LevelShop*.cs` · `StageManager.cs` · `RunSave.cs` · `RunLog.cs` · `RunStats.cs` · `AbilityHUD.cs` · `SignatureSkills.cs` · `LocTable.cs` · `LocTable.Paths.cs` · `LocTable.Skills.cs` · `boss.cs` · `EnermyController.cs` · `SpecialAbilities.cs` (거너의 `GunCards` 제외) · `Notice.cs` · 씬 · 프리팹.
- **Unity 를 실행하지 않는다** (배치 컴파일 · 플레이 · 캡처 모두). 컴파일은 지휘 쪽이 모아서 한 번 한다. 그래서 **컴파일되는 C# 를 눈으로 확인**하고 끝낸다: 없는 메서드 · private 접근 · 이름 충돌(같은 partial 클래스에 같은 이름) · 세미콜론 · 괄호.
- 커밋 · push 는 지휘 쪽 지시를 따른다.

## 3. 데이터 (`Paths/Paths.<영웅>.cs` 의 `BuildPaths` · `BuildCrosses` · `Extra`)

기획서 표대로 모두 채워 두었다. 수치 · 문장은 고쳐도 되지만 아래는 지킨다.

| 필드 | 뜻 | 주의 |
|---|---|---|
| `key` | 저장 · 판 기록 · 최근 고른 갈래 열쇠 | **바꾸지 않는다** |
| 갈래 순서 (배열 번호 0 ~ 4) | 입문 카드 번호 = 25 + 갈래 번호 · 이어하기 기록 `c25` 등 | **순서를 바꾸지 않는다** (이어하기가 다른 갈래로 바뀜) |
| `cards` | 갈래 카드 (전용 카드 `P G M K H A B` · 고유 스킬 `S(0~9)` · 새 카드 `X`) | 영웅 카드는 **정확히 한 갈래**에. 바꾸면 에디터 경고(`PathsValidate`)로 확인 |
| `evo` | 완성 = 기존 진화 키 | 재료가 모두 `cards` 안이어야 함 |
| `seed · seedDesc · cost · strong · weak · tagline · res1 · res2 · mastery · name` | 카드 · 알림 · HUD 글 (한국어 = 번역 키) | 고치면 `LocTable.Paths.<영웅>.cs` 키도 같이 |
| `power` | 갈래 효과 피해 배율 (기본 1) | 효과 코드가 **반드시** `Paths.Power(갈래)` 를 곱할 것 — 밸런스 손잡이 |
| `color` | 갈래 색 (입문 고리 · 알림 · 글) | |
| `form` | 형태 공명 짝 (4단계용 · 지금은 쓰지 않음) | |
| `CrossDef` | `Cross(a, b, "진화 키")` = 기존 진화 교차 (효과는 진화 그대로) · `Cross(a, b, key, name, desc)` = 새 교차 | 새 교차의 번호 = `Crosses` 배열 순서 (`OnCross(cross)` · `Paths.CrossOn(cross)`) |

- 연금술사 31번 「서리 장막」: 카드 글 · 단계 · 뽑기 · HUD 는 틀이 맡는다. **효과만** 구현 (`Paths.Level(Paths.ExtraId)` = 0 ~ 3, 외길이면 4).
- 연금술사 표에 「연쇄 폭발 × 조수」 짝이 두 번 있다 (기존 진화 유리 폭풍 + 새 효과 폭탄 조수). 기획서 그대로 둘 다 켜진다.

## 4. 훅 목록 · 호출 시점

모두 `HeroPaths` 의 가상 메서드다. 내 영웅 파일에 빈 `override` 가 이미 있다 — 필요한 것만 채우면 되고, 빈 채로 두어도 된다. **이번 판이 갈래 규칙일 때만 불린다** (옛 저장을 이어한 구판 규칙 판에는 안 불림). 훅 안에서 예외가 나도 게임 흐름은 끊기지 않게 `Paths` 가 잡아 로그만 남긴다 — 그래도 예외를 내지 않게 짠다.

### 4-1. 판 흐름 훅 (카드를 고를 때 · `LevelShop` 이 부름)

| 훅 | 언제 | 할 일 |
|---|---|---|
| `OnSeed(path, replay)` | 입문 카드를 확정한 직후 (갈래 A 또는 B) | 입문 효과를 켬 (보통은 아무것도 안 해도 됨 — 효과 코드가 `Paths.Has(갈래)` 를 물으면 됨). 시작부터 무언가를 **만들어야** 하면(예: 연금술사 조수의 호문쿨루스) 여기서 |
| `OnSingle(path, replay)` | 외길을 고른 직후 (`path` = 갈래 A) | 외길 전용 준비 (대개 비움) |
| `OnResonance(path, tier, replay)` | 갈래 단계 4(tier 1) · 8(tier 2)에 처음 닿음 | 대개 비움 (`Paths.Res(갈래) >= 1` 을 물으면 됨) |
| `OnComplete(path, replay)` | 갈래 카드가 모두 원래 최대 (진화는 `LevelShop` 이 따로 일으킴) | 대개 비움 |
| `OnMastery(path, replay)` | 극의 (외길 + 늘어난 단계까지 모두) | 대개 비움 (`Paths.Mastered(갈래)`) |
| `OnCross(cross, replay)` | 새 교차가 켜짐 (두 갈래 모두 공명 I) | 대개 비움 (`Paths.CrossOn(번호)`) |
| `OnPick(id, replay)` | 레벨업 카드 하나를 고른 뒤마다 (성장 카드 · 비상 보급 제외) | 카드 단계에 따라 캐시를 다시 만들 때 |
| `End()` | 판이 끝나 플레이어가 사라질 때 (`SignatureSkills.OnDestroy`) | 플레이어 값을 바꿔 두었다면 되돌림 |

- `replay == true`: 이어하기로 기록을 다시 적용하는 중. **연출 · 소리 · 알림 · 화면 글 · 오브젝트 생성 금지**, 상태만 맞춘다. 같은 판에서 같은 일로 두 번 불리지 않는다.
- 알림 띠 · 고리 · 소리는 틀이 이미 낸다. 영웅 쪽에서 또 띄우지 않는다.
- 판마다 `HeroPaths` 인스턴스를 새로 만든다 → 필드에 둔 상태는 판이 바뀌면 처음부터. **static 필드는 쓰지 않는다** (판을 넘어 남음).

### 4-2. 전투 훅 (`SignatureSkills` · `CharacterKit` 이 부름)

| 훅 | 부르는 곳 · 때 | 돌려주는 값 |
|---|---|---|
| `Outgoing(target, dmg)` | 적 · 보스가 피해를 받기 직전 (`EnermyController` · `boss` → `SignatureSkills.Outgoing`) — 모든 출처 | 피해 **배율** (곱함, 기본 1) |
| `Hit(target, dmg, killed, proc)` | 적 · 보스가 피해를 받은 뒤 | — · `proc == false` 면 갈래 · 고유 스킬이 준 피해나 지속 피해 → 여기서 다시 효과를 내면 연쇄됨 |
| `Taken(dmg)` | 플레이어가 맞을 때 (`PlayerController.TryHit`, 무적 시간은 이미 시작) | 바꾼 피해 (0 이상) |
| `Hurt(taken)` | 실제로 체력이 깎인 뒤 | — |
| `Attacked(start, dir)` | 평타를 쏨 — **거너 사격 · 도적 표창만** (`SignatureSkills.Attacked` 를 부르는 곳) | — |
| `KitAttack(kit, start, dir, dmg, shots)` | 거너가 아닌 영웅의 평타 (`CharacterKit.Attack`, 조준 · 피해 계산 뒤 · 입문 뒤에만) | `true` = 원래 평타를 쏘지 않음 (평타 모양을 바꾸는 입문). 원래 평타를 쓰고 싶으면 `false`. `kit` 의 private 메서드가 필요하면 자기 `CharacterKit.<영웅>.cs` 에 public 래퍼를 만든다 |
| `Killed(pos)` | 적이 쓰러짐 (모든 처치) | — |
| `Ult()` | 필살기를 씀 (`PlayerController.UltUsed`) | — |
| `MoveMul()` | 이동할 때마다 (`SignatureSkills.MoveMul`) | 이동 속도 배율 |
| `RateMul()` | 거너가 아닌 영웅의 공격 간격 (`CharacterKit.AttackSpeedMul`) | 공격 속도 배율 (거너는 `PlayerController` 사격 간격을 직접) |
| `Tick()` | 매 프레임 (멈춘 동안 · 쓰러지는 중은 안 불림. 입문 전에도 불리므로 `Paths.Has` 로 거를 것) | — |
| `Badge(path)` | HUD 입문 칸 오른쪽 위 글 (매 프레임) | 짧은 글(「45%」 · 「x3」) 또는 `null` (= I · II · 극의 표시) — **매 프레임 새 문자열을 만들지 않게** 값이 바뀔 때만 만들어 둘 것 |

- 훅은 **그 영웅이 고른 판에서만** 불린다 (다른 영웅 판에서는 그 영웅의 `HeroPaths` 가 없음). 그래도 갈래 효과는 늘 `Paths.Has(내 갈래)` 로 거른다.
- 거너 · 검사 · 도적 … 의 **기존 효과 코드 안**(예: `CharacterKit.Ghost.cs` 의 손길, `SignatureSkills.Gunner.cs`)에서도 `Paths.Has(GhostPaths.Frost)` 처럼 물어 분기해도 된다. 그쪽이 더 자연스러운 경우가 많다 (예: 냉기 쌓는 수 ×2).

### 4-3. 묻기 (어디서든)

| 함수 | 뜻 |
|---|---|
| `Paths.Active` | 이번 판이 갈래 규칙 (옛 저장 이어하기면 false) |
| `Paths.Has(갈래)` | 그 갈래에 들어왔나 (입문 효과가 켜짐) |
| `Paths.A` · `Paths.B` · `Paths.Single` | 첫 갈래 · 두 번째 갈래 (-1 = 아직) · 외길 |
| `Paths.Rank(갈래)` · `Paths.Res(갈래)` | 갈래 단계 · 공명 (0 · 1 · 2) — 고를 때만 다시 세어 둔 값이라 매 프레임 물어도 됨 |
| `Paths.Complete(갈래)` · `Paths.Mastered(갈래)` · `Paths.CrossOn(번호)` | 완성 · 극의 · 새 교차 |
| `Paths.Power(갈래)` | 갈래 효과 피해 배율 (`PathDef.power`) |
| `Paths.Level(카드 번호)` | 카드 단계 (31번 새 카드 등) — 기존 카드는 원래 쓰던 단계 값(`L("g.mine")` · `card[n]` · `gunCard[n]`)을 그대로 |
| `Paths.Def(갈래)` | 이번 판 영웅의 `PathDef` |

갈래 번호는 내 영웅 클래스의 상수로: `GunnerPaths.Snipe` · `SwordsmanPaths.Parry` · `GhostPaths.Phase` …

## 5. 도우미 (`Paths.*`)

| 도우미 | 쓰임 |
|---|---|
| `Paths.Atk` | 고유 스킬과 같은 기준 공격력. 갈래 효과 피해 = `Paths.Atk × 비율 × Paths.Power(갈래)` |
| `Paths.Deal(target, dmg, dir, knock, "출처 이름")` | 피해 한 번. 명중 효과 연쇄 방지(`Dealing`) · 판 기록 `dealt_by` 에 출처 이름(예 「저격탄」 · 「포탑」)으로 남음 |
| `Paths.Circle(pos, r, dmg, knock, "출처", each)` | 반지름 안 적 · 보스 모두 (맞힌 수) |
| `Paths.Zone(pos, r, life, tick, onTick, fx, tint, fxSize, ground)` | 장판 (`SigZone`: 끝나면 스스로 사라짐). 웅덩이 · 잉크 · 불 장판은 이것으로. 겹치면 합치거나 개수 상한 |
| `Paths.Invuln(초)` | 플레이어 무적: 지금 끝 시각에 `Mathf.Max` 로만 합침 · **한 번에 최대 1.5초** (`PlayerController.GrantInvincibility`) |
| `Paths.Trim(list, max)` | 개수 상한: 사라진 것을 치우고, `max` 를 넘으면 가장 오래된 것부터 `Destroy` (새것을 넣기 **전에** 부름) |
| `Paths.IsBoss(go)` · `Paths.IsFoe(col)` · `Paths.Nearest(pos, r, n)` | 보스 · 중간 보스 판정 (황금 고블린 제외) · 적 판정 · 가까운 적 |
| `SignatureSkills.Instance.Shot(...)` | 도트 그림을 입힌 투사체 (Bullet 판정 그대로) |
| `Fx.Spawn` · `Fx.Play` · `ShockRing.Spawn` · `Hostile.Play` | 이펙트 · 고리 · 소리 (기존 그대로) |

`SignatureSkills.<영웅>.cs` 안에서는 private 도우미(`Atk` · `Deal` · `Circle` · `Zone` · `Mark` · `Heal` · `Stun` · `Big` · `Flair`)도 그대로 쓸 수 있다.

## 6. 안전 규칙 (치명 사고 교훈 · 반드시)

### 6-1. 상태는 「끝나는 시각」(until) 하나로 — 1.2.7 보스 무적 사고

```csharp
float parryUntil;                                   // 막기 판정이 끝나는 시각
public override void Tick()
{
    if (!Paths.Has(SwordsmanPaths.Parry)) return;
    if (GameInput.UltDown) parryUntil = Time.time + 0.25f;
}
public override float Taken(float dmg)
{
    if (Time.time < parryUntil) { Paths.Invuln(0.6f); return 0f; }    // 켜고 끄지 않음 — 시간이 지나면 저절로 풀림
    return dmg;
}
```

- **코루틴으로 켜고 끄지 않는다** (`state = true; yield …; state = false;` 금지). 끊기면 `true` 가 남는다.
- 정적 bool 깃발이 꼭 필요하면 `try { … } finally { 깃발 = false; }` 로만.
- 무적은 `Paths.Invuln` 만. `invincibleUntil` 을 직접 만지거나 큰 값을 넣지 않는다. 한 번에 1.5초 상한.
- 플레이어 이동 속도 · 반투명 · 크기 등 바꾼 값은 `MoveMul()` 처럼 **매 프레임 계산해 돌려주는 방식**으로. 직접 바꿨다면 `until` 이 지나면 되돌리고 `End()` 에서도 되돌린다.
- 기다림에는 상한을 둔다 (`while (조건 && Time.time < 상한)`).
- **보스의 `invulnerable` 은 절대 건드리지 않는다.** 보스 패턴 · 결계 코드도 고치지 않는다.
- 이미 찾은 비슷한 위험 (기획서 6-3 (1) 5) — 해당 영웅이 같이 고친다:
  - 거너: `SignatureSkills.UltShots` 를 `PlayerController` 에서 켜고 끄는 곳에 `finally`.
  - 유령: `PossessRoutine` 의 이동 속도 · 반투명 되돌리기를 until 방식 + `OnDisable` 되돌림 (사령술이 빙의를 늘리므로 **반드시**).
  - 궁수: `Retreat` 가 `Alive` 를 보지 않고 위치를 바꿈 → 바람 갈래 전에 고침.
  - 시계공: `TimelessHeal` 이 쓰러진 뒤에도 회복 → `Alive` 확인.
  - 검사: `EyeOfStorm` 동시 1개로 (회오리가 회전 베기를 자주 씀).

### 6-2. 자기 복제 `Instantiate` 금지 — 1.1.8 렉 사고

- 스크립트가 붙은 자기 자신(`gameObject` · `this`)을 `Instantiate` 하지 않는다. `new GameObject` + 필요한 컴포넌트, 또는 기존 전용 프리팹 · `Fx` · `SignatureSkills.Shot` 만.
- 확인: `git grep -n "Instantiate(gameObject\|Instantiate(this" -- "Assets/Scripts/*.cs"`

### 6-4. 성능

- 매 프레임 `FindObjectsByType` · `GetComponents` · 새 리스트 · 문자열 만들기 금지. 검색은 `PhysHits.Circle` · `Paths.Circle` · `Paths.Nearest`.
- 갈래 단계는 `Paths.Rank/Res` 를 그대로 물으면 된다 (캐시).

### 6-5. 외길로 늘어나는 단계

- 외길이면 갈래 A 카드의 최대 단계가 +1 (최대 2단계 이상 카드만: 3 → 4, 4 → 5). 효과 코드가 단계 값을 `values[level - 1]` 처럼 **배열로 읽으면 넘친다**. 단계 공식(`V(L(key), a, step)` · `0.15f + 0.15f * card[n]` 등)이 단계 4 · 5 에서도 맞는지 확인한다.
- 카드 글의 늘어난 단계 수치는 틀이 「마지막 증가폭을 한 번 더」로 자동으로 만든다. 공식이 다르면 공식을 글에 맞춘다.

### 6-6. 밸런스 (기획서 4장)

- 갈래 효과 피해에는 **반드시** `Paths.Power(갈래)` 를 곱한다.
- 보스 화력은 영웅 목표의 ±8% 안. 강점 · 약점은 무리 처리 · 생존 · 기동에서 크게.
- 대가는 입문 순간부터 계속 붙는다 (`Has(갈래)` 이면 늘).
- 배치 테스트 · 자동 플레이 대량 실행은 하지 않는다.

## 7. 문구 (4개 언어)

## 9. 끝내기 전 확인 (스스로)

1. 고친 파일이 2절 표 안에만 있는가 (`git status`).
2. `using UnityEditor` · `System.Drawing` 없음: `git grep -nE "using UnityEditor|UnityEditor\.|System\.Drawing" -- "Assets/*.cs" ":!Assets/**/Editor/**" ":!Assets/Editor/**"`
3. 자기 복제 `Instantiate` 없음 (6-2).
4. 코루틴 on/off 상태 · 끝없는 기다림 · static 상태 없음. 무적은 `Paths.Invuln` 만, 보스 `invulnerable` 안 건드림.
5. 만드는 오브젝트에 개수 상한.
6. `replay` 때 연출 · 생성 없음. 이어하기로 같은 상태가 되는가 (상태를 카드 단계 · `Paths.*` 에서 다시 계산할 수 있으면 가장 안전).
7. 갈래 효과 피해에 `Paths.Power` 를 곱했는가 · 대가가 붙었는가.
8. 외길 단계 4 · 5 에서 공식이 넘치지 않는가.
9. 문구 4개 언어 · 키가 데이터 문장과 같은가.
10. 컴파일되는 코드인가 (눈으로): 없는 메서드 · 접근 권한 · 이름 충돌 · 타입.
11. 보고: 구현한 효과 표 (입문 5 · 공명 10 · 극의 5 · 새 교차 2) · 바꾼 수치 · 「필요한 공용 변경」 · 남은 위험.
