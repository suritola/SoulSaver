# Soul Saver UI 전면 개편 기획: 「싸구려 모바일 게임」 인상 걷어내기

근거 표기 규칙
- `파일:줄`의 파일은 따로 적지 않으면 `C:\Users\User\Desktop\Unity\Soul Saver\Assets\Scripts\` 아래에 있습니다. 도구와 장면 파일은 저장소 기준 경로로 적었습니다.
- 수치는 코드와 파일에서 직접 잰 값입니다. 잰 값이 아닌 것에는 「추정」을 붙였습니다.
- 그림 파일은 두 장만 열었습니다(1.4.7 시절 UiCapture 캡처의 메인 화면과 레벨업 화면). 그 뒤 1.4.8~1.5.0에서 바뀐 화면은 코드로 판단했습니다.
- 저는 읽기 전용으로 계획만 세웠고 파일은 하나도 고치지 않았습니다.

## 0. 한눈에 보는 우선순위

**P0: 배치는 그대로 두고 전 화면을 한 번에 바꿉니다. 효과가 가장 큽니다.**
1. 공용 그림을 교체합니다. 금테·리벳·붉은 보석·리본을 1도트 석판으로 바꿉니다.
2. 반복 연출 약 20곳을 없앱니다(숨쉬기·반짝임·후광·별빛·튀어나옴).
3. 선택 표시를 바꿉니다. 지금은 「통째로 금색 칠 + 1.06배 확대」인데, 테두리 강조와 포커스 괄호로 바꿉니다.
4. 글자를 4단계로 고정합니다. 굵게·그라데이션·외곽선을 없애고 금색 글자도 쓰지 않습니다.
5. 메인 배경을 어둡게 하고, 제목을 정리하고, 불티를 끕니다.
6. 버튼 이름을 짧게 바꿉니다. 4개 언어 모두 해당하며 번역 표의 한국어 칸만 덮어쓰면 됩니다.

**P1: 화면별로 다시 배치합니다.** 확인 창 → ESC → 메인 → 결과 → 레벨업/고르기 → 설정 → 로딩 → HUD → 영혼 트리 → 나머지 창 순서입니다.

**P2: 마감합니다.** 패드 포커스 통합, 소리 교체, 공통 키 안내 줄, 숫자 고정폭, 글꼴 A/B, 배경 재채색, 린트를 오류로 승격합니다.

**P3: 사람 작가에게 맡깁니다.** 로고, 메인 키아트, 아이콘 그림문자, 의례 장식 1~2개입니다.

## 1. 진단: 왜 「싸구려 중국 게임」처럼 보이는가

### 1-1. 공통 원인 (영향 큰 순)

**C1. 모바일 가챠 로비의 시각 어휘를 그대로 쓰고 있습니다**
- 그림 생성 스크립트가 그 어휘를 그대로 그립니다.
  - 버튼: 금장 테두리, 보라 경사 채움, 네 귀 금 리벳 (`tools/pixelart/make_ui_frames.py:26-55`)
  - 창: 금 이중 테두리, 모서리 금 브래킷, 붉은 보석 (`:58-109`)
  - 장식선: 가운데에 붉은 보석 (`:112-127`)
  - 리본: 양끝 깃과 금 보석 (`:130-161`)
  - 설계 의도도 주석에 그대로 적혀 있습니다 (`MenuExtras.cs:906-909`).
- 버튼 그림 한 장(`UIKit.ButtonSprite`)이 너무 많은 곳에 쓰입니다.
  - 버튼, 카드, 탭, 알약, 입력칸, 드롭다운, 슬라이더 손잡이, 트리 칸, 위아래 띠, 결과 왼쪽 판까지 모두 이 그림입니다.
  - 직접 사용이 24파일 45곳, `MakeButton` 호출이 32파일 111회입니다.
  - 그래서 누를 수 있는 것과 아닌 것이 구별되지 않고, 화면 전체가 금테로 덮입니다.
- HUD도 마찬가지입니다. 장면에 있는 HUD 판 5개(StatusPanel·CoinPanel·AmmoPanel·LevelPlate·StatsPanel)를 `RestyleScene`이 보석 창 그림으로 바꿉니다 (`MenuExtras.cs:964-973`). 싸우는 동안 화면 네 귀퉁이가 금 보석 틀입니다.

**C2. 연출이 쉬지 않습니다**

  - `LevelPips.cs:204`
  - `NewGlow.cs:79-89`: 테두리 굵기가 2→6px로 변하고 4% 커집니다.
  - `RecommendGlow.cs:4-8·286`: 후광, 금→흰→보라로 도는 테, 별빛 10개
  - `SkillEvolutionUI.cs:246`, `SkinShopUI.cs:341`
  - `SoulTreeUI.cs:160-171`, `SpecialTreeUI.cs:457`
  - `SpecialAbilities.Hud.cs:347`
  - `StageManager.cs:319-322·359-363`
  - `TutorialRun.cs:351·394`
  - `WeaponEvolutionUI.cs:162·167`
  - `MenuExtras.cs:2644`: 제목 숨쉬기
  - `Notice.cs:714-720`: 줄 숨쉬기, 아이콘 들썩임
- 튀어나오는 연출도 여럿입니다.
  - `CardIntro.cs:69-74`: 넘쳤다 돌아오는 움직임에 4도 기울기
  - `Notice.cs:690-693`: 1.35배 크기에서 튀어 들어오며 흰 번쩍

  - `MenuExtras.cs:2571-2576`: 창이 0.94배에서 1배로
- 떠다니는 것도 있습니다. 메인 메뉴 금 불티(`MenuExtras.cs:2646-2666`)와 로딩 화면 불빛(`SceneFlow.cs:106-114`)입니다.

**C3. 상태를 「통째로 금색 칠 + 확대」로 보여 줍니다**

  - `ChoiceUI.cs:73`, `LevelShop.cs:412`, `CodexUI.cs:306`
  - `MenuExtras.cs:660·1448·1613·1726·2371·2478`
  - `SpecialTreeUI.cs:406` 등
- 도트 그림을 1.06배로 키우면 화소 크기가 고르지 않게 뭉개집니다.

**C4. 도트 크기가 뒤섞이고 정수가 아닌 배율로 확대합니다**
그래픽 기획서의 A1 문제가 UI에서도 그대로 나타납니다.
- UI 그림은 PPU 50이라 1080p에서 1도트가 2px입니다. 그런데 `pixelsPerUnitMultiplier`가 곳마다 다릅니다.
  - 2(=1px), 1(=2px), 0.7(=2.9px), 0.3(=6.7px)이 섞여 있습니다.
  - 해당 위치: `ResultScreen.cs:428`, `RunStats.cs:349·412·436`, `SceneFlow.cs:128`, `NewGlow.cs:64`, `CodexUI.cs:811`, `SpecialTreeUI.cs:243·259`, `TutorialRun.cs:517`, `bossbar.cs:578`, `Notice.cs:495`, `SpecialAbilities.Hud.cs:208`
- 같은 키캡 그림이 두 굵기로 그려집니다(0.3과 0.7).
- 장식선 128×8 그림을 여러 크기로 늘립니다.
  - 384×24(3배)와 512×32(4배)
  - 폭×8: 가로 3.75배, 세로 1배로 비율이 다르게 늘어납니다 (`RunStats.cs:379-385`).
- 32px 아이콘도 정수가 아닌 배율로 그립니다.
  - 56(1.75배), 104(3.25배), 140(4.38배), 150(4.69배) (`SoulTreeUI.cs:401·416`, `CodexUI.cs:1020`, `ChoiceUI.cs:163`)
  - 메인 메뉴 영웅은 32px를 420으로 그립니다(13.1배, `MenuHeroPanel.cs:73`).
- 메인 배경 `Assets/Sprites/UI/Theme/menu_bg.png`은 1도트가 4px이고, 표본 색이 약 7,900색입니다(실측).

**C5. 글자 규칙이 없습니다**
- `UIKit.Text` 281회 호출에 글자 크기가 24가지(14~64)입니다.
- 화면 제목만 봐도 64·54·50·46·44·40·38로 제각각입니다.
- 결과 화면 제목은 장면에 120pt로 들어 있습니다(`Assets/Prefabs/Scenes/GameOver.unity`의 「사망하셨습니다...」).
- 굵게를 23파일 33곳에서 씁니다.
- 제목은 금빛 그라데이션 + 그림자 + 자간 8입니다 (`MenuExtras.cs:446-453`).
- 마우스를 올리면 자간이 0→4로 변해 글자가 출렁입니다 (`:2475`).
- 판 위 글자에 검정 외곽선을 둡니다 (`LevelShop.cs:438-440`).

**C6. 색 토큰이 없고 색 수가 많습니다**
- 금색 (0.96, 0.83, 0.47)을 25파일이 각자 정의하고, 리터럴로도 71회 씁니다.
- 금색 변형만 4가지 더 있습니다.
- 흐린 글자색이 5가지, 양피지색이 4가지입니다.
- 알림 강조색 9가지 (`Notice.cs:49-51`)
- 영혼 트리 가지 6원색 (`SoulTreeUI.cs:17-25`)
- 난이도 4색 (`MenuExtras.cs:633-636`)
- 결과 화면은 머리가 보라(`MenuExtras.cs:63`)이고 본문 머리는 금(`RunStats.cs:287`)입니다.
- 한 화면에 강조색이 4~6개입니다.

**C7. 쌍선형으로 부드럽게 번지는 빛을 도트 그림과 섞습니다**
- `GlowSprite`를 54회 씁니다.
  - 카드 아이콘 뒤 (`ChoiceUI.cs:158-162`)

**C8. 소리가 장난감 같습니다**
- UI 소리는 사인파로 합성한 「삑」 두 개뿐입니다 (`UISound.cs:36-43`).
- 창 열기·닫기, 취소, 거부 소리가 없습니다.
- 고르기 창은 전투용 범용 효과음(pop/chime/pulse)을 씁니다 (`ChoiceUI.cs:68·183·248`).

**C9. 많고 깁니다**
- 긴 버튼 이름: 「이 탭 기본값으로」, 「포기하고 결과 보기」, 「빌드 자세히 보기」, 「저장 폴더 열기」, 「튜토리얼 그만두기」 등
- 도감 탭 14개가 한 줄에 있습니다. 탭 폭 99, 글자 하한 14입니다 (`CodexUI.cs:241-250`).
- 화면마다 따로 안내 줄을 붙입니다 (`ChoiceUI.cs:118`, `SoulTreeUI.cs:348-351`, `MenuExtras.cs:1104`).

**C10. 여백과 정렬 기준이 없습니다**
화면 가장자리 여백이 16·24·26·30·36·60으로 제각각입니다.
- 결과 화면은 왼쪽 판 여백 36, 오른쪽 판 여백 60으로 좌우가 다릅니다 (`ResultScreen.cs:148`, `RunStats.cs:338`).
- 메인 메뉴 오른쪽 열은 오른쪽 30, 위 26입니다 (`MenuExtras.cs:519`).

**C11. 패드 포커스 표시가 화면마다 다릅니다**
- 메뉴에서 가상 커서 화살표를 버튼 위에 그대로 그립니다 (`GamePad.cs:497-507`).
- 고른 것을 보여 주는 방법이 화면마다 다릅니다(금 띠, 금 칠, 금 테, 확대).

**C12. 체계가 없습니다**
- 불만이 나올 때마다 금테·리본·불티·보석을 덧칠했습니다(1.4.8~1.5.0의 커밋 3bc7c1e, 66e48af, c273bc6, 4f9e28d, d595c72, 1d21809, 1f650b9, a0fd8a8, 0c532ea, eb8836f).
- 디자인 문서와 린트가 없어서 다음 수정이 또 같은 방향으로 퍼집니다.

**C13. (2순위) 글꼴**
- 한국어와 영어는 카페24 단정해 글꼴 하나에 가짜 굵게를 얹어 씁니다.
- 일본어와 중국어는 Noto Sans Bold가 대신 그려서 한 줄 안에서 글꼴이 섞입니다 (`Loc.cs:44-45·75-80`).
- 카페24 글꼴은 쇼핑몰 배너 인상이 있어 「싸구려」 느낌을 키운다고 봅니다(추정, A/B로 확인).

## 3. 디자인 시스템

새 파일 `UiTokens.cs` 하나에 모아 둡니다. UI 코드에는 숫자를 직접 쓰지 않고 토큰만 씁니다.

### 3-1. 도트 규칙
- **UI 1도트 = 1080p에서 3px**로 정합니다. 새 그림은 PPU 33.333이고, `pixelsPerUnitMultiplier`는 1로 고정합니다(UIKit 밖에서 바꾸는 것은 금지).
- 3px을 고르는 이유는 정수 배율입니다.
  - 장면 캔버스는 Expand 1920×1080입니다 (`Assets/Prefabs/Scenes/MainMenu.unity:844-849`).
  - 해상도별 캔버스 배율은 720p 0.667, 1080p 1, 1440p 1.333, 4K 2, 스팀 덱(100%) 0.667입니다.
  - 그러면 1도트는 각각 2·3·4·6·2px로 모두 정수가 됩니다.
  - 지금처럼 2px 기준이면 1440p에서 2.67px, 덱에서 1.33px이 되어 화소가 고르지 않습니다.
  - 그래픽 개편 기획서 3단계의 월드 목표(1080p에서 3화소)와도 같은 격자입니다.
- 크기와 위치는 **6의 배수**(2도트)로 정합니다.
- 도트 그림은 정수 배로만 그립니다.
  - 32px 아이콘은 64(목록·HUD·트리) 또는 96(카드)
  - 영웅 32px은 384(12배) 또는 192(6배)
- 확대·축소 연출은 금지합니다.
- UI 크기 80/90/110/120%와 4:3 화면에서는 정수가 아니게 되므로, 그때는 1px 흔들림을 허용합니다.
- 스팀 덱 자동 설정 110%(`GameSettings.cs:530`)는 글자 크기를 우선해 그대로 둡니다.

- **창 판**

  - 모서리 1도트를 깎습니다.
  - 보석, 브래킷, 금은 없습니다.
- **카드**: 바탕 Raised에 테 LineDim. 고른 카드는 테 Accent + 괄호입니다.

- **게이지**

- **아이콘**
  - 정수 배로만 그립니다.
  - 뒤에 빛을 깔지 않습니다.
  - 홈 칸 안에 넣고, 범주 틀(무기 사각, 스킬 원, 패시브 마름모, 유물 육각)을 씁니다. 이는 그래픽 기획서 ⑦을 앞당겨 하는 것입니다.
- **툴팁**

  - 최대 폭 480, 안쪽 여백 18
  - 제목은 본문 26 Text1, 내용은 보조 22 Text2
  - 0.1초 늦게 뜹니다.
- **알림 점**: NEW 알약을 2×2도트 Accent 점(윤곽 포함)으로 바꿉니다. 글자 옆에 붙이고 맥동하지 않습니다.
- **추천·NEW·잠김 이름표**: 테 AccentDim의 작은 판입니다.
- **키캡**: 하나로 통일합니다(지금은 0.3과 0.7 두 굵기).

- **패드**

### 3-10. 버튼 이름 규칙과 4개 언어 표

규칙
1. 행동 버튼은 동사형 2~4글자로 씁니다(다시 하기, 계속, 배우기, 받기).
2. 이동 버튼은 목적지 명사 2~4글자로 씁니다(설정, 도감, 메인 메뉴).
3. 같은 행동에는 같은 이름을 씁니다.
   - 닫기 = 정보 창을 나감
   - 취소 = 확인 창에서 하지 않음
   - 확인 = 알림을 확인함
4. 확인 창의 확정 버튼은 질문의 동사를 그대로 씁니다. 「다시 시작할까요?」면 [다시 시작]입니다. 파괴적 행동에 「확인」은 쓰지 않습니다.
5. 조건·키·설명은 버튼 글자에 넣지 않고 보조 글자, 툴팁, 키캡으로 옮깁니다.
6. 길이 상한: 영어 14자, 일본어 6자, 중국어 4자.
7. 번역 키 처리
   - 기존 키는 번역 표의 한국어 칸만 덮어써서 키를 그대로 둡니다. `Loc.cs:27`이 한국어 칸(tr[0])을 우선 쓰기 때문입니다.
   - 새 문구는 점 표기 키 `ui.btn.*`로 만듭니다.
   - 한국어 원문을 키로 새로 쓰면 안 됩니다. 「영웅」 키는 이미 희귀도 Epic으로 쓰이고 있습니다(`LocTable.cs:1693`).

# 「UI 개편 기획서」 비판 검토 (docs/art/UI-개편-기획서.md, eae8570)

코드만 읽고 판단했습니다. 캡처나 배치 테스트는 돌리지 않았고 파일은 하나도 고치지 않았습니다.

총평부터 말씀드리면, 기획서의 줄 번호는 대부분 맞습니다. MenuExtras.cs 줄 번호 25곳 정도를 표본으로 열어 봤는데 거의 다 일치했고, 결과 화면 버튼 · 피해 막대처럼 오늘 바뀐 부분(c48827e · fd2c2a2)도 반영돼 있습니다. 문제는 **방향**과 **기술 전제** 쪽입니다.
- 사용자가 지금까지 했던 말을 거스르는 부분이 있습니다.
- UI 크기가 100%보다 크면 「1920 안전 상자」가 성립하지 않습니다. 스팀 덱은 처음 켤 때 110%로 맞춰지므로 덱에서도 마찬가지입니다.
- P0를 한 번에 하면 화면이 깨진 중간 상태가 생깁니다.

이 세 가지가 가장 큽니다.

**주장**

1. **「월드와 같은 3px 격자」는 이미 틀렸습니다.** 그래픽 기획서 :189는 직교 20 · PPU 9를 전제로 했습니다. 그런데 카메라가 오늘 20 → 28 → 25 → 22로 바뀌었습니다(631b2f9). 지금 1080p에서 월드 1칸은 약 24.5px이고, PPU 8 그림은 1도트가 약 3.07px, 영웅은 ×1.35배라 약 4.1px입니다. UI 3px은 「월드와 같은 격자」가 아니라 「UI 자체의 격자」라고 고쳐 써야 합니다.

2. **「스팀 덱 · 해상도별로 모두 정수」는 UI 100%일 때만 맞습니다.**
   - 덱은 처음 켤 때 UI 110%로 맞춰집니다(GameSettings.cs:530). 이때 1도트 = 2.2px입니다.
   - 1366×768(약 2.13px), 1600×900(2.5px), 1680×1050(2.6px)도 정수가 아닙니다.
   - 「4:3 · 80~120%만 흔들림을 허용한다」는 표현은 범위를 너무 좁게 잡았습니다.

3. **「전면 화면은 1920×1080 안전 상자 안에」는 UI 110 · 120%에서 성립하지 않습니다.**
   - UiScaler.Fit은 기준 해상도를 UI 크기로 나눕니다(UiScaler.cs:48-53). Expand 방식에서는 논리 캔버스 폭이 **1745(110%), 1600(120%)**으로 줄어듭니다.
   - 스팀 덱 기본값(1280×800, 110%)에서도 논리 폭이 1745입니다.
   - 그래서 결과 화면 안(828 + 24 + 828 = 1680 + 좌우 여백 120씩)과 12열 격자는 120%에서 화면 밖으로 나갑니다.
   - 지금 코드는 이 경우를 따로 처리하고 있습니다(ResultScreen.cs:143 주석 「UI 크기 110 · 120% 로 짧아져도」).

4. **「QA/UiCapture가 이름으로 부르는 멤버」 목록이 모자랍니다.** 기획서는 `ToggleEsc` · `SettingsUI.Open/ShowTab/Close` · `pendingSlot, selectReady, showLv, cardGroup, AddPending, onSelect`만 적었습니다. 실제로는 아래도 이름으로 부릅니다.
   - **SceneFlow**: `Ensure, canvas, curtain, ShowLoading, targetProgress, Dots, Tick, loadingBox` (tools/qa/QaCapture.cs:1189-1202)
   - **LevelShop**: `first/second/third`(LevelShop.cs:702), `IsOpen`
   - **ChoiceUI**: `ready`, `confirmed`. 자동 플레이 QA가 이 둘로 카드를 고르므로(QaCapture.cs:454·1120), 이름이 바뀌면 밸런스 배치가 멈춥니다.
   - **WeaponEvolutionUI**: `Select/confirmed`
   - 그 밖에 `StageManager.ShowBanner`, `ClaimRewards.window`, `UIKit.HudCanvas`

5. **CardIntro를 쓰는 곳은 세 군데입니다.** 기획서는 ChoiceUI.cs:205만 적었는데, LevelShop.cs:692(갈래 창), SpecialTreeUI.cs:79(노드, 간격 0.045)도 있습니다. 「순차 등장 금지」를 그대로 넣으면 세 창의 입력 잠금이 모두 짧아집니다.

6. **움직임 시간이 서로 안 맞습니다.** P0-1은 「CardIntro 0.18초」, 3-8은 「카드 열림 0.14초」라고 적었습니다.

7. **ESC 새 배치도에 지금 ESC에 떠 있는 판 두 개가 없습니다.**
   - 오늘 고친 계약 판: 왼쪽 아래 (30, 18), 폭 480, Contracts.cs:557-566
   - 영혼 각인 목록: 가운데 -20, 최대 높이 464
   - 기획서의 「y1008 키 안내 줄 · 왼쪽 x120 목록」이 계약 판(높이 최대 약 270)과 겹칩니다.
   - 계약 판 글자를 22 이상으로 올리면 폭 480 안에 영어가 들어가지 않습니다.

8. **로딩 화면 개편 범위가 오늘 바뀐 장 전환 로딩(a220ac3)을 빠뜨렸습니다.** `SceneFlow.RunStageLoad`는 `ShowLoading(null)`로 씬 이름 없이 부르고, `loadingBox`에 CanvasGroup을 붙여 알파를 조절합니다(SceneFlow.cs:279-310). 기획서는 Build/Tick만 적었습니다.

9. **번역 표 자체가 스스로 정한 규칙을 어깁니다.**
   - 같은 행동에 같은 이름: ESC 「메인 메뉴」를 ja 「タイトルへ」로 바꾸면서, 결과 화면 `result.menu`는 「メインメニュー」로 남깁니다(LocTable.Result.cs:25).
   - 길이 상한: zh 「打开文件夹」은 5자라 4자 상한을 넘습니다.
   - ja 「フォルダ」는 「폴더」라는 뜻뿐이고 「열기」가 빠졌습니다.

10. **흐린 배경이 스스로 정한 규칙과 부딪칩니다.** ESC 배치도의 「흐린 게임 화면」은 지금 EscBackdrop이 화면을 1/8로 줄였다가 쌍선형으로 늘려 만듭니다(MenuExtras.cs:2488-2489). 이는 C7 「쌍선형 번짐 금지」와 맞지 않습니다. 메인 배경도 1도트가 4px인데 P2까지 그대로 둡니다. 3px 규칙의 예외로 문서에 적어 둬야 합니다.

11. **진단에 쓴 그림이 지금 화면이 아닙니다.** 기획서가 직접 연 캡처는 1.4.7 시절 두 장뿐입니다(:8). 정작 비판하는 금테 · 리벳 화면(1.4.8~1.5.0)은 한 번도 보지 않았습니다. 진단의 시각 근거는 「추정」으로 표시해야 합니다.

## 2. 위험과 대책

### 높음

**H1. 사용자가 했던 말과 정면으로 부딪칩니다.** 코드 주석에 사용자의 말이 그대로 남아 있습니다.
- 「도형에 색만 채우면 싸구려 같다 · 게임 스타일에 맞게 이미지를」(MenuExtras.cs:908)
- 「버튼이 너무 투명해서 누를 수 있는 건지 모르겠다」(:2434)
- 「메뉴 뒤 반투명 판은 별로」(:184)
- 「게임이 덜 완성된 것 같다」(:181)
- 「난이도 탭이 빨간 카펫 위에서 묻힘」(:640)

안 A의 「판 없는 텍스트 목록(Text2) · 1도트 평면 석판」은 바로 이 「평평 · 투명 · 미완성」 불만을 되살립니다. 사용자는 **평평한 것도 싸구려, 금빛으로 꾸민 것도 싸구려**라고 했습니다. 그러니 목표는 「장식을 빼는 것」이 아니라 **「물성은 있되 번쩍이지 않는 것」**이어야 합니다.
- 대책: 4장의 수정안을 따릅니다.

**H2. 그림을 바꾸는 커밋과 칠하는 코드를 바꾸는 커밋이 떨어지면 화면이 깨집니다.**
- 지금 상태 표시 코드는 밝은 보라 · 회색 그림에 색을 곱하는 방식입니다. 예: `img.color = Gold`, ResultScreen.cs:162의 (0.08, 0.06, 0.11, 0.72), MarkLocked의 (0.2, 0.19, 0.23), ColorBlock highlighted 1.15. EnsureStyle 주석(:907)에도 「색을 곱해 상태를 칠하는 기존 코드는 그대로 통함」이라고 적혀 있습니다.
- v2 그림이 어두운 색(#14131A)으로 칠해진 그림이면, 여기에 금을 곱해도 거의 검정이 됩니다. 기획서가 순서를 「P0-2 그림 교체 → P0-3 SetSelected」로 나눈 사이에, 선택 · 잠김 상태가 전 화면에서 보이지 않게 됩니다.
- 대책은 둘 중 하나입니다.
  - (a) v2 그림을 지금처럼 회색조로 그리고 색은 코드에서 곱합니다.
  - (b) 그림과 칠하는 코드를 **화면 단위로 같은 커밋**에서 바꾸고, 스위치 뒤에 둡니다.

**H3. 장식선 그림을 같은 필드에 넣으면 굵은 막대가 됩니다.** `DividerSprite`를 쓰는 곳이 20곳이고, 「그림이 있으면 512×32 / 384×24로 크게 그린다」는 분기에 묶여 있습니다(MenuExtras.cs:797, ChoiceUI.cs:110-112). `DividerSprite`에 4×1 v2 선을 넣으면 32px 두께 막대로 늘어납니다.
- 대책: 기존 필드는 건드리지 않고 새 필드 `UIKit.LineSprite`를 만든 뒤, 쓰는 곳을 화면마다 옮깁니다. 같은 이유로 `PanelSprite != null` · `BarArt` · `newStyle`(SpecialTreeUI.cs:94) 분기도 전부 검사합니다.

**H4. 로딩 화면을 고치다 예외가 나면 게임이 영영 멈춥니다(1.2.7 사고와 같은 종류).**
- `Run`과 `RunStageLoad`는 `loading = true` 뒤에 `ShowLoading` · `Dots` · `Tick`을 **try 밖**에서 부릅니다(SceneFlow.cs:213-260, 283-297). 새 배치 코드에서 여기서 예외가 나면 `loading`이 계속 true로 남습니다.
- 그러면 `Go()`가 모든 씬 전환을 조용히 무시합니다(:41-46). 막의 raycastTarget도 켜진 채라 클릭까지 막힙니다.
- 대책: 로딩 화면 꾸미는 코드를 try/finally로 감쌉니다. 무엇이 실패해도 `loading = false`가 되고, 막과 캔버스가 정리되게 합니다. QA가 부르는 멤버 이름은 그대로 둡니다.

**H5. CardIntro를 바꾸면 남는 상태와 입력 잠금 문제가 생깁니다.**
- 끝 시각을 돌려주는 계약은 지켜야 합니다. 다만 「2도트 상승」을 카드 루트의 anchoredPosition으로 하면 문제가 생깁니다. TidyCards(LevelShop.cs:538-572)가 연출 도중에 자리를 다시 잡으면 Restore가 옛 위치로 되돌려서 카드가 어긋난 채 남습니다.
- 「고른 카드 2도트 위로」도 같은 위치값을 건드립니다.
- 순차 등장을 없애면 잠금 시간이 지금 약 0.52초(0.08 + 2×0.09 + 0.26)에서 0.2초대로 줄어듭니다. 그러면 앞 창에서 연타하던 클릭이 다음 창 카드를 잘못 고르는 문제(CardIntro.cs:5)가 돌아옵니다.
- 대책
  - 움직임은 자식 「Face」나 별도 오프셋에만 줍니다.
  - 잠금은 연출 길이와 떼어 내서 `Mathf.Max(introEnd, now + 0.45f)`로 둡니다.
  - 세 군데 모두 고칩니다.

**H6. P0 「한 번에 전 화면」은 수백 곳을 고치는 일입니다.** 대략 ButtonSprite 59 · Text 283 · 금색 리터럴 71 · 굵게 33 · 맥동 23+ · 배율 16 · 장식선 20 · PillArt 15 정도이고, 50개 파일 가까이 걸립니다. 게다가 AGENT 규칙 7에 따라 사용자가 「빌드해」라고 하면 반쯤 된 상태가 그대로 배포됩니다.
- 대책: **`UiRules.Legacy`(기본값 true)** 스위치를 먼저 만듭니다. 그래픽 개편의 VisualRules.Legacy(VisualRules.cs:68)와 같은 방식입니다. 화면 단위로 작게 커밋하고, 스위치를 끄는 커밋은 사용자 승인 뒤 따로 합니다.

### 중간

- **M1. 패드 가상 커서.** 커서가 버튼으로 옮겨 가려면 버튼 **가운데**가 그 버튼에 맞아야 합니다(`TopAt(c)` 가 그 버튼의 자식인지 검사, GamePad.cs:572). 판 없는 텍스트 버튼은 줄 전체를 덮는 투명 raycast Image가 꼭 있어야 합니다. 포커스 괄호는 raycastTarget을 꺼야 합니다.
  - 메인의 「시작 < 보통 >」 스테퍼가 `TakeDpadX`를 늘 가져가면, 오른쪽 열 · 영웅 패널로 커서를 옮길 수 없게 됩니다. 커서가 그 줄에 있을 때만 가져가야 합니다.
- **M2. 유니티 기본 Selectable 문제.** 클릭한 버튼이 「선택됨」 상태로 남아서 마우스를 올린 버튼과 함께 두 개가 강조됩니다. 그리고 UiButtonView를 따로 만들기보다 기본 SpriteSwap 전환으로 충분한지 먼저 검토할 만합니다.
- **M3. 포커스 괄호를 화면에 하나만 두는 방식.** 결과 화면 UI가 다음 판까지 남던 사고(a41eb66)가 있었으니, HudCanvas(DDOL)에 붙이면 안 됩니다. 대상이 사라지면 괄호도 같이 사라져야 합니다.
- **M4. 한국어 칸 덮어쓰기.** 키가 표 하나에만 정의돼 있어서(게임 시작 · 계속하기 · 메인 메뉴로 등은 각각 1곳) 기술적으로는 안전합니다. 하지만 코드에는 `MakeButton("게임 시작")`이 남은 채 화면에는 「시작」이 뜨므로, find-text · grep으로 찾을 수 없게 됩니다.
  - 덮어쓰기는 **장면에 박힌 글자(SceneLocalizer, GameSettings.cs:542-561)에만** 씁니다. 코드에서 만드는 버튼은 `ui.btn.*` 새 키로 바꿉니다.

## 3. 방향에 대한 판단

**안 A의 골격(토큰 · 강조색 하나 · 맥동 · 확대 금지 · 정수 배율 · 포커스 표시 통일)은 유지합니다. 다만 겉모습은 수정안으로 갑니다.** 「석판」을 「평평한 사각형」이 아니라 **「새긴 돌」**로 정의해야 합니다.

1. **물성을 남깁니다.**
   - 판과 버튼에 2톤 디더 돌결, 위 1도트 하이라이트 + 아래 2도트 그림자(두께감), 홈은 파낸 느낌으로 그립니다.
   - 장식은 「창마다 모서리 각인 하나(1도트 선으로 새긴 룬 · 해골 · 영혼불 문양)」까지 허용합니다.
   - 보석 · 리벳 · 이중 금테만 금지합니다.
2. **누를 수 있는 것은 평소에도 그렇게 보여야 합니다.**
   - 메인 · ESC 목록에도 Raised 석판(불투명, 알파 1)을 깝니다. 반투명은 「별로」 피드백을 되살립니다.
   - 포커스는 테 Accent + 괄호 + 영혼불 표식으로 보여 줍니다.
   - 「판 없는 텍스트 버튼」은 툴팁 링크 · 보조 링크에만 씁니다.
3. **금을 0으로 만들지 않고 「희소한 보상색」으로 남깁니다.** 바랜 청동 #B89A5E 하나로 정하고 새 기록 · 전설 등급 · 진화 완료 · 동전에만 씁니다. Blasphemous와 같은 「절제」이지 「제거」가 아닙니다. 금을 완전히 걷으면 무료 에셋 같은 인상이 날 위험이 큽니다.
4. **청록 강조색은 유지합니다.** 월드의 푸른 화로 · 포털 색과 이어지고, 경험치(보라) · 체력(빨강) · 적 체력바(초록 · 노랑 · 빨강, dff5ba9)와도 겹치지 않습니다. 참고 게임으로는 Hyper Light Drifter(도트 + 청록 단일 강조)를 넣습니다. Hollow Knight · Death's Door는 손그림 게임이라 도트 근거로는 약합니다.
5. **결과 화면은 오늘 사용자가 「간결하게」를 받아들인 세로 버튼 열(c48827e)을 유지합니다.** 배치를 다시 짜는 것은 P1 승인 뒤로 미룹니다. 하루 만에 배치를 두 번 바꾸면 사용자가 혼란스럽습니다.
6. **안전 상자는 `min(1920, 실제 캔버스 폭)`으로 정의합니다.** 결과 화면 두 판은 120%에서 각 720 이하가 되도록 비율로 계산합니다.
